FuFumidi 插件开发文档 Plugin Developer Documentation

为第三方开发者准备的完整指南：从最小插件到事件、引擎与渲染层接口。插件系统不改动主程序，即可扩展 FuFumidi 的能力。

01总览与概念Overview

插件是放在插件目录中的一个文件夹，包含 plugin.json 清单和入口脚本。插件由用户主动安装，等同于本地可信代码：它能调用引擎、读写自己的设置、向界面发送消息。 A plugin is a folder placed under the plugin directory, containing a plugin.json manifest and an entry script. Plugins are installed deliberately by the user and run as locally trusted code: they can run the engine, read and write their own settings, and send messages to the UI.

插件能做什么What a plugin can do

  • 注册命令，供界面「设置 → 插件」页调用Register commands callable from the Settings → Plugins page
  • 订阅应用事件（载入歌曲、切换视图、转录完成等）Subscribe to app events (song loaded, view changed, transcribe done, …)
  • 调用引擎 Python 脚本，复用自己的转录/后处理能力Run engine Python scripts, reusing transcribe / post-process capabilities
  • 读写插件私有设置Read and write plugin-private settings
  • 通过渲染层脚本操作界面、显示提示Manipulate the UI and show toasts via a renderer script

插件不能做什么What a plugin cannot do

  • 不能修改主程序文件或其它插件Cannot modify the host app or other plugins
  • 单点异常只记日志，不影响主程序运行A single failure is logged only, without affecting the host
  • 引擎调用带 30 分钟超时，死循环会被终止Engine calls carry a 30-minute timeout; infinite loops are killed
建议：所有引擎调用、文件操作都放在主进程插件里；渲染层脚本只负责界面反馈。 Tip: keep engine calls and file operations in the main-process plugin; the renderer script only handles UI feedback.

03插件清单 plugin.jsonThe plugin.json manifest

{
  "id": "my-plugin",      // 唯一 ID：小写字母/数字/-/_，必填
  "name": "我的插件",      // 展示名
  "version": "1.0.0",
  "author": "作者",
  "description": "一句话说明",
  "entry": "index.js",    // 主进程入口，必填（CommonJS）
  "renderer": "ui.js",     // 可选：注入到界面环境的脚本
  "commands": ["hello"]   // 可选：声明命令，设置页会列出按钮
}
字段Field必填Required说明Notes
id是yes全局唯一，用于启用状态与消息路由。只能含小写/大写字母、数字、-、_Globally unique; used for enable state and message routing. Letters, digits, -, _ only
name否no展示名，缺省用 idDisplay name, defaults to id
entry是yes主进程入口，相对本目录Main-process entry, relative to this folder
renderer否no渲染层脚本，随启用注入一次Renderer script, injected once when enabled
commands否no声明命令名，设置页据此列出按钮（实际仍须在 activate 中 register）Declared command names shown as buttons (still must be register()ed in activate)

04入口脚本Entry script

入口导出 activate(ctx)（必选）与 deactivate()（可选）。启用时调用 activate，停用或退出时调用 deactivate。 The entry exports activate(ctx) (required) and optionally deactivate(). activate is called on enable, deactivate on disable or quit.

module.exports = {
  activate(ctx) {
    // 注册命令、订阅事件、读取设置……
    ctx.commands.register('hello', async () => '你好');
  },
  deactivate() {
    // 释放资源、取消订阅（可选）
  }
};
deactivate 只在应用退出与插件停用时调用。若你订阅了事件或持有句柄，建议在这里清理。 deactivate is called on app quit and plugin disable. Clean up listeners or handles you hold.

05上下文 ctx APIThe ctx API

ctx.commands.register(name, fn)
注册一个命令。fn 返回 Promise 或值；渲染层点击「设置 → 插件」页对应按钮时调用，返回值会以 toast 展示（对象会被 JSON 序列化）。注册前建议先 unregister 旧的同名命令，避免重复注册。 Register a command. fn returns a Promise or value; it is invoked when the user clicks the matching button on the Settings → Plugins page, and the return value is shown as a toast (objects are JSON-serialized). Unregister any previous same-name command first to avoid duplicates.
注意：重复 activate 不会覆盖，请自行 unregister。Note: repeated activate does not overwrite; unregister yourself.
ctx.events.on(name, cb) → unsubscribe
订阅应用事件，cb(payload)。返回一个取消订阅函数。见第 08 节事件一览。 Subscribe to an app event, cb(payload). Returns an unsubscribe function. See section 08 for the event list.
ctx.events.emit(name, payload)
向所有已启用插件广播事件（包括其它插件的同名监听）。可用于插件间协作。 Broadcast an event to all enabled plugins (including same-name listeners in other plugins). Useful for inter-plugin collaboration.
await ctx.engine.run(args, { script, timeoutMs }) → { code, result, out, err }
运行引擎 Python 脚本。script 为绝对路径或引擎目录内的文件名（如 'smart_midi.py'），args 为传给脚本的命令行参数数组。复用主程序的 Python 环境解析、UTF-8 中文路径适配与超时机制。 Run an engine Python script. script is an absolute path or a file name inside the engine directory (e.g. 'smart_midi.py'); args is the CLI argument array. Reuses the host's Python resolution, UTF-8 path handling and timeout.
约定：脚本在 stdout 输出一行 ###RESULT {json}，解析结果放入 result。超时（默认 30 分钟）时进程会被强制终止。 Convention: the script prints a line ###RESULT {json} on stdout; the parsed JSON lands in result. On timeout (default 30 min) the process is force-killed.
ctx.settings.get(key) / ctx.settings.set(key, value)
读写插件私有设置，持久化到应用的 settings.json（命名空间自动按插件 id 隔离）。值可以是任意 JSON 可序列化数据。 Read and write plugin-private settings, persisted in the app's settings.json (namespaced by plugin id). Any JSON-serializable value works.
ctx.ui.broadcast(name, payload)
向本插件的渲染层脚本发送消息，脚本以 window.addEventListener('fuplugin:<id>:<name>', ev => ev.detail) 接收。见第 07 节。 Send a message to this plugin's renderer script, received via window.addEventListener('fuplugin:<id>:<name>', ev => ev.detail). See section 07.
ctx.ui.notify(text, type)
在界面顶部弹出 toast 提示。type 可为 'info' | 'ok' | 'err'。 Show a toast at the top of the UI. type can be 'info' | 'ok' | 'err'.
ctx.log(...args)
输出到「设置 → 插件」日志区与主进程控制台，自动带插件名前缀。 Log to the plugin log panel and the main-process console, prefixed with the plugin id.
ctx.app.getSongMeta() → { fileName, trackCount, totalTicks, totalSec, bpm } | null
读取当前载入歌曲的轻量信息。未载入歌曲时返回 null。 Read light metadata of the currently loaded song. Returns null when no song is loaded.
ctx.manifest
本插件的 plugin.json 原对象（含 name / version / author / description）。 This plugin's raw plugin.json object (name / version / author / description).

06运行引擎脚本Running engine scripts

把需要 AI 能力的 Python 脚本放在任意位置，用 ctx.engine.run 调用。脚本与主程序共用 Python 环境与依赖，可直接 import 引擎模块（如 music2midi 的辅助函数）。 Place your Python script anywhere and call it with ctx.engine.run. It shares the host's Python environment and dependencies, and can import engine modules directly. 

const fs = require('fs'), path = require('path');
// 先落地一个脚本，再运行它
const script = path.join(ctx.manifest.id, 'scripts', 'enhance.py');
const r = await ctx.engine.run(['enhance', inMidi], { script, timeoutMs: 5 * 60 * 1000 });
if (r.code === 0) {
  ctx.log('处理完成：' + JSON.stringify(r.result));
} else {
  ctx.log('失败：' + (r.err || r.out), 'err');
}
脚本必须以 ###RESULT {json} 单行形式输出结构化结果，否则 r.result 为 null，但 r.out 仍包含全部输出。 Your script should print a single ###RESULT {json} line for structured results; otherwise r.result is null while r.out still holds all output.

07渲染层脚本 rendererRenderer scripts

renderer 指向的脚本会被注入界面环境，可操作 DOM、调用 window.fuBridge 与 toast()。主进程插件用 ctx.ui.broadcast 发消息： The renderer script is injected into the UI and can manipulate the DOM, call window.fuBridge and toast(). The main-process plugin sends messages with ctx.ui.broadcast: 

// ui.js —— 界面环境
(function () {
  const id = 'my-plugin';
  window.addEventListener('fuplugin:' + id + ':my-event', function (ev) {
    // ev.detail 即主进程广播的 payload
    toast('收到：' + (ev.detail && ev.detail.text || ''), 'ok');
  });
})();
渲染层脚本一旦注入，跨插件重载不会再次注入（按插件 id 去重）。渲染层异常不会影响主进程，但请自行 try/catch。 A renderer script is injected once per plugin id across rescans. Renderer errors do not affect the main process, but do wrap your code in try/catch.

09完整示例Full example

一个「歌曲信息卡片」插件：命令读取当前歌曲信息，监听载入事件，渲染层显示一条欢迎提示。 A “song info card” plugin: a command reads current song info, a listener tracks song loads, and the renderer shows a welcome toast.

// plugin.json
{
  "id": "song-info",
  "name": "歌曲信息",
  "version": "1.0.0",
  "author": "你",
  "description": "展示当前歌曲信息",
  "entry": "index.js",
  "renderer": "ui.js",
  "commands": ["showInfo"]
}
// index.js
module.exports = {
  activate(ctx) {
    ctx.commands.register('showInfo', async () => {
      const m = ctx.app.getSongMeta();
      if (!m || !m.fileName) return '尚未载入歌曲';
      return m.fileName + ' · ' + m.trackCount + ' 轨 · ' +
             Math.round(m.totalSec) + ' 秒 · ' + (m.bpm || '-') + ' BPM';
    });
    ctx.events.on('song-loaded', (m) => {
      ctx.ui.broadcast('song', { text: m && m.fileName });
    });
  },
  deactivate() {}
};
// ui.js
(function () {
  const id = 'song-info';
  window.addEventListener('fuplugin:' + id + ':song', function (ev) {
    toast('已载入歌曲：' + (ev.detail && ev.detail.text || '未知'), 'ok');
  });
})();

10开发建议与常见陷阱Tips and common pitfalls

  • 命令与事件回调保持异步安全：返回 Promise，或使用 try/catch，勿让异常抛出到主程序。Keep command and event callbacks async-safe: return Promises or use try/catch; never let exceptions escape to the host.
  • 勿在 activate 中做长时间同步阻塞（如同步读大文件）；如需耗时工作，用 ctx.engine.run 或异步接口。Do not block synchronously in activate; move heavy work into ctx.engine.run or async APIs.
  • 重复注册同名命令不会覆盖——先 unregister。Re-registering the same command does not overwrite — unregister first.
  • 插件之间通过 ctx.events.emit 协作时，注意避免互相触发形成死循环。When collaborating via ctx.events.emit, guard against mutual triggering loops.
  • 依赖其它模块请本地打包进插件目录，应用不保证全局 Node 模块存在。Bundle third-party Node dependencies inside your plugin folder; global modules are not guaranteed.
  • 设置的值会长期保留；改名或升级时做好迁移，避免读到旧结构。Settings persist; handle migrations on upgrade so stale structures don't break reads.
