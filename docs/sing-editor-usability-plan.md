## 0. 先说四个"会让用户觉得工具坏了"的实证问题

这些不是主观体验，是代码里能指到行的正确性缺陷，建议**第一个迭代就修**（改动小、风险低、收益立竿见影）。

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| A1 | **音量语义三处打架**：UI 显示「音量 0」、渲染载荷发 `volume: n.volume ?? 0`、而引擎默认是 **100**（`engine_utau.py` `volume=100.0`，`if volume != 100.0: out *= volume/100`）。留空 = 发 0 | `ViewSing.vue` 音量输入 `(tr.gainDb ?? 0)`；`singer.ts` `_renderUtau` 的 `volume: n.volume ?? 0`；`engine_utau.py:788,955` | 一旦走到 legacy 回退引擎，**整轨静音**；界面上也是「默认 0 音量」的误导 |
| A2 | **GENC 语义颠倒**：UI 是 `-100..100`（0 为默认），legacy 引擎是 **0..100、50=不变**（`_apply_gender` 的 `k=(v-50)/50`）。而 `renderPayload` 直接透传 | 同上 + `engine_utau.py:629` | 设 `GENC=0` 本意"不染色"，实际按**最男声**渲染；调 GENC 的结果不可预期 |
| A3 | **音量/表情的极性没标注**：OpenUTAU 的 `vol` 是"表情级"、而 UTAU 的 `g`/`B` 是相对量，界面只说"音量" | `_EXPRESSION_SPECS`（vol 默认 100） vs UI 文案 | 用户按"衰减 dB"理解，调完发现是"整体音量" |
| A4 | **撤销只覆盖钢琴卷帘内部**：`pushUndo/undo/redo` 全在 `PianoRoll.vue` 内，`singer.ts` 里**没有任何 history** | `PianoRoll.vue:248-399` vs `singer.ts` grep `undo|history` = 0 命中 | 改音量、效果链、自动化、轨名、歌词、渲染设置**都无法撤销**，误操作只能手工改回 |

> 另有一处"用了但没用上"的现成资产：`components/utau/VoicebankPicker.vue`（统一声库选择器，含 UTAU/DiffSinger 分类与计数）**全工程无人引用**；编辑器里选歌手还是手打**目录路径**文本框。

## 1. 现状盘点（编辑器已有的能力）

**布局**：左轨道列表（引擎下拉 / 轨名 / 歌手路径 / 语言 / 静音 / 音符数）＋右侧（工程文件条 → 显式栏 → 传输栏 → 轨道属性三页签 → MIDI 选轨弹窗 → 钢琴卷帘 → 音符检查器 → 音高曲线）。

**钢琴卷帘**（`PianoRoll.vue`，宿主通过 `api` 注入）：选择/框选/拖动/改长、画笔、吸附 1/4~1/32、双击改歌词、右键（撤销/重做/编辑歌词/删除）、`Ctrl+Z/Y/A`、`Delete`、方向键微调、±缩放、行高、音素条带、音高车道（移动/手绘/直线/正弦/平滑/清空）、横向滚动对齐。

**渲染**：渲染本轨 / 渲染全部轨（串行）、进度条、推理后端（自动/CPU/CUDA/DirectML）、UTAU 采样音、导出 WAV、伴奏与渲染结果同钟播放。

**工程**：.fufumidi 自包含工程包（新建/打开/保存/另存为），伴奏随包、缺文件有提示。

**参数**：UTAU（重采样器/波源工具/采样音 + velocity/GENC/气声 + 本轮新增 ATK/DEC/DYN/SHFT/CLR）、DiffSinger（深度/步数）、本轨效果链、自动化子轨（PIT/DYN/BRE/GEN/VOL/PAN）。

## 2. 问题清单与优先级

### P0 —— 正确性与"看得懂"（1 个迭代，改动集中在 3 个文件）

| 项 | 做法 | 影响面 |
|---|---|---|
| P0-1 修 A1/A2 语义 | 渲染载荷只在**用户真的设过**时才发 `volume/gender/breath`（当前无条件发）；GENC 与引擎 0..100/50 中位做**显式映射**并加注释；界面把「音量」改成「音量（表情级，100 = 原样）」 | `singer.ts`、`ViewSing.vue`、i18n |
| P0-2 默认值可见 | 所有留空即默认的输入框用 `placeholder` 显示引擎默认值（100 / 0 / 50），并在 title 里写清范围与方向 | `ViewSing.vue` |
| P0-3 全局撤销栈 | 把 history 从卷帘提到 `singer.ts`（快照 track / meta / fx / 曲线），卷帘调 store 的 `pushUndo/undo/redo`；`Ctrl+Z/Y` 做成**页面级**快捷键，覆盖音量、效果、自动化、歌词、轨名 | `singer.ts`、`ViewSing.vue`、`PianoRoll.vue`、单测 |
| P0-4 顶部工具条重排 | 拆成「工程 | 轨道 | 渲染」三段：设备后端与采样音下沉到**轨道属性 → 参数**（它们是"这条轨怎么渲"的），渲染主按钮加 prominent 样式，禁用时给**原因气泡**（无歌手/无音符/渲染中） | `ViewSing.vue` |
| P0-5 空态引导 | 无轨道时给三步卡（新建轨 → 导入 MIDI 或画音符 → 选歌手并渲染）；无歌手时在渲染按钮旁直接给「去选歌手」；无音符时提示"导入 MIDI 或切画笔" | `ViewSing.vue` |

**验收**：`npm run test:ui` 全绿 + 新增 `singer.undo` 单测；手工验收 A1/A2（legacy 引擎下音量不发 0、GENC=0 等于不染色）；渲染按钮的禁用原因与空态文案实测可见。

### P1 —— 高频操作提速（1~2 个迭代）

| 项 | 做法 | 备注 |
|---|---|---|
| P1-1 选歌手改成点选 | 启用现成的 `VoicebankPicker`（v-model 目录 + 引擎联动），保留"手输路径"为高级入口；未安装声库时给「去模型管理 → UTAU 声库」直达 | 需注意 DiffSinger 轨的语言/声库联动 |
| P1-2 渲染流程化 | 「渲染」→「试听」→「导出」三步条：渲完自动装载并播放；渲染中可取消（引擎已有 cancel 通道）；渲染全部轨显示"第 i/n 条 + 预计剩余"；完成后 toast 带"导出 WAV" | 复用 `sing_transport` |
| P1-3 页面级快捷键 | `Space` 播放/暂停、`Enter` 渲染本轨、`Ctrl+S` 保存工程、`[ ]` 切换页签、`Ctrl+Shift+Z` 重做；与卷帘既有键位不冲突（卷帘内优先） | 与 P0-3 一起做最省事 |
| P1-4 统一提示 | 现在消息散在 `msg`（编辑区顶）与各处 inline；收敛成一个 toast 区域 + 可展开详情，错误给"下一步该做什么" | 复用 `app.toast` |
| P1-5 轨道列表增强 | 拖拽排序、S/M 快捷、轨色、渲染状态徽标（未渲/已渲/已过期——音符改了要提示重渲）、双击轨名重命名、右键菜单（复制轨/清空/删除） | "已过期"能省掉大量"为什么没变化"的困惑 |
| P1-6 传输栏补常用件 | 循环区间、播放速度 0.25×~2×、跟随播放滚动、时间码点击输入定位 | 播放器已有实现，可参考复用 |

### P2 —— 向 OpenUTAU 靠拢的编辑深度（2~3 个迭代，逐项可独立验收）

| 项 | 做法 | 现状差距 |
|---|---|---|
| P2-1 卷帘编辑补齐 | 复制/粘贴/重复、切分（split）、合并、批量歌词输入（多选 → 一次填词/按空格分配）、力度工具（渐强/渐弱/曲线）、音阶高亮与键盘预览发声 | 现在只能一次改一个音符的歌词；无复制粘贴 |
| P2-2 音素级编辑 | 音素条带上点选单个音素 → 改 preutterance / overlap / 辅音速度 / 该音素表达式（引擎已支持 `phoneme_indexes` 精细指定） | 条带目前是**只读**；引擎侧能力已经就绪 |
| P2-3 工程级参数 | 全局 BPM 变化时音符不动/跟随、拍号、对齐偏移（整体平移 n ms 让歌词对拍）、工程模板 | 目前只能改 BPM 数值 |
| P2-4 参数车道补齐 | 现在自动化是**表格加点**；补成可拖拽的曲线车道（对齐 OpenUTAU 的曲线编辑） | `track_automation.js` 已有数据模型 |
| P2-5 声库可用性提示 | 歌词不在声库别名表里时，行内标红并给相近别名建议（引擎已回传 warnings） | 现在只在渲染后的 warning 列表里 |

## 3. 实施顺序与验收方式

1. **迭代 1 = P0 全部**（预计 1 个工作日内可交付）：先修 A1/A2（正确性），再加全局撤销与工具条重排；每项都在测试版里实测并截图，跑 `test:ui` + 新增单测。
2. **迭代 2 = P1**：按 1→2→3 的顺序，渲染流程化最容易感知。
3. **迭代 3 = P2**：先 P2-1（编辑效率）与 P2-2（音素级，引擎已就绪，只差 UI），再工程级参数与曲线车道。
4. 每轮结束后仍走"**你先测 → 通过后再构建安装包**"的节奏；安装包构建脚本已备好：`E:\Midi\构建并安装-5.0.0-beta.1.cmd`。

## 4. 我不建议现在做的

- **推倒重写编辑器布局**（对齐 OpenUTAU 的左侧工具面板 + 底部参数区）：收益是"像 OpenUTAU"，但代价是把已验证过的卷帘/传输/工程包全动一遍，回归面太大；先用 P0/P1 把易用性做上去，等真要上音素级编辑时再局部调整布局。
- **在 P0 阶段做音素级编辑**：它需要"选中音素 → 改属性 → 重渲"的完整交互链，属于 P2，硬塞进第一轮会拖慢正确性修复。

---

## 5. 需要你拍板的三件事

1. **是否按 P0 → P1 → P2 这个顺序走**？还是你更想先看到某个具体能力（比如"批量填词"或"音素级编辑"）？
2. **GENC 的界面语义**要哪种：`-100..100（0 不变，正=女声）` 更符合直觉，还是直接改成和引擎一致的 `0..100（50 不变）`？我倾向后者（少一层心算），但会改到界面习惯。
3. **撤销栈的粒度**：全局撤销（一次 Ctrl+Z 可能回退"多个音符的整体移动"）vs 分域撤销（音符/参数各自独立）。我倾向前者，实现简单且符合直觉。
