# 通用识别内置“智能分轨”方案（最少步骤）

> 目标：不新增页面、不新增向导，把分轨、逐轨转录、固定音色、合并全部收进现有“通用识别”的一次转录里。
> 用户步骤保持 3 步：拖入音频 → 选模型（可默认）→ 点开始。

## 1. 交互方案

现有“通用识别”面板只加一行：

```text
[✓] 智能分轨（推荐）  人声/鼓/贝斯/钢琴/吉他/其他自动分轨，避免串音与音色乱跳
```

规则：

- 默认开启（分轨模型已安装时）。
- 分轨模型未安装：开关置灰，右侧显示“去安装”，不阻止整曲转录。
- 钢琴专用模式不显示；MIROS 隐藏该开关（走整曲多通道拆分）。
- 用户不需要看路由表、不需要逐轨选模型、不需要新页面。

开始后仍只有原来那一个队列条目，进度文字按阶段变化：

```text
分轨 1/3 → 人声转录 → 鼓转录 → 贝斯转录 → 修正 → 合并音色 → 完成
```

完成后的行为与现在一致：队列里点结果载入编辑器，只是 MIDI 变成多轨且每轨固定音色。

## 2. 自动化流程

```text
点击“开始转录”
  │
  ├─ 检查：分轨开关 && 分离模型已安装
  │     否 → 直接走现有整曲转录（行为不变）
  │
  ├─ [A] 自动分轨（复用 engine:separate）
  │      默认 HTDemucs 6 stems；没有则 BS-Roformer 4 stems
  │
  ├─ [B] 自动逐轨转录
  │      roles: vocals / drums / bass / piano / guitar / other
  │      每根 stem 用固定默认模型，不弹路由表
  │
  ├─ [C] 逐轨修正（复用 smart_midi.py refine）
  │
  ├─ [D] 合并 + 固定音色
  │      每轨只保留一个 program_change；
  │      鼓走 9 通道；轨名固定
  │
  └─ [E] 输出原队列结果，载入编辑器
```

任何一步失败：

- 分轨失败 → 自动回退整曲转录，日志说明“未分轨”；
- 单根 stem 失败 → 其它轨保留，失败轨标记可重试；
- 合并失败 → 回退未合并的分轨 MIDI，不让整单失败。

## 3. 默认路由（全部内置，不暴露给用户）

| stem | 模型 | GM 音色 | 通道 |
|---|---|---|---|
| vocals | YourMT3+ | 52 Choir | 0 |
| drums | Basic Pitch | 鼓组 | 9 |
| bass | Basic Pitch / YourMT3 | 33/34 | 1 |
| piano | piano_pt | 0 Grand Piano | 2 |
| guitar | YourMT3 | 24/25 | 3 |
| other | YourMT3 | 48 Strings | 4 |
| 整曲兜底 | 用户选择的通用模型 | 按轨拆分 | 轮转 |

MIROS 不参与逐 stem 推理（5.36GB 太重）；MIROS 结果按通道/program 拆成多轨并固定音色。

## 5. 关键实现细节

### 5.1 音色不跳的保证

1. 每个 stem 输出一个独立 MIDI，不先合并；
2. 读入后删除该 MIDI 里除第一条外的所有 `program_change`；
3. 按 stem 角色写一个固定 `program_change`；
4. 通道分配：旋律 0–15，鼓固定 9；超过 16 轨轮转并写警告；
5. 同一轨禁止再出现第二种音色；如果模型原始轨道里有多个 program，先按 program 拆成子轨。

### 5.2 不增加等待感的进度

- 分离和逐轨转录共用现有队列进度，不新开第二个进度条；
- 阶段文字 + 当前 stem 名称即可；
- 低内存设备分离和转录串行，不做并行“加速”。

### 5.3 开关默认策略

- 已安装分离模型、且选择的是 YourMT3+/MuScriptor/Basic Pitch：默认开；
- 未安装分离模型：默认关并提示“去安装”；
- MIROS：开关隐藏，走整曲多通道拆分；
- 用户手动关掉后记住选择（localStorage/设置项）。

## 6. 分阶段交付

### P0（最小可用，4–6 天）
- `stem_merge.py` + 固定 program/通道；
- `main/stem-workflow.js` 自动分轨 → 逐轨转录 → refine → merge；
- ViewTranscribe 一个开关 + 阶段进度；
- 失败回退整曲转录；
- 单测 + 一首 30 秒素材 E2E。

### P1（体验）
- 单根 stem 重试；
- 分离结果缓存，重复转录不重复分轨；
- 低内存调度和开关记忆；
- 结果卡显示每轨音符数/警告。

### P2（质量）
- 接入 MDTK 式检测指标做评估；
- 评估 RefinPaint/MIDBACK 的离线可行性；
- 按角色微调默认模型，但 **仍不新增用户步骤**。

## 7. 验收标准

- 用户不进入任何新页面，只操作原“通用识别”面板；
- 开启时最终 MIDI 为多轨，每轨只有一个 `program_change`；
- 播放时同轨音色不再随段切换；
- 关掉开关时行为与当前版本完全一致；
- 分轨失败自动回退整曲转录，不出现“整单失败”；
- 8GB 机器不因分轨+转录串联触发 #35 的内存风险；
- 现有队列、模型选择、参数、导入编辑器路径保持不变。


## 9. 专用模型与音色丰富度（补充）

### 9.1 「一个专用模型」怎么定义

不新增需要用户逐个下载的模型矩阵，而是定义一个**智能分轨转录包**（资源中心一个条目）：

- 分离：HTDemucs 6 stems（固定一个）
- 转录：YourMT3+（固定一个，433MB）
- 乐器组标签：AudioSet tagger（**已随包内置 20.8MB**，不需要下载）
- 后处理：smart_midi（无权重）

用户只看到一个「智能分轨转录包」下载按钮；已安装的组件自动跳过。MIROS 作为可选高质包，不塞进默认包。

### 9.2 没下全模型时的自动分档

| 已安装 | 行为 |
|---|---|
| 分离 + YourMT3 | 完整分轨转录 |
| 分离 + Basic Pitch（内置） | 分轨 + Basic Pitch，质量降级但不失败 |
| 只有 YourMT3/其它通用模型 | 整曲转录，按 program/音域拆轨 |
| 什么都没有 | Basic Pitch 整曲兜底 |

开关不可用时只提示一次「去安装」，不阻塞现有转录。

### 9.3 音色是否足够丰富

- GM 128 音色 + 现有 SF2 库（GeneralUser、SGM、FluidR3、Salamander、Allvoice、Arachno 等）覆盖面够广，但**表现力有限**：固定 program 解决“音色乱跳”，不解决“听起来像真乐器”。
- 自动转录模型只能给出**乐器角色/音色族**，不能可靠推断演奏法、力度层次、音色品牌。
- 建议：每个角色绑定一个默认 GM program + 首选 SF2 预设（人声 Choir、钢琴 Salamander、鼓 Arachno 等）；用户仍可在编辑器里单轨换音色。不要为了让“音色更丰富”而让模型乱猜 program。
- 真正的“丰富”应来自音色库（SF2/VST3）与用户选择，而不是转录模型；模型负责声部归属和音高/时值。

### 9.4 是否要训练专用模型

- 现在不建议训练：没有公开的“分轨+多轨转谱+GM 角色”标注数据，训练成本和版权风险都高。
- 近期可做的是**工作流专用包**，不是新网络。
- 中期若要做，最现实的是微调 YourMT3+/MuScriptor 增加稳定 instrument token；不是从零训练。
- RefinPaint / MIDBACK 作为后处理研究项放 P2/P3，需权重与授权评估，不能作为 6.4.2 的阻塞项。


## 10. 30+ 轨复杂音频

### 10.1 先承认边界

没有任何消费级 6-stem/12-stem 分离模型能从一轨混音里可靠还原 30 条真实分轨。强行拆只会得到大量串音轨。产品不能把“30 轨”当默认承诺。

### 10.2 三条路线

1. **用户已有分轨（最稳）**
   - 直接选择“导入分轨文件夹”，每根 stem 一对一转录；
   - 这是唯一能保证 30 轨身份稳定的路径；
   - 不跑分离模型。

2. **无分轨，但可以接受组级结果**
   - 6-stem 粗分离；
   - 需要时再做二级分离：drums → kick/snare/cymbals/toms，other → 乐器组；
   - 输出 6–12 个“乐器组轨”，不强行拆成 30 轨；
   - 用户可在编辑器里再拆/合并。

3. **无分轨，又要 30 轨**
   - 不承诺逐轨还原；
   - 用多乐器 AMT（YourMT3+/MIROS）输出 instrument token，按 token/音域/角色聚合成最多 12–16 条可信轨；
   - 剩余细节标记为“未归类”，不冒充独立乐器。

### 10.3 轨道预算与 MIDI 限制

- 应用内部工程可以保留 30 轨；
- 标准 MIDI 只有 16 通道（9 为鼓），30 轨会复用通道，同一通道的 program_change 会互相覆盖；
- 因此导出时提供：
  - “组级 MIDI”（≤16 轨，推荐）；
  - “工程文件”（保留 30 轨，应用内播放）；
  - “多 MIDI 分卷”（按通道组拆成多个 .mid）。
- 不静默把 30 轨塞进 16 通道。

### 10.4 UI 不增加步骤

仍然只有原有“开始转录”：

- 检测到复杂混音时，结果卡提示“已按乐器组合并为 N 轨”；
- 高级选项里才出现“最大轨数 / 保留 30 轨工程”；
- 默认不弹出新页面。


## 11. 轨道数显示与用户选择

### 11.1 开始前：默认自动，但始终可见

通用识别面板增加一行，不新增页面：

```text
保留轨道：自动（建议 12 轨）  ▾
```

下拉项：

| 选项 | 行为 |
|---|---|
| 自动 | 按音频复杂度选 6–12 轨，默认 |
| 6 组 | 人声/鼓/贝斯/钢琴/吉他/其他，最稳定 |
| 12 轨 | 推荐，组内再细分 |
| 16 轨 | 单 MIDI 上限 |
| 全部候选 | 工程内保留全部，导出时再分组 |

用户不改也能直接开始；复杂音频才需要动。

### 11.2 运行中：显示候选数

进度文案增加：

```text
分轨 6/6 · 候选声部 23 · 转录 4/23
```

让用户知道“不是只有 6 轨”，而是在候选池里保留。

### 11.3 完成后：内联轨道选择

队列结果条目展开，不跳新页面：

```text
检测到 28 个候选声部
保留轨道：12 ▾   [合并同类（推荐） / 丢弃]

☑ 人声     Choir 52      1,245 音符   98%
☑ 鼓       鼓组            2,031 音符   96%
☑ 贝斯     Bass 33         890 音符   94%
☑ 钢琴     Grand 0         1,102 音符  91%
☑ 吉他     Guitar 24       540 音符    88%
☐ 合成器  Pad 89          310 音符    72%  → 合并到其他
...

[载入工程]  [保留全部候选]
```

用户有两种操作：

1. **改数字**：选择 6/12/16/全部，系统按“保留核心轨 + 合并同类 + 丢弃低置信度”重新分组；
2. **逐轨勾选**：精确决定哪些轨保留、哪些合并/丢弃。

默认不展开；点结果卡“查看轨道”才展开。这样简单音频仍是原流程。

### 11.4 轨道预算算法

输入：候选轨（role、program、音符数、置信度、重叠率）。

1. 固定核心：drums、vocals、bass、piano、guitar 各最多 1 条；
2. 其余按音符数 × 置信度排序；
3. 目标 N：
   - N < 核心数：把低置信度核心并入同类，不减鼓/人声；
   - N > 候选数：按 instrument token/音域拆分子轨，标注“拆分”；
   - N > 16：工程内允许，单 MIDI 导出提示分卷；
4. 被合并轨的音符不丢，进入同类轨；被丢弃轨明确标红提示。

### 11.5 导出规则

- 目标 ≤16：导出一个多轨 MIDI；
- 目标 >16：工程文件保留全部；MIDI 导出默认按 16 通道分组为多个 .mid；
- 不静默把第 17–30 轨塞进同一通道。

### 11.6 验收

- 开始前用户能看到“保留轨道”选项；
- 完成后展开能看到候选轨、置信度、合并去向；
- 改成 6/12/16/全部后，结果卡和实际 MIDI 轨数同步；
- 合并/丢弃不会改变鼓通道和已固定音色；
- 不展开结果卡时，仍是一键开始、一键载入。
