# 可视化**完全重做**方案（2026-10-17）

> 用户判词：「**效果很一般**」「**没有让琴键透明的选项**」「**是对可视化部分完全重做，参考 GitHub 上的项目**」。
> 这份是**重做方案**（不是继续打补丁）。前一版"分层重构"（`2026-10-16-viz-waterfall-fx.md` / `2026-10-17-viz-rewrite.md`）
> 降级为历史：那份只是把现有单体函数拆开，**技术路线没换**；本文换路线。

## 0. 为什么必须换路线，而不是再调参数

三条硬理由，全部有据：

1. **观感好的参考实现清一色 GPU 路线**：MIDIVisualizer（C++/**OpenGL**）、Neothesia（Rust/**WGPU**，README 自述依赖）、
   Pianola（Python/**GLSL**，"任意分辨率/帧率/**超采样**"）、Midi-Virtual-Piano（React/**three.js**）、
   3d-piano / 3d-piano-player（**three.js**）。我们用 Canvas 2D 单体函数在追它们的**结果**，但用的是**不同代**的工具。
2. **Canvas 2D 做不了它们的关键笔画**：着色器级泛光（阈值+多级模糊+色调映射）、**超采样导出**（Pianola 的核心卖点）、
   上万粒子的实例化绘制。我们只能用 `shadowBlur` + `drawImage` 缩放近似 —— 这就是"看着一般"的技术原因之一。
3. **现在的结构在**限制**能做什么**：`drawVizWaterfall` 一个 520 行函数把六件事写死；
   连"让琴键透明"这种层语义都要**逐个补乘 `globalAlpha`**，一漏就是 bug（上一轮实测漏了两次）。
   测试也被迫"按填充类型猜层"——测试在迁就实现，这是架构到顶的信号。

**结论：重做 = 换成「状态层（纯 JS，可测）+ 图元层（纯数据，可断言）+ 可插拔光栅器（WebGL2 主 / Canvas2D 兜底）+ 着色器后处理」。**

### 0.1 把"一般"量化（本方案的工具：`scripts/viz-lookcheck.py`）

拿 6 张参考截图（SeeMusic ×2 / 粒子流 ×2 / Synthesia / DoraPiano）与我们现在的渲染各量一遍
（`lum`=全图平均亮度、`keys`=底部 15% 键盘区、`fg%`/处`fgLum`=饱和亮元素占比与亮度、`colors`=量化色数）：

| 指标 | 参考实现 | **我们现在** | 判读 |
|---|---|---|---|
| **键盘区平均亮度** | **0.00 – 0.33** | **0.59 – 0.65** | ★ **元凶**：全画最亮的是**一大条白键盘**，音符被压成陪衬 |

## 2. 目标架构

```
frontend/src/core/viz/                 ← 全新目录，旧 core/viz.js 逐步退成 shim
  index.js         门面：createVizRenderer({ raster:'webgl2'|'canvas2d' })、render()、stats()
  state/
    timeline.js    音符 → 块（buildVizBlocks/visibleRange 的二分裁剪不变量照旧保留）
    layout.js      几何 + **相机矩阵**（正交默认；透视=键盘梯形与音符纵深收拢，统一用一个矩阵）
    themes.js      主题 = 调色板 + 材质 + 参数（**数据**；内置若干 + 用户命名主题，沿用现有 localStorage）
    palette.js     颜色工具（hex/rgb/hsl → rgba、混色、按背景亮度取可读色）
  scene/
    primitives.js  **图元列表**的数据结构与构造器（quads/胶囊/精灵/线/文字）
    compile.js     每帧把状态编译成 Primitive[]（这一层是纯函数 → 可单测、可断言）
    budget.js      每类图元的预算上限与丢弃策略（对标 MIDIViz 的 Max Items）
  raster/
    webgl2.js      WebGL2 光栅器：实例化 quad（音符/键面）、sprite 粒子、文字图集
    canvas2d.js    Canvas2D 光栅器：**同一份 Primitive[]** 的兜底实现（单测/离线台/无 GPU）
  post/
    bloom.glsl     阈值 + 多级模糊 + 加法合成
    vignette.glsl  暗角（"暗场要真的黑"）
    grade.glsl     色调映射/饱和度（可选颗粒）
  export/
    offline.js     离屏 + **超采样**（Pianola 式：任意分辨率/帧率/SSAA）+ 透明 alpha 输出
```

**数据模型（关键）**：`Primitive = { kind, layer, z, geo, color, alpha, blend, budgetKey }`
- `layer` ∈ `background|notes|impact|keyboard|particles|overlay` → **每层的开关/透明度/顺序都是数据**（琴键透明=层属性，不再补乘全局状态）
- `budgetKey` 让"粒子/冲击环/光柱"各自有上限（对标 MIDIViz 的 per-node Max Items）
- 语料：**"画什么"是纯数据，"怎么画"由光栅器决定** → 测试断言图元列表，不再"按填充类型猜层"

**管线**：`state → compile（Primitive[]）→ raster → post → 合成`；
实时与导出**只差一个渲染目标与超采样倍数**（同门面、同状态、同图元）。

## 11. 用户验收后的推倒重做（2026-10-17 晚）

用户看过安装版后给出四条硬伤，全部实测复现并**推翻重做**（不是打补丁）：

| 用户原话 | 实测根因 | 处理 |
|---|---|---|
| 「键盘透视做得很差，粗暴的拉伸」 | ① 透视只作用于**键面上边**（音符落点边），下边与前脸不动 → 键与音符列错位；② 横向扇形系数 1.15 让最边缘黑键斜成 ~65° | 重写 `scene/keyboard.js`：一台相机 `project(u,t,h)`，**t=0（落点线）恒等**所以音符永远对得上键；横向收敛 0.04、纵向用 1/z 做透视缩短（**上一版方向是反的**）；默认 `persp=0`（平板，与 Synthesia/SeeMusic 同路线），滑块拉到 1 也只是温和倾斜 |
| 「琴键做得一塌糊涂，被割裂了」 | 数组圆角 `r:[0,0,4,4]` 在 WebGL 打包成 **NaN** → SDF 退化成整块药丸（上下都圆），与方前脸断开 | 光栅层支持 canvas 的 [TL,TR,BR,BL] 语义（按上/下两组半径做 SDF）；高亮/闪光/标签与键面**共用同一个 quad**；补白键分隔线（主题里 `wkLine` 一直是死数据） |
| 「是调节音符的透明度，而不是琴键」 | 滑块本身没错（琴键带 Δ=75，音符区 Δ=0.4）；但音符当时渲染成半透明白块，看着像"透明度调到音符上了" | 音符变白是下一行的原因；现在实测琴键带 Δ=75.05 / 音符区 Δ=0.42 |
| 「配色不够自由，除了轨道色生效，其它选项都不生效」 | ① `noteColor` 先判 `colorBy` 就 return → "配色档"在选了按音高后**整排失效**；② 返回 `hsl()` 字符串而 **WebGL 颜色解析只认 hex/rgb** → GPU 路径静默变白（数据变了、画面没变） | 重写 `state/colors.js`：**两条正交轴**（取色方式 × 调色参数），预设只填参数、填完还能拖；**统一输出 #rrggbb**；光栅层补 hsl 解析兜底 |

**顺带揪出两个死开关**：`gloss`（音符质感）与 `keys3d`（3D 键盘）在面板里存在、渲染层却没人读 —— 已接上真行为
（实测从 0.2% 噪声变成 5.16% / 0.73% 的真实像素变化）。

**验证方式（这次换了判据）**：区域均值会把几个小光点摊平到 0.2 以下，于是"开关其实生效"被误判成"没反应"。
改成**逐像素统计改变比例**后，**20 个面板控件全部证实改变画面**（0.21%–99.9% 像素，最大差 139–221）。
新增 `viz-keyboard.test.js`(8) 与 `viz-colors.test.js`(10)；像素对齐同时变好（全帧平均差 1.04 → **0.65/255**）。

> **M3 实测（着色器后处理）**：`post/glpost.js` —— 软膝阈值 → 1/2·1/4·1/8 三层倍频带各自 9 抽头分离高斯 →
> 权重 0.30/0.20/0.11 累加 → 加进场景 → 蓝通道 lift/gain 调色 → tanh 肩部（拐点 0.63 以下恒等，白点 0.95）。
> **1080p 单帧后处理 0.1 ms**（有链 0.3 ms vs 无链 0.2 ms；计划要求 ≤1.5 ms）。视觉：音符由"平色块"变成"发光体"，
> 命中线出现光晕，强档（bloom 1.2）与霓虹主题均不过曝。采样图见 `_attic/vizrender/v3-*.png`。
> 同一纹理不能同时作输入输出 → 每层倍频带各配独立临时贴图（否则是 WebGL 未定义行为）。

> **M2 实测结果（本机 RTX 5070 Ti / ANGLE-D3D11）**
>
> - **像素对齐**：真 Chromium（Electron 33）里跑两条光栅路的逐像素比对，1920×1080 / 265 图元 / 同一 song+tick。
>   全帧平均差 **1.04/255 = 0.41%**；**99.4% 的像素差 ≤ 8/255（3%）**；残差集中在细线与胶囊的边缘覆盖
>   （canvas 的解析 AA vs SDF 覆盖）。分类型平均差：径向光 0.49 · 线 0.16 · 光柱 1.29 · 矩形 1.13 · 胶囊 1.68 · 暗角 0.06。
> - **真机后端**：安装版内 `vizRasterInfo()` 返回 `webgl2` + `ANGLE (NVIDIA … D3D11)`；
>   应用层每帧 rAF 回调 CPU **p50 3.3 ms / p95 4.6 ms**（2310×1200 设备像素，dpr 2.5）。
> - **推翻了本计划 §0 的一个前提（重要）**：浏览器里的 Canvas2D **本身就是 GPU 加速**（Skia）。
>   纯光栅基准：canvas2d **0.55 / 0.53 / 0.57 ms** vs webgl2 **0.50 / 0.45 / 0.38 ms**（1080p / 1440p / 4K，1.1–1.5×）。
>   先前引用的"28.9 ms @1080p、100.6 ms @4K"是 **Node 离线台**（`@napi-rs/canvas`，纯 CPU）的数字，
>   不能代表应用内表现。→ WebGL2 存在的理由改为：**着色器后处理（M3 的前提）**、逐图元可编程、导出与预览同一条链；
>   **不再声称"光栅速度提升"**。Canvas2D 后端继续作为回退保留（不支持 WebGL2 的机器自动走它）。
> - **顺带修掉两个真 bug**：① `compile.js` 落点光晕写成 `P.glow(..., 大半径, 0)`（内外半径相等），
>   按 canvas 规范该渐变**什么都不画** → 光晕一直是不可见的；② `packPrims` 跳过 text 图元时多减一次实例计数，
>   真机上只要有文字图元就会损坏打包。
> - 验证台与基准都在 `E:\Midi\_attic\vizrender`（`parity-main.cjs` / `gl-perf.cjs` / `bench.cjs`），
>   属于一次性工具，**不进仓库**；仓库里留下的是纯函数单测 `frontend/tests/viz-raster.test.js`（8 条）。

## 6. 验收标准

1. **观感（革新）**：`python scripts/viz-lookcheck.py` 的指标表达标 ——
   **键盘区 ≤0.35、背景 ≤0.14、前景 0.40–0.70、对比 ≥4×、色数 ≥150**；
   音符（不是键盘）是画面里最亮的东西；附"参考 vs 新渲染"并排对照图，**由用户判定是否够革新**。
2. **功能**：★琴键不透明度 0..1、★隐藏、★只显按键 —— 面板可调且**导出同效**。
3. **性能**：真机 1080p ≥ 60 fps（≤ 16 ms/帧，目标 ≤ 6 ms）；`renderer.stats()` 报**每层耗时**；导出 4K + SSAA2× 可离线跑（不要求实时）。
4. **可测**：图元列表单测（层顺序、每块一次、透明度、预算上限）；像素对齐测试（两个光栅器）。
5. **同源**：实时与导出只有一个门面 `createVizRenderer()`。
6. **确定性**：同 tick 两遍 PNG 字节一致（随机量继续走 `noise(seed)`）。
7. **导出**：透明档 alpha 正确（含预乘处理）；超采样档可出图。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| Electron 里 WebGL2 在某些显卡/驱动上不可用 | 门面自动降级到 `raster:'canvas2d'`（同一份图元），并在面板显示当前光栅器 |
| 导出录制与 WebGL 双缓冲不同步 | 导出走 `export/offline.js`：`preserveDrawingBuffer:true` 或渲染后立刻 `readPixels`/`drawImage` |
| 双光栅器漂移 | 只有一份 `Primitive[]`；像素对齐测试进 CI |
| 重构期"实时与导出不一致" | 门面唯一入口；`viz.js` shim 期两条路都指向新 renderer |
| 大改造成半成品长期并存 | M1 就建立 shim 与判据（逐像素一致），M6 强制删除旧实现 |
