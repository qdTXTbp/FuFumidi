# 界面设计语言重构（M1–M5）

- 起因：用户要求按米哈游系的资源（GDC 演讲、Curio 风格指南、HoYo-Glyphs，以及中文社区对
  字体/对比度/按钮字重的批评）**读并重构应用的界面设计语言**。
- 用户四项决定：① 字体**全部内置**；② 按我的建议取舍；③ **保留浅色但主推深色**；④ **外壳结构不改**
  （顶栏 + 左侧栏 + 内容区 + 底部播放条）。
- 目标不是"换皮"，而是**把散落的手写集合换成设计语言**：字号/间距/圆角成阶、颜色只有一个来源、
  并有脚本守着不让它长回去。

## 做这件事时踩到的坑（都留了护栏）

1. **codemod 的"CSS 区段"必须排序**。`.vue` 里 `<style>` 块与模板 `style="…"` 天然不同序，
   不排序会让区间互相包含，实测把 `ViewSing.vue` 整块复制了一遍（3439 → 4781 行）。
   → 现在每次都做**结构不变量校验**：`<style|template|script>` 标签数、行数必须与 HEAD 一致。
2. **替换颜色要连引号一起吃掉**。`'#ea5ec1'` → `themeColor('--data-7', '#ea5ec1')`；
   只替换 hex 本体会得到 `'themeColor(…)'` 这种"字符串里的 JS"，实测把构建打红两次。
   → codemod 现在产出后立刻断言，发现 `'themeColor(` 就抛错不写盘。
3. **兜底位置不许再包一层**。`cssVar('--a','#hex')` 里的 hex 是合法兜底，
   再包会变成 `cssVar('--a', themeColor('--b','#hex'))`。
4. **纯层不许碰 DOM**。`core/viz/**` 是 Node 单测的纯状态层、`core/util.js` 是通用工具；
   给它们注入 `import palette.js`（间接引 `theme.js`）会让 typecheck/测试直接红。
   作用域限定为 `components/**` 与 `views/**`。
5. **`git checkout` 会把工作区还原成 CRLF**，之后用 LF 字符串做匹配的重放脚本会全部失效 ——
   重放脚本一律用 `\r?\n` 无关的匹配。
6. **别用 PowerShell 的 `Set-Content` 改源码**：默认编码会把 UTF-8 中文写成乱码，
   实测把 `ViewViz.vue` 写坏到解析失败。源码改动一律走 edit 工具或 Node 脚本。
7. **`node --check` 挡不住语义错误**（上一轮的教训）；这一轮改成"每条 codemod 之后跑
   typecheck + build + 260 个单测 + 结构不变量"，四处都绿才继续。
8. **棘轮基线要连"误判"一起修**：注释里的色号、`css('--x','#hex')`、`|| '#hex'`、
   `var(--x, #hex)` 都是合法的，一开始全被计入违规（70 处里有一半是误判）。
   守门脚本的价值在于**判据准确**，否则大家会习惯性无视它。
