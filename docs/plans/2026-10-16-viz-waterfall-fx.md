# 瀑布流视效升级方案（2026-10-16）

> 起因：「根据以下内容对可视化瀑布流的视效进行升级」（用户给了 SeeMusic / Synthesia / Lumiric Stage /
> DoraPiano / Echo Moss 等一整套参考清单）→ 随后「查看那些网址里的样式，丰富本工具的瀑布流视效」
> → 再「配色归入视效」→ **本文 = 把这轮调研与改动整理成可评审的方案**。

## 0. 一句话

把现在的瀑布流从"能看"升级到 SeeMusic 那一档的观感：**发光胶囊（白热内芯）+ 落键光柱 +
击键线波纹与冲击环 + 3D 键盘 + 键名标注**，并且全部**开关化**（可一键回旧观感）、
**实时与视频导出共用同一份设置**（预览 = 成片）、**逐帧可复现**（同一次导出重跑画面一致）。
配色从工具栏独立 chip 并入「视效」面板。

## 1. 目标与非目标

| | 内容 |
|---|---|
| ✅ 目标 | 观感对齐参考；每笔效果可关（关掉要**逐像素回到旧观感**）；实时/导出同源；确定性；成本可测 |
| ❌ 非目标（另立） | 真 3D 透视键盘 / 钢琴内部机械、**钢琴卷帘（横向时间轴）模式**、按手分色、OBS 叠加预设、MIDI 输入实时演奏 |

## 3. 五种主流样式 × 取舍

| 样式 | 参考里长什么样 | 取舍 | 落点 |
|---|---|---|---|
| **音符下落** | 发光胶囊、白热内芯、按力度分亮度 | ✅ **已升级** | `fx.gloss`：胶囊圆角 + 白热内芯 + 落点光晕 + 下落边高光 |
| **粒子与光效** | 击键迸火花、**光柱**、**冲击波环**、体积光雾 | ✅ **已升级** | `fx.particles` / `fx.beams` / `fx.hitLine`：加色混合 + 贴图发光 + 三类粒子 |
| **3D 键盘** | 键有厚度、有台面、按键下沉、光打在白键上 | ✅ **已做"厚度版"**；真透视不做 | `fx.keys3d`：键面 + 前脸 + 顶边高光 + 按压下沉 + 向上的光 |
| **钢琴卷帘** | 横向时间轴滚动、左侧竖键盘 | ⏳ **本轮不做**（是另一种可视化，不是瀑布流的视效） | 见 §9 后续 |
| **琴键高亮反馈** | 按键发光、颜色跟随音符、余辉 | ✅ 已有 + **增强** | 原有余辉 + 按键向上洒光 + 击键线波纹 |

## 4. 改动前已有什么（避免重复造）

下落块（轨道色/按音高推导的两套配色）、击键线发光、琴键余辉（0.09 衰减）、粒子（**2px 圆点**，上限 260）、
音乐能量驱动的背景光晕、背景四档（主题/纯色/图片/透明）、**实时与视频导出共用 `core/viz.js`**。

## 5. 本轮已实现（可直接评审）

### 5.1 开关与归属

- `core/viz.js` 新增 **`FX_DEFAULTS` = 单一来源**：`keys3d / particles / beams / hitLine / gloss / keyNames`，默认前五项开、键名标注关。
- `stores/vizbg.ts` 持久化并暴露 `fxOpts()` —— **与背景同一个 store、同一个 localStorage 键**，
  所以「可视化」页与「导出视频」页读的是同一份（这是背景那次踩过的坑：两套设置 → 预览与成片不是一幅画）。
- 「可视化」页新增 **「视效」chip + 面板**；**配色（轨道色/按音高·七彩/暖/冷）从工具栏并入该面板**（用户要求）；
  面板里有 **全开 / 全关**，全关 = 逐像素回旧观感。

### 5.2 视觉（对照参考逐条落地）

| 改动 | 实现要点 |
|---|---|
| 粒子 2.0 | 加色混合 `lighter`；**按颜色缓存 64×64 发光贴图**（每帧只 drawImage，不每帧建渐变）；火花 / 冲击波环 / 光柱三类；上限 260 → **420** |
| 3D 键盘 | 键区高度拆「键面 72% + 前脸 28%」；顶边高光；按下 → 键面变短（**顶边不动**，见 §7 不变量） |
| 击键线 | 整条线**脉冲光带**（约 0.8 s 衰减，脉冲统一衰减与开关无关）+ 每个发声音的**半圆波纹** |
| 音符 | 胶囊圆角（半径取半宽/半高上限）+ **白热内芯**（竖渐变叠加）+ 落点光晕 + 下落边高光 |
| 光柱 | **三层嵌套渐变**：canvas 渐变只能沿一个轴，单层左右是硬边（离线台实测像红纸条） |
| 键名标注 | 默认关；白键宽 ≥14px 才画（Synthesia 那种跟弹辅助） |

### 5.3 验收证据（本轮实测）

- **单测**：`frontend/tests/viz.test.js` **9/9 通过** —— 它守着两条硬不变量：
  ① 每个屏内音符块**恰好一次 `roundRect`**、颜色仍是调色板**纯色**（所以新效果只能用 arc / fillRect / 渐变叠加）；
  ② 「第一个 y === wN 的 roundRect」= 琴键起点（所以 3D 键面必须仍从 wN 起）。
- **门禁**：`typecheck` / `audit` / `test:ui`（**225**）全绿；`build:ui` 通过；已 `deploy-installed` 冒烟通过。
- **像素**：新建**离线渲染台** `E:\Midi\_attic\vizrender\render.mjs`（`@napi-rs/canvas` + 真实 `drawVizWaterfall`），
  输出 `fx-on.png` / `fx-off.png` 对照 —— 见下图。为什么不用安装版截图：窗口被遮挡时 Chromium 不重绘，
  `Page.captureScreenshot` 拿到的**一直是旧帧**（实测 5 次），改从 canvas 后端取才可靠；离线台还能逐帧复现。
- **成本**（离线台，1920×1080，200 帧）：

  | 配置 | ms/帧 | 帧率上限 |
  |---|---|---|
  | 旧观感（全关） | **3.98** | 252 fps |
  | 全开 | **9.19** | 109 fps |
  | 倍率 | **2.31×** | — |

## 6. 待你定的决策

| # | 决策 | 选项 | 建议 |
|---|---|---|---|
| **D1** | 新视效是否**默认全开** | ① 全开（可一键全关）② 默认关，用户自己开 | **①** 观感提升是这轮的目的；有「全关」兜底 |
| **D2** | 是否加**性能档位**（高/中/低） | ① 加 ② 不加 | **①** 因为 4K 导出 24fps 的预算是 **41 ms/帧**，全开在 1080p 已 9.19 ms，4K 约 4 倍像素 → 很紧 |
| **D3** | 键名标注默认 | ① 关 ② 开 | **①** 它是教学辅助，平时是噪点 |
| **D4** | 要不要做**钢琴卷帘（横向）模式** | ① 本轮不做 ② 立刻做 | **①** 它是第三种可视化，值得单独立项（不是"瀑布流的视效"） |
| **D5** | 按手/按轨分色 | ① 等有分轨信息再做 ② 现在就按轨分 | **①** 现有配色已按轨/音高 |
| **D6** | 真 3D 透视键盘（梯形键 + 灭点） | ① 不做 ② 做 | **①** 收益小于每帧成本；当前"厚度版"已拿到体积感 |

## 7. 验收标准（回归时照这个跑）

1. `node --test frontend/tests/viz.test.js` **9/9**（两条硬不变量不能破）。
2. `npm run typecheck / audit / test:ui` 全绿；`npm run build:ui` 通过。
3. **像素对照**：`node E:\Midi\_attic\vizrender\render.mjs` → `fx-on.png` 与 `fx-off.png` 必须肉眼可辨；
   「全关」应当与升级前**逐像素一致**（这是开关的语义）。
4. **确定性**：同一 tick 连跑两遍，PNG **字节一致**（随机量全走 `noise(seed)`，禁 `Math.random`）。
5. **同源**：在「可视化」页改任一开关，导出页预览立刻同效（读写同一 store）。
6. **成本**：1080p 全开 ≤ 12 ms/帧；4K 导出若用中/低档，需 ≤ 41 ms/帧（D2 定档后补测）。
7. **安装版**：`deploy-installed.cjs` 冒烟通过 + 手工切到「可视化 → 瀑布流」目视。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 逐帧成本（渐变/粒子） | 发光贴图按颜色缓存；粒子上限；三层光柱只在**短命**粒子期；D2 档位兜底 |
| 视觉过载（参考站都很浓） | 默认强度保守；「全关」一键回退；键名标注默认关 |
| 参考站不可达/改版 | 关键画面已落到 `_attic\vizref`（22 张），不依赖实时联网 |
| 预览与成片不一致 | 所有开关与背景同走 `stores/vizbg`（背景那次已经踩过一回） |
| 破坏既有不变量 | 单测里明确写着「新效果只能用 arc/fillRect/渐变，块本身仍是一次 roundRect + 纯色」 |
