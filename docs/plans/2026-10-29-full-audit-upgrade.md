# FuFumidi 全量产品审计与升级方案（审阅稿）

- 版本基线：6.2.9（当前正在发布）
- 审计日期：2026-10-29
- 范围：产品功能、MIDI 制作、调教/编辑、乐谱/OMR、转录、分析、编排/影视、转换/视频、资源/插件、设置/外观、任务中心、前端布局与可访问性、后端引擎、性能、包体、代码质量
- 方法：全量源码静态审计 + 已有测试/性能/已知问题文档 + 本机安装版实测 + GitHub/同类工具调研
- 说明：本文件是审阅稿。未批准前不执行功能重构；仅完成 6.2.9 版本更新上传。

## 0. 结论

FuFumidi 的能力广度已经超过多数开源 MIDI 工具：从音频转录、钢琴卷帘、CC/演奏法、调教/UTAU/DiffSinger、乐谱刻版/OMR、分离/翻唱，到视频导出、插件和 Wallpaper Engine。真正的问题不是“功能少”，而是：

1. **入口与状态重复**：同一设置有两套实现，核心工作区在默认窗口就被裁切。
2. **功能深度不均衡**：编辑器/转录已有专业级骨架，但校对、质量反馈、批量工作流和参数可解释性不足。
3. **工程债开始反噬体验**：24 个视图、2 万行视图代码、多个 2000~3600 行的单文件；小改动容易产生跨模块回归。
4. **包体与运行时偏重**：安装后约 2.1 GB，Python 运行时 1.6 GB；首装和更新成本高。
5. **可访问性和 i18n 是明显短板**：键盘无法完成核心列表操作，159 个中文键缺英/日翻译。

## 2. P0：先修“默认配置就坏”的问题

### P0-1 两套“界面缩放”相乘

证据（详见 frontend-ux.md）：

- 编辑器视图菜单写 stores/workspace.ts 的 layout.scale，App.vue 无条件写 document.documentElement.style.zoom。
- 设置/外观走 core/display.js 的 bridge.setZoomFactor。
- 1.15 × 1.30 = 1.495，980px 最小窗口的布局视口掉到约 655px；媒体查询、检查器、曲目标签栏全部异常。

修法：

1. 以 core/display.js 的 ui_scale 为唯一真源。
2. workspace.layout.scale 改为兼容别名，读时归一化，写时转发。
3. 删除 App.vue 的 CSS zoom 与 data-ui-scale 双写。
4. 迁移旧 localStorage，保留 100% 一键恢复。
5. 视觉回归：980/1280/1585 × 100%/115%/130%。

### P0-2 编辑器主工具条默认窗口溢出

- 默认窗口 1280，可用宽度约 932px；工具条自然宽超过 1237px，约 300px 被裁。
- 代码自带注释承认 1585px 时“全屏”已不可见。
- 补救方式是把检查器/全屏/谱面底图在“更多”里再放一遍，形成重复控件。

修法：

1. 工具条按“工具 | 视图 | 编辑 | 更多”两行或响应式溢出菜单。
2. 删除“更多”里的重复开关，只保留低频动作。
3. 980/1280/1585 三档截图验收；不出现横向滚动条。

### P0-3 设置中的外观页签不存在

- SettingsPanel 的 TABS 没有 appearance，但整套外观段仍挂着。
- 搜索索引有 7 条指向 appearance，14 条没有 data-setting 锚点，点击静默无反应。
- 用户从设置搜索进入后，页签高亮错位、内容却是外观。

修法：保留外观抽屉为唯一入口，删除设置里的外观段；搜索索引改成 action 型目标；补锚点或 toast。

### P0-4 混音台语义错误

- 外观是 per-track，实际效果是 per-channel（PlayerBar.vue 自己注明）；同通道多轨会一起变，界面无提示。

修法：明确“轨道音量”和“通道音量”两层；per-track 用增益节点，per-channel 用 MIDI 通道 CC；UI 显示联动提示；增加回归测试。

### P0-5 外观/主题/壁纸入口重复

- 外观抽屉、设置外观段、TopBar 死函数、首页、引导、命令面板、主题库、壁纸库之间至少 6 条路径。
- 两套实现写不同存储，云同步/换机结果不一致。

修法：唯一入口 + 单一状态源；删除 TopBar 死导航、旧 WallpaperGallery 入口；保留兼容迁移。


### P0-6 卷帘没有音符试听（D 级）

- EditorCanvas 的 onDown 没有发声道，player 也没有 previewNote 接口；反馈只能整段播放。
- 这是 MIDI 编辑器最基本的反馈回路，直接影响画音、移调、和声判断。
- 修法：synth 增加 previewNote(midi, vel, duration)，接到落音/点击/移调/键盘预览；加试听开关与音量，避免触发 program change。

### P0-7 多选拖动只移动一个音

- 卷帘分支 dragState.notes 固定为单元素；同文件的乐谱视图却使用整个 selection，说明是漏写。
- 影响转谱校对、移调、和声改写等最高频操作。
- 修法：拖动起点取整个选区，统一施加 dTick/dMidi；顺手补 Ctrl+拖拽复制。

### P0-8 任何编辑都重置走带位置与循环区间

- afterEdit 无条件 player.load，load 把 pausedTick 归零、循环清空，再把循环重设为整曲。
- 「循环里打磨一个乐句」这一核心动作被击穿。
- 修法：快修是 load 前保存/恢复 pausedTick、loopStart、loopEnd、playing；正解是 Player.patchSong 增量重排。

### P0-9 撤销语义错误

- 整轨 JSON 快照 ×80，无标签；逻辑编辑器/宏是改完才 push，撤销等于恢复改后状态。
- 9 万音符单轨每步约 3~4 MB，80 步数百 MB。
- 修法：先修三处 push 时机；中期改命令式撤销（before/after 闭包），历史面板显示操作名/真实时间。

### P0-10 编排片段不参与播放

- 编排只写 song.arrange，播放器读 song.tracks；clip 移动/裁剪/静音对声音无效。
- 编排页目前是示意图，不能作为编曲试听闭环。
- 修法：播放前按 clipsRenderJobs 把 clip 映射为事件，应用编排轨 mute/solo；无 arrange 时保持旧行为。

### P0-11 内置音色下 CC/踏板/弯音静默丢弃

- 桌面端默认内置合成器；synth.midiEvent 在 sf2Ready 为假时直接 return。
- 用户画的表情/踏板/弯音默认听不到，只有导出 MIDI 后在别的 DAW 生效。
- 修法：内置合成器实现最小子集（bend、CC7、CC11、CC64、CC1），不支持的参数在泳道标注“当前音色不生效”。

### P0-12 乐谱视图无法表达跨小节时值

- 无连音线、无小节内临时记号、无小节内休止、无连拍；长音只画起始小节。
- 当前五线谱只能当音高分布图，不能给演奏者看，也不能当校对依据。
- 修法：长期用 Verovio 渲染可点击谱面，Canvas 保留卷帘；短期明确改名为“音高视图”，避免承诺制谱能力。

### P0-13 全局快捷键劫持编辑页

- 调教页 1~9 改时值，同时 App 全局数字键切歌单/跳曲库；N/P 换歌。
- App 只判断输入框，不知道当前视图，一次输入就丢上下文。
- 修法：全局快捷键按视图/焦点分区，编辑页优先；快捷键表与实现同源，可配置。

> 以上 P0-6..P0-13 来自 midi-workflow.md 的静态审计；报告第 9 节给了 12 条“点一遍即可复现”的清单，建议在排期前先实测确认，避免把运行时行为误判成源码缺陷。

## 4. MIDI 制作、编辑与调教

### 4.1 编辑器：从“功能很多”到“专业工作流”

已有优势：

- 卷帘、步进、列表、鼓组、CC、表达映射、音阶/和弦、量化/groove、逻辑编辑器、宏、跨轨、自动化和 MIDI 2/MPE 基础。
- 参数化 MIDI 工具带实时预览和单撤销点。
- 音频对齐、智能伴奏、帧吸附等差异化能力。

主要差距：

1. 工具条信息架构和重复控件（P0-2）。
2. 专业 DAW 的“选择语义 + 修饰键矩阵 + 右键上下文”不完整；部分选择/工具靠记忆。
3. 音频轨/片段/comping 没有形成完整闭环，编排页和编辑页仍是两套。
4. 大曲目内存与重绘：60k 音符 529ms，JS 堆增加约 34MB；缺少 LOD/虚拟化。
5. 自动化和速度/拍号编辑的入口分散，表达映射未覆盖 PC/通道/力度全链路。
6. MIDI 2/MPE 有数据层，但缺少可视化/编辑闭环。
7. 撤销是快照式，超大工程的内存与粒度需要评估。

升级方案：

- 6.3.0：工具条两行化、上下文工具条、删除重复入口、统一选择/修饰键、编辑器内 ? 快捷键表。
- 6.3.1：轨道/片段/音频轨统一；Chord Track 与音阶约束；表达映射编辑器；CC 目标扩展；大曲目 LOD/虚拟列表。
- 6.4：MIDI 2/MPE 编辑视图；速度/拍号自动化；VST3/CLAP 与外部音源。

### 4.2 转录：把“结果”变成“可校对的质量”

已有优势：

- 多模型、GPU、分离、标签模型、队列、长音频保护、零音符保护、并集探测、时长估算。
- 质量门禁覆盖合成样本。

差距：

1. 没有面向用户的 note F1 / onset F1 / 置信度显示，用户无法判断“哪里该改”。
2. 没有“音频证据 + MIDI 结果”的校对视图和人工接受/拒绝。
3. 长音频存在已知僵尸音（KI-4）；max-note-hold 默认关闭。
4. 模型选择缺硬件/曲风推荐；首次下载/显存压力不透明。
5. 质量基准只用合成样本，真实模型 F1 未纳入门禁。
6. 转录后处理（量化、去短音、证据收尾）分散，缺少一键“清理并试听”。

升级方案：

- 6.3.2：质量面板（note/onset/pedal F1、置信度、长音/异常统计）+ 音频/MIDI 双视图校对 + 人工接受/拒绝 + AB。
- 长音频：明确 tie 语义修复，提供 15/30/60s 上限作为可选保险；断点/分段结果缓存。
- 模型中心：硬件推荐、显存预算、模型包分层（核心/可选/离线）。
- 回归：真实素材 F1 基线纳入 quality 门禁。

### 4.3 调教/歌声合成

已有优势：

- UTAU/DiffSinger 双引擎、参数曲线、音素条带、音高曲线、oto 编辑、声库管理、增量渲染/A-B 基础。

差距（已有方案文档已指出）：

1. 音素边界不能拖，音素时值/辅音速度不可精细编辑。
2. 曲线工具仍不完整（画线/平滑/复制/参考轨叠加）。
3. 渲染只能整轨或大范围；缺少按乐句增量与缓存命中显示。
4. 声库/别名发现性、试听、音域热力图仍可打磨。
5. 颤音仍是少数参数，不是完整包络。
6. 没有与专业 SynthV/OpenUtau 对标的 A/B 盲测流程。

升级方案：

- 6.3.3：曲线工作区 + 音素边界/时值 + 增量渲染 + A/B 槽位。
- 统一 Inspector 的音符/音素/参数/技法分页。
- 声库工作流：别名编辑、试听、音域、批量导入、版本兼容。

### 4.4 乐谱/OMR

已有优势：

- Verovio 刻版、自动谱号/八度、MusicXML 导入、PDF/PNG、OMR 多后端、按页重试。

差距：

1. OMR 预处理和误检在真实总谱上仍有问题（KI-7）。
2. 识别后没有就地校对视图，用户只能导出去改。
3. MusicXML 导出、分谱/总谱、版式/换行/分页控制不足。
4. 谱面与卷帘的双向编辑只覆盖定位，不覆盖改音。
5. 没有 OMR 质量报告与失败页视觉标注。

升级方案：

- 6.4：OMR 校对层（原图半透明底图 + 音符覆盖 + 逐页置信度/重试）。
- MusicXML 导出、分谱、总谱压缩、版式选项。
- 谱面输入（步进/和弦/连音）与卷帘同步编辑。

### 5.2 Python 运行时与包体

- torch 463 MB、llvmlite 115 MB、transformers 102 MB、imageio_ffmpeg 84 MB、scipy 80 MB、transkun 54 MB、onnxruntime 45 MB。
- 模型：安装包内 212 MB；用户模型目录 21 GB（按需）。
- 安装包 712 MB，安装后 2.1 GB。

优化方案：

1. 合并/淘汰冗余 Python 运行时（历史 3.11/3.12 双运行时；当前安装版只有一份，但仓库仍有备运行时脚本）。
2. 按需拆包：核心推理依赖 + 可选模型/引擎包；首装只装基础。
3. 清理运行时 dev-only 依赖：matplotlib/pandas/sklearn/tensorboard/grpc/sympy/networkx/seaborn 等先做 import 审计，再分批移除或移到开发包。
4. 去重 ffmpeg/imageio_ffmpeg、OpenBLAS/NumPy/SciPy libs；检查是否有重复二进制。
5. 模型包按硬件/曲风推荐，支持校验、断点、去重、空间预算。
6. 差分更新：保留基线 win-unpacked，生成增量包；优先 NSIS solid 压缩与资源去重。
7. 启动：worker 延迟 import、模型懒加载、引擎发现缓存；避免每次请求重新 import torch/transformers。

### 5.3 代码质量

- 前端 74k 行；main 17.5k；engine 25k。
- 巨型文件：ViewSing 3,642、ViewEdit 3,594、ViewTranscribe 2,897、EditorCanvas 2,017、SettingsPanel 1,997、SideBar 1,391。
- 23 个视图、约 40 个组件；多层 KeepAlive 常驻。
- 361 处 catch {} 吞错；34 个模块导出无外部引用；60 个跨文件 10 行重复窗口；引擎两个渲染脚本高度重复。
- 复核结果：测试基础好（546 UI、185 测试文件），但视觉/可访问性/真实素材质量/包体没有门禁。

重构顺序：

1. 先修 P0 与入口重复，不先大拆。
2. 按领域拆 ViewEdit/ViewSing/ViewTranscribe：编辑画布、Inspector、工具栏、任务/导出。
3. 抽出统一 UI 原语：Dialog、Listbox、Toolbar、Field、EmptyState、Toast。
4. 死代码/死导出/旧路由/旧壁纸清理；每个模块补一个回归测试。
5. 引擎侧抽出共享推理运行时、模型适配层、下载/校验层，合并重复渲染脚本。

## 7. 升级路线（建议按版本）

### 6.3.0 — 可信基础与编辑手感（优先级最高，约 15–22 人日）

## 8. 门禁建议

每个版本必须过：

- 0 新增 i18n 缺失；最终 100% 中文键有 EN/JA。
- 0 新增死控件；audit:dead-options 保持 0。

- axe 核心页面 0 严重违规；核心路径键盘可达。
- 任务中心：完成/失败/取消 2s 内落终态；无永久 running。
- 编辑 60k：首次进入 ≤700ms，播放帧 p95 ≤16.7ms，内存增长 ≤25MB。
- 安装包/运行目录不超过预算；每次发布记录差分大小。
- 真实素材转录 note/onset/pedal F1 基线不下降。
- 包内无未引用旧入口/旧壁纸/旧导航死代码。
