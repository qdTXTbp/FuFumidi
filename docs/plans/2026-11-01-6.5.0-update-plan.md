# FuFumidi 6.5.0 更新方案

> 主题：**从“转谱”到“演奏”**
> 版本：6.5.0（基于 6.4.2 稳定线）
> 原则：不训练新模型；优先复用现有引擎、分轨、MIDI 输入、录音和播放能力。

## 0. 版本目标

6.5.0 交付两条主线：

1. **智能分轨转录**
   - 直接收进“通用识别”，不新增页面；
   - 固定专用分轨模型 + 固定转录模型 + 固定音色；
   - 用户可选保留多少轨；
   - 解决“同一 MIDI 轨音色不断切换”。

2. **3D 互动钢琴 / 音游 / 外接电钢琴**
   - 在“可视化”里新增 3D 钢琴模式；
   - 可自由演奏、跟弹、音游、录制；
   - 支持 USB/蓝牙 MIDI 键盘；
   - 复用现有 MIDI 输入和录音引擎。

非目标：

- 不训练新的分离/转录模型；
- 不做 VR、云同步、在线排行；
- 不承诺把任意混音还原成 30 条真实录音分轨；
- 不替换现有 2D 仪表盘/瀑布流，3D 是新增模式。

# 第一部分：智能分轨转录

## 1. 用户流程（最少步骤）

通用识别面板保持原样，只增加一行：

```text
[✓] 智能分轨（推荐）    保留轨道：自动（建议 12 轨） ▾
```

用户步骤：

1. 拖入音频；
2. 选模型（可保持默认）；
3. 点“开始转录”。

不需要选分轨模型、不需要路由表、不需要新页面。

## 2. 自动流程

```text
开始
 ├─ 开关关闭 / 分轨包不可用
 │    └─ 走现有整曲转录，行为完全不变
 ├─ 分轨（固定 HTDemucs 6-stem）
 ├─ 逐轨转录（固定角色默认模型）
 ├─ smart_midi 逐轨修正
 ├─ 合并：固定轨级 program、清除轨内 program_change
 ├─ 轨道预算：按用户选择保留/合并/拆分
 └─ 原队列返回结果，载入编辑器
```

进度复用原队列：

```text
分轨 1/3 → 人声转录 → 鼓转录 → 贝斯转录 → 修正 → 合并 → 完成
```

## 3. 分轨模型与依赖

### 3.1 固定分轨模型

优先：

```text
HTDemucs4_6stems.th
→ vocals / drums / bass / piano / guitar / other
```

兜底：

```text
bs_roformer_4stems_ft.ckpt
→ vocals / drums / bass / other
```

禁止把 `melband_roformer_instvox_duality_v2` 当作智能分轨默认模型：它只有 Vocals/Instrumental，Instrumental 仍然混在一起，不能保证音色稳定。

### 3.2 智能分轨转录包

资源中心新增**一个组合条目**：

```text
智能分轨转录包（约 0.7–1 GB）
  ├─ HTDemucs4_6stems.th
  ├─ YourMT3+ 运行时（433MB）
  └─ AudioSet tagger（随包内置 20.8MB，无需下载）
```

规则：

- 一个下载按钮，下载队列内部按依赖顺序安装；
- 已安装的组件自动跳过；
- 状态聚合显示“已就绪 / 缺分轨模型 / 缺转录模型”；
- 不要求用户单独理解每个模型。

### 3.3 自动分档

| 已安装 | 行为 |
|---|---|
| 6-stem + YourMT3+ | 完整智能分轨转录 |
| 6-stem + Basic Pitch（内置） | 分轨 + Basic Pitch，降级但可用 |
| 只有通用模型 | 整曲转录 + 按 program/音域拆轨 |
| 什么都没有 | Basic Pitch 整曲兜底 |

## 4. 默认角色与固定音色

| stem | 默认模型 | GM 音色 | 通道 |
|---|---|---|---|
| vocals | YourMT3+ | 52 Choir | 0 |
| drums | Basic Pitch | 鼓组 | 9 |
| bass | YourMT3+ | 33/34 | 1 |
| piano | piano_pt | 0 Grand Piano | 2 |
| guitar | YourMT3+ | 24/25 | 3 |
| other | YourMT3+ | 48 Strings | 4 |
| 整曲兜底 | 用户所选模型 | 按轨拆分 | 轮转 |

规则：

- 每个 stem 输出独立 MIDI，不先合并；
- 每轨只写一个 `program_change`；
- 删除轨内后续所有音色变化；
- 同一 stem 内出现多个 program，按 program 先拆子轨；
- 鼓固定 9 通道，定音鼓/钟琴留在旋律通道；
- 用户不需要看到这些表，默认自动执行。

## 5. 轨道预算（显示 + 用户选择）

### 5.1 开始前

通用识别面板显示：

```text
保留轨道：自动（建议 12 轨） ▾
```

选项：

| 选项 | 行为 |
|---|---|
| 自动 | 按复杂度选 6–12 轨，默认 |
| 6 组 | 人声/鼓/贝斯/钢琴/吉他/其他，最稳定 |
| 12 轨 | 推荐，组内细分 |
| 16 轨 | 单 MIDI 上限 |
| 全部候选 | 工程内保留全部，导出时分组 |

用户不改也能直接开始。

### 5.2 运行中

```text
分轨 6/6 · 候选声部 23 · 转录 4/23
```

### 5.3 完成后内联选择

结果卡展开，不跳新页面：

```text
检测到 28 个候选声部
保留轨道：12 ▾   [合并同类（推荐） / 丢弃]

☑ 人声    Choir 52     1,245 音符  98%
☑ 鼓      鼓组          2,031 音符  96%
☑ 贝斯    Bass 33        890 音符  94%
☑ 钢琴    Grand 0       1,102 音符  91%
☐ 合成器  Pad 89         310 音符  72% → 合并到其他

[载入工程]  [保留全部候选]
```

默认不展开；点“查看轨道”才展开。

### 5.4 轨道预算算法

输入：候选轨（role、program、noteCount、confidence、overlap）。

1. 固定核心：drums、vocals、bass、piano、guitar 各最多一条；
2. 其余按 `noteCount^0.5 × confidence × roleWeight` 排序；
3. 目标 N：
   - N < 核心数：低置信度核心并入同类，但鼓/人声不合并；
   - N > 候选数：按 instrument token/音域拆分，标注“拆分”；
   - N > 16：工程内允许，单 MIDI 导出分卷；
4. 合并时音符不丢，进入同类轨；丢弃轨明确提示。

## 6. 30+ 轨与 MIDI 16 通道

- 应用工程内部可以保留 30 轨；
- 标准 MIDI 只有 16 通道（9 为鼓）；
- 导出三种模式：
  1. 组级 MIDI（≤16 轨，推荐）；
  2. 工程文件（保留全部轨道）；
  3. 多 MIDI 分卷（按通道组拆 .mid）。
- 不静默把第 17–30 轨塞进同一通道。

## 7. 后端接口

### 7.1 请求字段

在现有 `engine:transcribe` 请求中增加：

```ts
  stemTranscriber?: string;   // 内部默认 yourmt3

```

### 7.2 进度事件

新增：

```ts
win.webContents.send('engine:stem-progress', {
  id, stage: 'separate'|'transcribe'|'refine'|'merge'|'done',
  stem?: string, current?: number, total?: number,
  candidates?: number, text?: string

```

现有 `engine:log` 继续输出详细日志；前端不需要第二个任务中心。

### 7.3 结果

```ts
  ok: boolean;
  out: string;                  // merged.mid
  tracks: Array<{
    id: string; role: string; name: string;

```

## 8. 新增模块

```text
main/stem-workflow.js
  runStemWorkflow(cfg, ctx)
  separateStems()
  transcribeStem()
  refineStem()
  mergeStems()

engine/stem_merge.py
  merge_stem_midis()

  assign_channels()

engine/stem_roles.py

```

接入点：

- `main/task-queue.js`：`engine:transcribe` 检测 `cfg.stemEnhance` 后走 workflow；
- `main/separate-common.js`：复用分离参数；
- `engine/midi_programs.py`：扩展角色固定 program；
- `engine/smart_midi.py`：逐轨 refine；
- `frontend/src/views/ViewTranscribe.vue`：开关、轨道数、结果卡。

## 9. 失败/取消/低内存

- 分轨失败 → 自动整曲转录，日志标记“未分轨”；
- 单 stem 失败 → 其它轨保留，失败轨可重试；
- 合并失败 → 保留分轨 MIDI；
- 低内存设备：分轨和转录串行，不并行；
- 取消：终止当前阶段，保留已完成 stem 的缓存（P1）。

# 第二部分：3D 互动钢琴 / 音游 / 外接电钢琴

## 10. 现有可复用能力

- 2D 瀑布：`ViewViz.vue` + `core/viz/`
- 合成/播放：`audio.js`、player、SoundFont
- MIDI 输入：`frontend/src/core/midiin.js`
  - Web MIDI 设备枚举、note on/off、velocity、CC64、时间戳
- 录音：`frontend/src/core/recorder.js` + `RecordPanel.vue`
  - 预备拍、量化、replace/overdub、延迟校准
- MIDI 编码：`frontend/src/core/midi.js`

3D 只补场景、镜头、游戏判定和 3D 交互，不重做输入和录音。

## 11. 产品形态

“可视化”新增模式：

```text
仪表盘 | 瀑布流 | 3D 钢琴
```

四个子模式：

1. 自由演奏
2. 跟弹练习（等待/分手/循环/变速）
3. 音游（判定、Combo、准确率、结算）
4. 录制（复用现有录音引擎）

## 12. 3D 场景

### 12.1 钢琴模型

程序化 88 键优先：

- 白键/黑键、琴体、琴盖、谱架、踏板、琴腿；
- PBR：亮面黑漆、木纹、毛毡、黄铜；
- 环境反射、柔和阴影、ACES tone mapping；
- P1 增加剖视琴槌/琴弦；
- 后续允许用户导入 glTF，默认不打包受版权限制的模型。

### 12.2 镜头

| 镜头 | 用途 |
|---|---|
| Player | 演奏者视角 |
| Audience | 观众视角 |
| Top | 教学/录像 |
| Cinematic | 展示/导出 |

弹簧平滑切换。

### 12.3 音符与反馈

- 3D 下落条/粒子，按轨颜色；
- 命中线 + 光晕；
- 长音光带、踏板延音尾迹；
- 琴键随输入下沉，力度决定深度/高光；
- 背景沿用现有主题/壁纸。

## 13. 输入、延迟、判定

### 13.1 外接电钢琴

复用 `midiin.js`：

- USB/蓝牙 MIDI 枚举；
- 设备选择、热插拔、断线重连；
- note on/off、velocity、CC64、pitch bend（P1）；
- 通道过滤、移调、键盘分割；
- 设备持久化。

### 13.2 延迟

- 复用 `recorder.calibrateLatency`；
- 写入现有 `midiInputOffsetMs`；
- 音游判定使用音频时钟 + 输入延迟补偿；
- 手动滑杆微调；
- 蓝牙 MIDI 提示优先 USB。

### 13.3 判定

```text
Perfect ±25 ms
Great   ±50 ms
Good    ±90 ms
Miss    超过 130 ms（可配置）
```

- 和弦整组命中；
- 长音按持续时长给分；
- 错误音只扣准确率；
- 掉帧不改变得分，判定基于音频时钟。

## 14. 录音

复用 `recorder.js`：

- 预备拍 0/1/2 小节；
- 量化 off/1/4/1/8/1/16/1/32；
- replace / overdub；
- 延迟补偿；
- take 采用/丢弃。

新增：

- 3D 视图内紧凑“录制”按钮；
- 录完生成新轨/新曲；
- P1 增加 WebAudio 音频录制（MediaRecorder）与视频导出。

## 15. 代码结构

```text
frontend/src/views/ViewViz.vue       mode='piano3d'
frontend/src/components/viz/Piano3D.vue
frontend/src/core/piano3d/
  scene.js        场景/灯光/后处理
  pianoModel.js   程序化钢琴
  notes3d.js      下落音符/InstancedMesh
  game.js         判定/准确率/连击
  camera.js       镜头
  input.js        包装 midiin.js
```

依赖：

- 新增 `three`（约 600KB），不引入 React/Babylon；
- 不新增原生依赖；Web MIDI 继续走 Electron 内置能力。

## 16. 性能

- `InstancedMesh` 渲染音符/琴键；
- DPR ≤2，低端 GPU 自适应降级；
- 只渲染可见时间段音符；
- HUD 用 DOM/Canvas，不做 Vue 逐音符响应式；
- 目标 1080p 60fps，低端 30fps；
- 3D 模式默认不叠 2D 瀑布。

# 第三部分：两条主线的联动

## 17. 转录 → 3D 试奏

分轨转录结果卡增加：

```text
[在 3D 钢琴中试奏]
```

- 多轨 MIDI 直接进入 3D 钢琴；
- 按角色着色（人声/鼓/贝斯/钢琴/吉他/其他）；
- 用户可只选一轨练习，或全轨展示。

## 18. 外接键盘 → 录制 → 编辑

3D 录制生成的新轨/新曲：

- 走现有工程/导入路径；
- 可继续用编辑器修正、换音色、导出；
- 不引入第二套文件格式。

## 19. 共享设置

新增设置键：

```text
stemEnhance.enabled
stemEnhance.trackBudget
stemEnhance.sepModel
stemEnhance.transcriber
piano3d.camera
piano3d.quality
piano3d.inputDeviceId
piano3d.inputOffsetMs
```

默认值保证旧用户升级后行为不变：`stemEnhance.enabled = auto`、`piano3d` 仅手动进入。

## 23. 风险

| 风险 | 缓解 |
|---|---|
| 6-stem 分离串音 | 固定角色 + 置信度提示 + 单轨重试 |
| 30+ 轨无法逐轨还原 | 明确组级输出、工程内保留、MIDI 分卷 |
| 用户没装模型 | 组合包一键装、自动降级、开关禁用提示 |
| Three.js 低端 GPU | 质量档、DPR 限制、2D 回退 |
| 蓝牙 MIDI 延迟 | USB 优先提示、校准滑杆 |
| 真实钢琴模型版权 | 程序化默认、用户自带 glTF |
| MIROS CUDA 未用上 | 6.5.0 先修 GPU torch 路径优先级，合并 PR #37 |

### 25.4 使用边界

- 参考项目用于**交互、判定、渲染思路**，不直接复制 GPL/专有代码；
- 分离/转录模型只使用允许离线分发的权重，下载前核对许可证；
- Demucs、YourMT3+、MuScriptor 的权重条款可能不同，不能只看代码仓库 license；
- 钢琴 3D 默认程序化建模，不使用来源不明的钢琴模型/贴图；
- 研究模型（MDTK/RefinPaint/MIDBACK）不进入 6.5.0 必需路径，避免拖慢发布。
