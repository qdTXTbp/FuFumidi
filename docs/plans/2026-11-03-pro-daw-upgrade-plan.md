## 0. 结论先行

### 0.1 三句话

1. **引擎与格式层已经是专业级（A-/B+），交互与工程层只到「能改」**：MIDI 事件级保真、10+ 转录模型、Verovio 刻版、OMR 三后端、DAWproject/LUFS/BWF 都很强；但**没有音符试听、多选拖动只动一个音、编辑会重置循环、轨道不能增删改、拍号不能编辑、编排不参与播放**（审计 F-01…F-08、L1/L2）。
2. **专业化不是加更多功能，而是补齐四条主干**：**① 工程骨架**（轨道/拍号/速度图/撤销/混音）；**② 编辑手感**（试听/吸附/标尺/快捷键/CC 体系/量化）；**③ 编排进入播放**（clip → 事件流，成为播放真源）；**④ 校对闭环**（转录质量面板、谱面校对、调教 A/B）。这四条做完，才谈得上「专业工具」。
3. **与全 Rust 重写的关系：功能升级不应等 Rust**。Rust A 路线 12–18 个月；功能升级 6–9 个月，两条线必须并行但分工明确——**UI/交互/数据模型在现有栈上做，引擎能力（节拍检测、质量指标、渲染）先在 Python 做再随 Rust 迁移**。若只有 2–3 人，按「先 6.6 能用（1.5 个月）→ 再并行 Rust A + 6.7/6.8」排，总周期约 22–30 个月；若 4–5 人，12–18 个月可同时完成。

### 0.2 专业化验收（用户视角，而不是功能清单）

| # | 场景 | 验收标准 | 当前 |
|---:|---|---|---|
| 1 | 从零写 8 小节 | 新建工程 → 建轨/改名 → 画音（即响）→ 循环里改 → 量化 → 导出：≤10 分钟 | 不成立（无试听/无轨道 CRUD/循环被重置） |
| 2 | 转录校对 | 一条 3 分钟音频转录后，30 分钟内完成：质量面板看问题 → 音频/MIDI 双视图对照 → 局部重转 → 接受 | 不成立（无质量面板/无双视图） |
| 3 | OMR 校对 | 识谱结果在谱面上逐音核对、改连音线/休止、导出 MusicXML/PDF | 不成立（乐谱页只读/解析器两份） |
| 4 | 调教迭代 | 改一个参数 → 局部重渲 → A/B 对比 → 再改，单次循环 <10 秒 | 不成立（只能整段渲染） |
| 5 | 60k 大工程 | 拖拽/缩放/播放帧 p95 <16.7 ms；编辑响应 <50 ms | 部分成立（帧 3.4 ms，但撤销深拷贝/命中 O(n)） |
| 6 | 20 轨工程 | 可编排、可每轨增益/声像/静音独奏、导出分轨与 marker | 不成立（16 轨上限、通道级混音、编排不参与播放） |
| 7 | 快捷键 | 可改键、可存两套、帮助表由实现生成 | 不成立（只读假恢复） |
| 8 | 撤销 | 命令式、带操作名、跨页统一、内存可控 | 不成立（整轨快照 ×80、两套历史） |

### 1.2 竞品参照（只列差距，来自审计 §6）

- 必须对齐的底线（不做就不是专业工具）：音符试听、多选拖动、拖动吸附、标尺/点击定位/循环拖拽、拍号编辑、轨道增删改排、命令式撤销+命名、快捷键可配置。
- 应该对齐（决定「顺不顺手」）：量化参数组、Groove 导入、时间人性化、per-note bend/MPE、每轨混音、编排参与播放。
- 差异化优势（已有，要守住并做深）：10+ 转录模型、OMR 三后端、Verovio 刻版、调教双引擎、DAWproject/LUFS/BWF、分轨转录（6.5.0）。
- 明确不追（审计 §7「不建议做」）：完整排版引擎、实时 VST 宿主、音频 clip 时间伸缩、MIDI 2.0/UMP。

## 4. 优先级与取舍（决策建议）

### 4.1 必做（不做就不是专业工具）

B1–B8（试听/多选/吸附/走带/快捷键让位/撤销时机/标尺/CC 最小集）、A1–A4（轨道/拍号/撤销命令式）、C1（编排参与播放）、D1（MusicXML 单解析器）、E1（公共节拍层）、E6（重复音合并开关）、H1–H3/H6（性能与门禁）。

### 4.2 强烈建议（决定「顺不顺手」）

B9–B12/B14（快捷键/量化/Groove/CC 体系/命中索引）、C2–C3（编排交互/播放头）、E2（质量面板）、F1（音高曲线归属）、G1–G2（格式/选区导出）、A5（每轨混音）。

### 4.3 可延后 / 需产品决策

A6（音频轨/录音，最大范围）、A7（模板/自动恢复）、B13（和弦轨）、B15（MPE）、C4–C5（clip 编辑/自动化）、D2–D5（谱面校对/分谱 PDF）、E3–E4（双视图 AB/refine 进编辑页）、F2–F7（调教深度）。

### 4.4 不做（审计结论）

完整排版引擎、实时 VST 宿主、音频 clip 时间伸缩、MIDI 2.0/UMP、云协作（本阶段）。

## 5. 风险

| # | 风险 | 对策 |
|---:|---|---|
| 1 | 范围蔓延（功能清单越加越多） | 每版只做表格内条目；未列入一版不接 |
| 2 | 与 Rust A 双线冲突（数据模型改动被重写） | 先冻结「工程数据模型 v2」（轨道/拍号/曲线归属），Rust 与功能都按它实现 |
| 3 | 回归（工作流改动碰播放/导出） | 金标语料 + 双跑对比 + 每版冒烟；播放/导出必须有逐样本/事件级对拍 |
| 4 | 音频轨/录音是另一个产品的工程量 | 6.8 决策；不做就用参考音频兜底 |
| 5 | 制谱校对被预期成「制谱软件」 | 文案明确「校对视图」，不承诺排版编辑 |
| 6 | 快捷键/手势改动破坏老用户肌肉记忆 | 提供两套默认（老/新），设置可切 |
| 7 | 数据兼容（轨道/拍号/曲线归属改变工程格式） | 只增不删 + 迁移脚本 + 旧版本可读 |
