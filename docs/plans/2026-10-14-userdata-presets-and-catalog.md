### P1 · 预设革新（收尾上一版没做完的 ②③④）

**目标**：删掉现有 13 个按"用途"命名的老内置预设，改成**每个模型一套默认**，
切模型自动套用；用户一旦自己指定，**以用户为准**且永久记住。

**判据（用户明确）**：**最高质量 + 保证稳定性，不考虑速度和性能。** 落到参数上：

- 只影响速度/资源的 → **一律选最重的**（`perf=quality` 全核、`precision=fp32`）
- 影响结果且**值越高越不稳定**的 → 取"更准但不会崩"的那一档，**避开会引发重复/崩句的高值**
- 每个预设的**代价写进说明**，界面里看得见

**待确认的默认值表**（执行前请过一眼；`—` 表示该模型不适用）：

| 模型 | perf | precision | temperature | cfg_coef | beam_size | prelude_forcing | 其它 |
|---|---|---|---|---|---|---|---|
| basic-pitch（通用基础） | quality | fp32 | — | — | — | — | onset 0.5 / frame 0.3 / min_note 128ms / melodia 开 / beat_grid 开 |
| MuScriptor small/medium/large | quality | fp32 | 1.0 | 1.0 | 1 | 开 | max_note_hold 0（不干预）/ 合并重叠开 / 力度归一化开 / 节拍网格开 |
| 钢琴（piano_transcription） | quality | fp32 | — | — | — | — | 包含踏板 **开** / 音符合并间隔 30ms |

### P3 · 用户元数据底座（P2-3 与 P4 共用）

一张按 `id` 存的用户元数据表，落在**数据根**（复用 P1 已打好的迁移框架）：

```
{
  "schema_version": 2,
  "items": {
    "<kind>:<id>": {
      "name": "用户改过的名字",     // 空 = 用内置/原始名
      "author": "", "source": "",
      "tags": ["人声", "中文"],
      "category": "我常用",
      "order": 12,                  // 自由排序位
      "pinned": true                // 顶置
    }
  }
}
```

**为什么必须是独立表而不是写进各处的清单**：资源中心四页的数据来源是三套
（`model:list` / `utau:voicebankRegistry` / DiffSinger 声库目录），各自结构不同、
且前两者每次刷新都会**重算**。用户改的名字与排序如果写进那些结构里，刷新即丢。

### P5 · 删任务模板 + 转录队列革新（用户 2026-10-14 追加）

**目标**：删掉「任务模板」；队列改成**可建多个**，用来区分"用什么模型、什么参数"。

- **模板删除**：状态/函数/界面/死 CSS 全删；`fufumidi_task_templates` 不再读写。
  连带把**失真的引导文案**改掉 —— 引导浮层原写「内置多套预设（钢琴快速琶音、人声主旋律、
  吉他拨弦等）」，那些老预设在 P1 已删，属于"文档在说假话"，必须一起改。
- **多队列**：队列 = `{ 名字, 模型选择, 参数快照, 条目 }`。
  · 切队列 = 先把当前界面的模型/参数存回旧队列（`snapshotIntoQueue`），
    再把新队列的设置加载到界面（`loadQueueSettings`）→ **切队列就是切模型与参数**；
  · 参数快照**复用 P1 的 `collectPresetParams` / `applyPresetParams`**，不另立一套序列化；
  · 运行中禁止切/新建/删除/复制队列（半路换设置会让同一批条目用两套参数，结果无法解释）；
  · 持久化到 `fufumidi_queues_v1`，并把老的单队列 `fufumidi_batch_queue` 迁移成第一个队列。

**两条容易踩的**：

1. Vue 的 `watch` 是**异步**的 —— `loadQueueSettings` 里只靠 `presetApplying` 挡不住
   "切队列后 watch 又套一遍模型默认"，必须**同时**摆好 `lastModelKey`。
2. `loadQueue()` 在 `onMounted` 里**早于** `loadPresets()`，所以 `loadPresets` 末尾要
   重新快照当前队列并落盘，否则首次启动存下的是"预设生效前"的旧参数。

### P4 · 落地情况（含一次返工）

- **渲染端单例** `frontend/src/core/usermeta.js`：读一次表、按 `<kind>:<id>` 取、把用户排序与顶置套到列表上。
  `orderList()` 规则是 **顶置优先 → 用户 order → 原始顺序（稳定）**，四页共用，所以行为一致。
- **顶置**：`.cat-card / .vb-card / .ds-card / .sf-tile` 都有 📌，写 `pinned: true`。
- **拖拽排序**：目录壳（音色 / 调教模型）、UTAU 声库、DiffSinger 声库、音色工坊四页都可拖。
  ★ **分类/搜索时不禁止拖拽**（第一版禁止，是错的）。正确语义：把**可见项**的新顺序
  **回填到全量顺序里它们占据的那些位置**上（`mergeSubsetOrder`），没显示的条目一个都不动。
  未过滤时"可见 == 全量"，回填就是恒等，行为与旧版一致。
  返工原因（用户实测反馈）：第一版用 `:draggable="!hasFilter"` 一刀切，结果在「原神」这类
  分类里**根本拖不动** —— 而"在某个分类里排序"正是最常见的用法。
- **标签 / 作者 / 分类 / 改名**：四页共用一个 `ItemMetaEditor.vue`（浮层表单）；搜索框把
  名字 / 作者 / 标签 / 分类一起搜。**空字段 = 用原始值**，「恢复原始」= 删掉该条目的用户改动。

**DiffSinger 的两个额外坑（都已修）**：

1. **它的用户排序是在模板里套的**（`v-for="(m, mi) in dsOrdered(c.models)"`），不在 `filteredWorks`
   里。所以算下标用的 id 列表**必须也走 `dsOrdered`** —— 否则一旦已有自定义 order，
   `indexOf` 算出的下标与用户看到的顺序对不上，拖动会落到错误位置。
2. **它的排序是按 category 分桶的**（每桶内部排）。写下去的 order 是全局 1..n，
   但只有**同桶内**的相对大小有意义 —— 这与模板行为一致，所以两个 id 列表都按桶拼。

仍然存在的**语义边界**（不是 bug，是分组视图的固有性质）：跨 category 拖动时，条目归属由数据
决定、不由顺序决定，所以它在界面上仍留在原桶里，只是桶内位置变了。

## 7. P6 · v20（Worldline-R2）实现记录（2026-10-14）

用户判定「做」。上游 `Classic/WorldlineRenderer.cs:138-193` **逐行对齐**，四个容易漏的点全部照搬：

| 上游事实 | 我们怎么做 | 漏了会怎样 |
| --- | --- | --- |
| 补帧 = `ceil((totalFrames + 12) / 16) * 16`，**左补固定 4 帧** | `r2_pad()` 返回 `(padded, left, ...)` | 只按 `(-T) % 16` 补：T=16/32 时帧数与上游不同 |
| `f0`/`sp_env` 补 **0**，`ap` 补 **1** | `np.ones` 补 ap | ap 补 0 = 宣称这些帧完全周期，边缘出错 |
| 出波形后 `Skip(left*512).Take(T*512)` | 裁掉补出来的帧 | 输出前移 4 帧、长度是补齐后的长度 |
| 首尾各 512 样本线性淡入淡出 | 同样的斜坡（第 0 个样本增益恰为 0） | 乐句拼接处爆音 |
| mel 会话固定 **CPU**，声码器用默认 | `resolve_providers('cpu')` / 默认 | 85 KB 的模型挪 GPU 不划算 |

**资源**：`mel.onnx`（85,404 B，sha256 `1493ffc8…`，上游 commit `4d26fa51`）**随包** ——
它是 v20 自足的前提，来源与许可证待办记在 `docs/VENDOR.md` 第 4 条（**发布前必须核实许可证**）。
声码器是外部的 128bin/512hop PC-NSF-HiFiGAN，资源中心已有「NSF-HiFiGAN 通用声码器」条目，
缺失时报可行动的错，不静默算错。

**接界面**：`RENDERER_OPTIONS` 加 `WORLDLINE-R2`（文案「最新，需通用声码器」，**不写音质结论**
—— 本机没有 A/B 过，不编）；三语 i18n、CLI `--renderer` 帮助、`main/settings.js` 注释同步。

**验证**：`engine/tests/test_worldline_r2.py` 9 项（补帧语义 + 端到端形状 + 报错文案 + 空乐句）；
`test_openutau_core_matches_source.py` 里新增**真机端到端**（真 native WORLD → mel → 声码器，
判据是过零率主频 ≈ 440 Hz —— 补帧/裁剪错一格它就会偏），并把旧的「v20 是桩」断言换成照搬一致性检查。
