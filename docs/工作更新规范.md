## 1. 项目概况

- **产品**：FuFumidi —— Electron + Python 的纯离线「音频转 MIDI」桌面应用。
- **版本**：1.2.1（大版本 1.2.0 的缺陷修补版）。
- **GitHub**：https://github.com/qdTXTbp/FuFumidi
  - 默认分支：`master`（历史原因存在 `main`，不要把新代码推到 main）。
- **本地安装位置**：`E:\Midi\FuFumidi`
- **本地发布目录**：`E:\Midi\安装包\FuFumidi`
  - `Windows\`、`MacOS\`、`Linux\`、`FuFumidi开发者文档\`、`FuFumidi视频\`
- **主要技术栈**：
  - Electron 33（主进程 `app/main.js`、预加载 `app/preload.js`、单文件渲染器 `app/renderer/FuFumidi.html`）
  - Python 转录引擎 `app/engine/`（basic-pitch / piano-transcription / demucs）
  - 内置运行时：python-build-standalone（安装包 `resources/python`）
  - 内置模型：`resources/models`（basic_pitch_quant.onnx、piano-transcription、demucs）
  - CI：GitHub Actions `.github/workflows/build.yml`（推 `v*` 标签自动构建三平台并发布 Release）

## 3. 使用的工具与技能

### 3.1 工具清单
1. **PowerShell / bash**：进程管理、文件复制、压缩、调用 ffmpeg / python / git。
2. **Node.js（v24）脚本**：
   - 读写大文件、字符串补丁（注意 CRLF）。
   - **CDP 远程调试**：通过 `http://127.0.0.1:9223/json` + WebSocket 调用 `Runtime.evaluate`、`Page.captureScreenshot`、`Emulation.setDeviceMetricsOverride`，用于自动化验证 UI、批量测试转录。
   - 分段下载器：GitHub Actions 产物 Azure Blob 单连接慢（约 0.3MB/s），用 `curl.exe -r` 分段并行下载，速度可达 3–7MB/s。
3. **@electron/asar**：`npx --yes @electron/asar extract/pack` 解包/重打包 `app.asar`，用于直接修补已安装应用。
4. **ffmpeg**：视频制作、抽帧、音频响度检测（`volumedetect`）、转码 H.264/AAC。
5. **7-Zip**（`C:\Users\qdTXTbp\scoop\shims\7z.exe`）：源码包 `-tzip -mx=9` 最高压缩。
6. **GitHub REST API**（Node fetch + Personal Access Token）：
   - `GET/PUT /repos/{owner}/{repo}/contents/{path}`（base64 读写文件，branch 参数控制分支）
   - `POST /repos/.../git/tags` + `POST /repos/.../git/refs` 创建标签
   - `GET /repos/.../actions/runs/{id}/jobs`、`.../logs` 查 CI
   - `GET /repos/.../actions/runs/{id}/artifacts`、`.../artifacts/{id}/zip` 下载产物
   - `POST uploads.github.com/repos/.../releases/{id}/assets?name=...` 上传 Release 资产
   - `PATCH /repos/...` 修改默认分支、仓库描述
7. **Git**：源码已迁移到 GitHub；本地无仓库时，直接用 GitHub Contents API 提交单个文件（渲染器约 520KB，API 可承受）。

### 3.2 技能使用说明
- 本任务主要使用**通用工程能力**（PowerShell + Node/CDP + ffmpeg + GitHub API），未强制加载专项 skill。
- 可用的相关 skill：`browser-automation`（CDP/Electron 自动化）、`vision-tools`（截图/OCR 检查 UI）、`api-security`（若做安全审计）。视觉模型曾遇到 `429` 限流，不能依赖它做最终验收；用 ffmpeg 抽帧 + 像素统计兜底。
- 新增专项需求时，再按需调用对应 skill；本项目核心仍是桌面应用工程，不涉及逆向。

## 4. 标准工作流

### 4.1 修复缺陷
1. 先复现：用 CDP 连 `http://127.0.0.1:9223/json`，在页面里直接调用相关函数（例：`btAddPaths([...]); await btRun();`）拿到 `BT_STATE.items` 状态和 `error`。
2. 分层定位：
   - UI 事件没触发 → 检查 `bindXxx()` 是否在初始化中调用。
   - 渲染器报错 → 检查桥接 `fuBridge` 方法是否存在。
   - 引擎失败 → 直接用内置 Python 跑：
     `E:\Midi\FuFumidi\resources\python\python.exe E:\Midi\FuFumidi\resources\app.asar.unpacked\engine\music2midi.py convert <audio> -o <out.mid> --mode universal --perf fast`
     引擎日志比 UI 更准确。
3. 修复渲染器：解包 asar → 改 `FuFumidi.html` → 语法检查 → 重打包替换 → 重启应用验证。
4. **用户确认前不要推 GitHub**（用户明确要求过「先让我测试，再更新上传」）。

### 4.2 版本号升级（必须同步 5 处）
1. `app/package.json` → `"version": "x.y.z"`
2. `app/renderer/FuFumidi.html` → `const APP_VERSION = 'x.y.z';`
3. `CHANGELOG.md` → 顶部新增版本条目
4. `README.md` → 版本号、下载文件名
5. `.github/workflows/build.yml` → Release 标题用 `${{ github.ref_name }}`（不要写死版本号）

### 4.3 GitHub 提交与打标签
- 默认分支是 `master`；Contents API 写文件必须传 `branch: "master"`。
- 提交代码后创建 annotated tag：
  - `POST /git/tags`（object 指向 master 最新 commit）
  - `POST /git/refs` 建 `refs/tags/vX.Y.Z`
  - 打标签会自动触发三平台构建。

### 4.4 CI 与 Releases
- `.github/workflows/build.yml`：`actions/cache` → 内置 Python → basic-pitch int8 量化 → 卸载构建期依赖（**不能卸载运行期依赖**）→ 构建安装包 → `softprops/action-gh-release` 自动上传 Release。
- 三平台产物：
  - Windows：`FuFumidi-Setup-<ver>.exe`
  - macOS：`FuFumidi-<ver>.dmg` / `-mac.zip` / `-arm64.dmg` / `-arm64-mac.zip`
  - Linux：`FuFumidi-<ver>.AppImage` / `fufumidi_<ver>_amd64.deb`
- GitHub 单个 Release 资产**必须 < 2GB**（Linux 包靠 CPU-only torch 才达标）。

### 4.5 本地发布目录同步
1. 从最新 Actions run 拉取三个 artifact（用分段下载器）。
2. 解压后覆盖：
   - `Windows\` ← exe
   - `MacOS\` ← dmg + mac zip
   - `Linux\` ← AppImage + deb
3. 更新 `FuFumidi开发者文档\` 中 HTML 版本号与变更日志。
4. 保留源码 zip 和视频等按平台归档。

## 5. 踩过的坑（重要，逐条背下来）

### 渲染器/Electron
1. **bindBatch 从未调用** → 批量按钮全部无反应。新增 `bindXxx` 一定要在初始化序列里调用。
2. **`window.fuBridge` 是冻结对象**：`fuBridge.transcodeVideo = ...` 测试桩赋值会静默失败（contextBridge 不可写）。测试要用真实 IPC 或改主进程环境变量测试开关。
3. **隐藏/最小化窗口**：`requestAnimationFrame` 停摆，后台录制必须用 `setInterval` + `webPreferences.backgroundThrottling:false`。
4. **离屏 canvas 录像**：空白画布录出来是 0 字节；MediaRecorder `onstop` 可能不触发，需 `rec.stop()` 后 `stream.getTracks().forEach(t=>t.stop())` 兜底。
5. **设置页文字竖排**：`.fr-ctl` 写 `width:100%` 会挤压左侧标签成 20px 单字列；应 `flex:1;min-width:0`，标签列 `flex:none`。
6. **asar 修补流程**：`npx @electron/asar extract` → 改文件 → `npx @electron/asar pack` → 覆盖 `resources/app.asar`（先备份）。
7. **大字符串补丁**：文件是 CRLF；Node `s.includes('...\n...')` 会漏，优先用 `indexOf` + slice，或 `/[\s\S]*?/` 正则并注意 `$`、`(` 转义。
8. **函数切片误伤**：用 `indexOf('dz.addEventListener('drop'...')` 替换时，首个匹配可能在别的函数里，把 `bindTranscribe` 整个删掉。修补必须用「函数头 → 下一函数头」的边界。
9. **JS 内嵌脚本校验**：用 Node `vm.Script` 逐个提取 `<script>` 编译，重打包前必做。

### Python/引擎/模型
10. **NoBackendError**：不要直接 `librosa.load()`；统一走 `audio_io.load_audio_float32()`（soundfile + imageio-ffmpeg）。
11. **mir_eval 是运行期依赖**：basic-pitch 转录流程会 import；安装包瘦身时把它卸载导致「转录失败: No module named 'mir_eval'」。瘦身清单只能删真正构建期依赖（tensorflow/keras/coremltools/onnx/ml-dtypes）。
12. **onnx 与 tensorflow 冲突**：CI Linux 上 `onnx>=1.17` 需要新 ml-dtypes，而 `tensorflow<2.15` 锁旧版；固定 `onnx>=1.16,<1.17`。
13. **macOS 缺 ml_dtypes**：`onnxruntime.quantization` 在 macOS（无 TF）需要显式安装 `ml_dtypes>=0.5.4; platform_system == "Darwin"`。
14. **批量转录参数键名**：必须与主进程 `engine:convert` 的 map 一致：
    - universal：`min_note_length`
    - piano：`min_note_ms`、`merge_gap_ms`、`no_pedal`
    - separate：`with_drums`、`export_stems`
    - 公共：`onset_threshold`、`frame_threshold`、`denoise`、`normalize`、`auto_bpm`
    - 批量任务还必须带上 `mode`、`perf`。
15. **钢琴模型下载重定向**：Zenodo 会返回相对 `Location`，下载器要 `new URL(location, currentUrl)`。
16. **Linux 包体积**：PyPI 默认 torch 含 CUDA 运行时，AppImage/deb 会超过 GitHub 2GB 限制；Linux 用 `--index-url https://download.pytorch.org/whl/cpu` 安装 torch。

### CI
17. **working-directory 陷阱**：workflow 设了 `working-directory: app`，步骤内路径不能再写 `app/...`（曾导致 `app/python/bin/python3` 不存在）。
18. **Windows Python stdout 编码**：量化脚本打印中文报 `UnicodeEncodeError: charmap`；给步骤加 `PYTHONUTF8: "1"`。
19. **NSIS 压缩**：electron-builder 25 的 `nsis` schema 不支持 `compression`；改在 `build/installer.nsh` 里写 `SetCompressor lzma`（不要 `/SOLID`，否则 `SetCompress off` 触发 NSIS 8021 警告并当错误）。
20. **Linux deb 需要 homepage**：`app/package.json` 必须写 `"homepage"`。
21. **cache key 升版时 restore-keys 也要改**：否则会命中旧缓存（旧 python 带 CUDA torch / 缺依赖）。
22. **GitHub Release 上传**：`fail_on_unmatched_files` 要 `false`，否则 Windows 匹配不到 dmg 会导致整个 job 失败。
23. **Release 资产 >2GB**：GitHub API 直接拒绝；要么缩包，要么换分发方式。
24. **Actions artifact 下载慢**：不要单连接 curl 拉 5.9GB；Azure Blob 支持 Range，用 8–16 段并行 curl 下载再合并。
25. **Actions 日志**：运行中的 job 日志 API 可能返回 `BlobNotFound`，等 job 结束再拉；失败后先看 `##[error]` 和 `Traceback`。

### GitHub / 网络
26. **默认分支是 master**，不是 main；Contents API 不带 `branch` 会写到 main，造成「代码在 master、README 在 main」的分裂。
27. **GitHub 直连网络不稳定**：`Recv failure`、`Authentication failed` 交替出现；重试 3–5 次，成功后立刻把 remote 重置为无 token URL。Token 必须轮换。
28. **README 更新**：直接用 Contents API 的 PUT + base64；文件 <1MB 没问题。
29. **视觉模型 429**：`vision_describe` 可能持续限流；做 UI 验收优先用 ffmpeg 抽帧 + `Page.captureScreenshot` + 像素/尺寸统计，不要阻塞在视觉 API 上。

### 视频制作
30. **更新介绍视频**：用 CDP `Emulation.setDeviceMetricsOverride` 模拟 1920×1080 截图，ffmpeg `drawtext` 加中文字幕（`fontfile='E\:/.../HYWenHei.ttf'`，路径里的冒号转义），分段生成后 concat，再混入 BGM。
31. **视频发布**：Uploads API 的资产名 URL 编码中文易丢失；上传后可用 `PATCH /releases/assets/{id}` 改回正确文件名。
