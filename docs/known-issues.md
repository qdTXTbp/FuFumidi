## KI-1 卸载向导第一页文字显示不全、互相遮挡（2026-10-13，5.1.0 实测）

| | |
|---|---|
| **影响范围** | Windows NSIS 卸载向导（`Uninstall FuFumidi.exe`）第一页，**自定义的"是否保留用户数据"页** |
| **严重度** | 中 —— 不影响功能（选择、默认值、静默语义都正确），但**用户会读不全关键提示**（数据在哪、删了不可恢复） |
| **引入版本** | 5.1.0（该页是 5.1.0 新增，替换了原来的 MessageBox） |

### 现象

卸载向导第一页上，三行说明文字**显示不全**（第二行被裁掉），且与下方的单选按钮**重叠遮挡**。

### 复现

1. 装 5.1.0（`FuFumidi-Setup-5.1.0.exe`，非静默）；
2. 运行安装目录下的 `Uninstall FuFumidi.exe`（**不要**加 `/S`）；
3. 第一页即自定义页：标题行 + 两行说明 + 两个单选 + 数据路径行。

### 根因

`build/nsis-custom.nsh` 里用 `${NSD_CreateLabel}` 建的是 Win32 静态控件，**不会自适应高度**：
我给的控件高度是 `14u` / `12u`（dialog unit），而文案是 30+ 个汉字，在对话框宽度下必然折成两行
→ 第二行落到控件矩形之外被裁掉；同时下一个控件只隔 `14u ~ 16u` 就开始了，于是**压在残留文字上**。

另有一处小瑕疵：文案里的 `**你自己的**` 是 Markdown 残留 —— Win32 标签不解析 Markdown，会原样显示星号。

`makensis` **抓不到这类问题**（它只校验语法，不排版）：本次的独立 harness 编译通过、真实构建也通过，
是人工在卸载界面上目视才发现的。所以修完必须**再看一眼真实界面**。

### 建议修法（下个版本）

1. 按**行数**预留高度：单行 `12u`、两行 `24u`；相邻控件的 y 起点至少留 `26u`，别让文字区域重叠。
2. 去掉 Markdown 残留（`**`），标签只放纯文本。
3. 最长的那行（`模型 / 声库 / 音色库 / 曲库 / 设置，位置：$INSTDIR\FuFumidiData`）拆成两行，
   或改用只读文本框（`${NSD_CreateText}` + `ES_READONLY`）以便横向滚动。
4. 改完跑一次 `makensis`（语法）+ 一次真实安装后**目视核对**（静默安装看不到这一页）。
