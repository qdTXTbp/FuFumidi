FuFumidi 开发者文档

项目简介

离线音频转 MIDI 一条龙工具 —— 转录、修正、编辑、演奏、可视化、分析、乐谱，全程本地运行，无需联网。

FuFumidi 是一款基于 Electron 的纯离线音频转 MIDI 桌面应用。内置 Python 运行时，音频文件全部在本地处理，不上传任何数据。

内置三套完全离线的转录引擎：

  • 通用模式（basic-pitch，ONNX）：适用于人声 / 乐器等通用场景（兼人声分离）；
  • 钢琴模式（piano-transcription，PyTorch）：钢琴专用，还原力度与踏板；
  • 分离模式（demucs，PyTorch）：先做人声 / 乐器分离，再对分离后的音轨转录。

引擎支持 GPU 自动检测（NVIDIA CUDA / AMD·Intel DirectML / CPU 兜底），并提供三档性能模式（quality / balanced / fast），按你的 CPU 核数与显卡自动推荐档位，低配置机器也能流畅转录。

功能特性

  • 七个视图一体：演奏 / 编辑 / 可视化 / 分析 / 乐谱 / 转录 / 转换，一次导入、全程无缝衔接；
  • 三引擎离线转录：通用、钢琴、人声分离三种模式随切随用，支持拖放或对话框导入音频；
  • 智能修正（refine）：转录完成后一键精修 —— 对齐起音、还原力度、声部平衡、清理杂音；
  • 内置预设：内置「人声：最优」「钢琴：最优」两个推荐预设并设为默认，可排序、删除、一键恢复，切换引擎模式自动套用对应预设；
  • 高级转录参数：最短音符、起音判定、音符合并间隔、输出鼓组节奏轨等可调；
  • 中英双语界面：一键切换语言；
  • 主题库：内置深色主题，可切换更多外观；
  • 插件系统：内置插件宿主与示例插件，可扩展功能；
  • 新手引导：首次启动的引导流程，快速上手；
  • 完整性一键修复：启动时后台校验设置、预设、插件清单，误删可一键修复；
  • 内置 Python 运行时：安装包自带免安装 CPython 与全部依赖，开箱即用，无需另装 Python 环境；
  • MIDI 关联：.mid / .midi 文件可直接双击打开；
  • 编辑器精修：选区量化、移调（±半音 / ±八度）、复制 / 粘贴 / 克隆、力度渐强 / 渐弱、音阶吸附；
  • 导出 MusicXML：把当前曲目导出为标准 MusicXML，可导入 MuseScore / Sibelius 继续编排；
  • 混音台：每轨音量 / 声像（pan）/ 静音 / 独奏，实时生效；
  • 节拍器：播放时按节拍打点（重拍高音、普通拍低音）；
  • 工程文件（.fufu）：保存 / 恢复编辑状态、混音参数、循环区间、播放速度与目标轨道；
  • 离线渲染提速：MIDI → WAV 按起始时间分桶渲染 + overlap-add 合成，大文件不再卡顿。

界面预览

FuFumidi 采用统一的深色扁平设计语言（窗口底色 #0a0f18），以 teal 青绿色 #00C9B1 作为强调色贯穿全局。顶栏七个视图标签切换流畅，编辑 / 可视化与播放界面同源一体，离线状态下渲染器零依赖运行。

安装

  • 支持 Windows 10 及以上系统；
  • 到 GitHub Releases 页面下载安装包（FuFumidi-Setup-<版本>.exe）；
  • 安装包自带内置 Python 运行时与转录模型，无需安装 Python、Node 或任何依赖环境，装完即用；
  • 注意：v1.0.1 安装包体积约 556MB（内置运行时已做瘦身，由 853MB 缩减而来）。

使用流程

  1. 转录：导入音频（拖放或选择文件），选择引擎模式（通用 / 钢琴 / 分离），点击转录；
  2. 智能修正（可选）：转录后点「开始智能修正」，得到对齐起音、还原力度的精修 MIDI；
  3. 编辑：载入编辑器逐音符精修；
  4. 演奏 / 可视化 / 乐谱 / 分析：在其余视图查看结果。

也支持直接导入已有 MIDI（资料库按文件名去重），并可通过预设管理快速切换引擎参数组合。

AGENTS.md —— 项目宪法

本文件是给 AI（与人类）的项目背景文档。动手改代码前请先读它。未列出的文件约定，以代码中的既有注释与实际实现为准，不要臆造。

项目一句话定位

FuFumidi = 音频 → MIDI 转录 + 播放 / 编辑 / 可视化 一条龙桌面应用。

  • Electron 壳：app/main.js（主进程）+ app/preload.js（fuBridge 桥）+ app/renderer/FuFumidi.html（单文件渲染界面）。
  • Python 子进程引擎：app/engine/（音乐转 MIDI 转录引擎，源自 AudioMuse 工具内核）。
  • 架构基调：纯离线本地应用。不依赖网络服务，音频不上传，模型本地加载。

架构决策与理由

1. 转录用 Python 子进程，Electron 只做壳

  • 转录引擎是 Python：basic-pitch（ONNX，通用/人声分离）/ piano-transcription-inference（torch，钢琴专用）/ demucs（torch，人声/乐器分离）。
  • Electron 主进程通过 child_process.spawn 调用 music2midi.py 的 convert / refine / probe 命令行（app/main.js 的 spawnEngine()）。
  • 智能修正是独立脚本 smart_midi.py 的 refine 子命令（spawnEngine 的 script 参数可换脚本）。
  • 进度协议：引擎把结果输出为一行 ###RESULT {json}，主进程按行解析；其余 stdout 逐行转发为进度日志（engine:log / engine:refine:log），stderr 独立缓冲，防止串入 RESULT 行。
  • 编码约定：spawn 时注入 PYTHONIOENCODING=utf-8、PYTHONUTF8=1，避免 Windows 默认 GBK 乱码污染 JSON 解析、保证中文路径无乱码。
  • 子进程优先级：Windows 下提到「高于标准」（os.setPriority(pid, -1)），避免转录拖慢 UI。

2. GPU 自动检测与性能档位

  • app/engine/engine_gpu.py：懒加载探测（首次调用才 import torch/onnxruntime），带超时与异常保护，任何探测失败只影响加速、绝不阻断转录。
    • NVIDIA → CUDA（torch.cuda / onnxruntime CUDAExecutionProvider）
    • AMD / Intel → DirectML（torch-directml / onnxruntime DmlExecutionProvider）
    • 其余 → CPU 兜底（行为与纯 CPU 一致）
  • app/engine/engine_perf.py：三档性能 quality / balanced / fast，分别映射不限线程 / ≤4 核 / ≤2 核。
    • 通过 OMP_NUM_THREADS 等环境变量 + torch.set_num_threads() + onnxruntime SessionOptions 限制线程。
    • detect_recommended() 按 CPU 核数 / 内存 / GPU 自动推荐档位，随 probe 返回给 UI 默认选中。

3. 设计语言：深色扁平 + teal 强调色

  • 主题基底为深色扁平风，强调色 teal #00C9B1，渲染器里统一定义为 CSS 变量 --accent（--accent2:#2ee6cd、--accent-dim:rgba(0,201,177,.14)）。
  • 窗口底色 #0a0f18（main.js 的 BrowserWindow.backgroundColor）。
  • 与旧「MIDI播放器.html」界面同源（Synthesia 式瀑布可视化等），属同一设计语言家族。

4. 内置 Python 运行时：开箱即用

  • app/scripts/bundle-python.js + app/engine/requirements-bundle.txt：
    • 下载 python-build-standalone 自包含 CPython（免安装、含 pip）→ 解压到 app/python/ → 用内置 pip 装 requirements-bundle.txt。
    • torch 按 --torch 参数选择：cpu（默认，最小体积）/ cuda（PyTorch cu121 索引）/ directml。
    • 完成后清理测试套件与 __pycache__ 瘦身，并跑 probe 自检。
  • 运行时发现顺序（main.js resolvePython()）：用户显式 engine_path → 内置 app/python → FUFUMIDI_PYTHON 环境变量 → 开发机已知路径 → python/python3。
  • 注意：bundle 脚本注释声明打包时随 files:"python/**/*" 分发，动手改 package.json 的 build.files 前请核对这一条。

5. 设置持久化与 i18n

  • 设置持久化：userData/fufumidi/settings.json（main.js 的 readSettings / writeSettings，原子写入：临时文件 + rename）。
  • 插件用户目录：userData/fufumidi/plugins。
  • i18n：渲染器内 LANG（'zh'/'en'，来自设置）+ I18N_MAP（中文为源文案）。静态 DOM 用 applyLang() 整体替换（长串优先），动态字符串用 t('中文') 即时翻译，反向 en→zh 用整词匹配避免误翻。
  • 默认设置 perf_mode: 'quality'、lang: 'zh'、theme: 'deep'。

6. 渲染器功能面

七个视图（FuFumidi.html 顶栏 tab）：演奏 / 编辑 / 可视化 / 分析 / 乐谱 / 转录 / 转换。

  • 转录视图内嵌「智能修正」（转录 MIDI + 原音频 → 精修 MIDI）为一条龙第二步。
  • 播放/编辑/可视化完全离线；渲染器 JS 零依赖单文件。

编码规范

  • Python：文件首行 # -*- coding: utf-8 -*- + 模块级 docstring（说明用途与依赖）。见 app/engine/*.py。
  • 渲染器 / 主进程 JS：注释用中文；主题一律走 CSS 变量（不要硬编码颜色）；main.js / preload.js 文件头有 banner 注释。
  • 行宽与命名沿用各文件既有风格（PEP 8 风格 Python、camelCase JS），不做强制格式化工具约定。

已否决方案（重要：避免反复提出）

  1. 不用 PySide6 / Qt 界面。原 AudioMuse 有 PySide6 GUI，但 Electron 已是主界面；engine/requirements-bundle.txt 已刻意排除 gui 依赖（只注释提及 PySide6），Electron 只走 convert / refine / probe CLI，永不调用 run_gui()。
  2. 不把 ~700MB torch 运行时直接打进安装包本体。用 python-build-standalone 瘦身内置（app/python/），且 torch 默认 CPU 版最小体积。
  3. 性能档位"推荐但不锁定"。detect_recommended() 只推荐不强制；低配置用户也可手动挑战最高质量（quality 档）。
  4. 主题不照搬 AudioMuse 浅色底。统一深色基底 + teal accent 传达精神，不复刻浅色皮肤。
  5. 打包门禁：最终一键安装包必须在用户测试工具可用并回复「可以」之后才进行；不要把未经用户验证的包发出去。

工作流

一条龙：转录 → 修正 → 编辑 → 播放。用户导入音频 → convert 转录为 MIDI →（可选）refine 智能修正（对齐起音 / 还原力度 / 声部平衡 / 清理杂音）→ 载入编辑器精修 → 演奏 / 可视化 / 乐谱 / 分析。全部离线本地完成。

UPDATE.md —— 版本发布与测试规范

面向 FuFumidi 的后续维护与版本发布，AI 与开发者共用。发布前请先读 AGENTS.md 与 CHANGELOG.md。

一、版本号规则

变更类型规则示例（当前 1.0.1）
大功能更新版本号 +0.11.0.1 → 1.1.0
缺陷修补 / 小功能更新版本号 +0.0.11.0.1 → 1.0.2
  • 大功能更新：新增 / 重构显著功能面（如新引擎、新主视图、架构调整）。
  • 修补和小更新：bug 修复、预设 / 参数调整、界面细节、打包优化等。
  • 每次只做一种加法，不要在同一版本里既 +0.1 又 +0.0.1。

二、版本号改哪里（必须同步改）

  1. app/package.json → "version": "x.y.z"：决定安装包文件名（FuFumidi-Setup-<version>.exe）与系统版本信息。
  2. app/renderer/FuFumidi.html → const APP_VERSION = 'x.y.z';：界面显示版本。

注意：app/engine/music2midi.py 里的 VERSION 是转录引擎 CLI 自身的版本号，独立维护，不随应用版本号改动。

三、每次更新必做清单

  1. 按规则改版本号（上面两处）。
  2. 在 CHANGELOG.md 顶部追加本次条目（新增 / 修复 / 备注），记录版本号与日期。
  3. 全流程回归测试（详见 测试流程与规范）：
    • 安装 → 使用 → 卸载；
    • 转录至少一次真实文件（通用 / 钢琴 / 分离三种模式各至少一次）→ 智能修正 → 载入播放 / 编辑 / 乐谱。
  4. 重建发布产物：
    • 内置运行时瘦身（可选，大幅减小安装包）：node app/scripts/prune-python.js --commit（只删 __pycache__ / Lib/test / torch bin|share|include；绝不碰依赖包）。scripts/bundle-python.js 构建后会自动调用它。
    • 安装包：在 app/ 目录 npm run dist:win，产物 FuFumidi-Setup-<version>.exe。
    • 源码包：必须用内置 python 跑 scripts/pack-source-zip.py 生成真 zip（GNU tar -a 对 .zip 只会产出 ustar tar，Explorer 无法解压）。脚本会自动收录 AGENTS.md / CHANGELOG.md / UPDATE.md / .gitignore / .github/ 与 app/（排除 python / node_modules / dist）。
    • 两份产物放桌面，替换旧版本；有问题的旧包不要留在桌面。
  5. 用户确认「可以」之后才把新安装包对外发布（AGENTS.md 四.5「打包门禁」）。

四、测试流程与测试规范

目标：模拟真实用户交互，覆盖全部功能与选项；任一流程出问题就重新走一遍，直到完全通过。以下流程在 1.0.1 实测建立并验证，后续开发与更新沿用。

4.1 三阶段总流程

阶段 A · 安装

  1. 卸载旧版后，静默安装新包到固定测试路径： 
    cmd //c "dist\FuFumidi-Setup-<ver>.exe /S /D=C:\Users\qdTXTbp\_fufuinst\FuFumidi"
    （Git Bash 直传 \ 会被吃成路径分隔符，必须走 cmd //c 转交。）
  2. 验证安装完整：resources\python + models\piano_transcription 就位、桌面 / 开始菜单快捷方式存在、注册表卸载项版本号正确。

阶段 B · 使用（核心回归）

用 CDP 驱动真实 UI 交互（应用加 --remote-debugging-port=9223 启动），逐项执行：

  1. 版本号与 package.json 一致。
  2. 三引擎转录：通用 / 钢琴 / 分离各至少一次真实音频 → 严格校验临时目录出现带新时间戳的 transcribe_*.mid 文件（不能只看 TR_STATE.lastOut，否则会读到上次残留的陈旧值）。
  3. 智能修正：转录后点「开始智能修正」，校验输出 *_refined_*.mid 新文件 + 统计日志（起音吸附 / 尾音修正 / 主奏轨道）。
  4. 导入：真实 MIDI（E:\Midi\midi\*.mid）→ 资料库计数 +1、当前歌曲加载正确；再验证播放 / 暂停（App.player.playing 为 true 且 currentTick() 递增）。
  5. 预设系统：内置预设切换自动套用参数（「钢琴：最优」→ mode=piano、最短音符 20ms）；排序 / 删除内置 / 恢复默认。
  6. 七个视图逐一切换（演奏 / 编辑 / 可视化 / 分析 / 乐谱 / 转录 / 转换），每视图都能正确渲染当前歌曲。
  7. 设置 / 主题库对话框打开与关闭正常。

阶段 C · 卸载

4.2 CDP 实测要点（踩过的坑，务必遵守）

  1. 文件选择：CDP DOM.setFileInputFiles 注入的 File 没有 Electron 的 .path 属性，fi.files[0].path || f.name 会回退成纯文件名，引擎按相对路径解析必然报「找不到文件」。正解：模拟原生对话框，直接 TR_STATE.audio = '<绝对路径>' 并放行 $('#btnTranscribe').disabled = false 再点真实按钮。（真实用户走 fuBridge.pickAudio() 原生对话框或拖放，均返回绝对路径，不受影响。）
  2. 校验任务真实执行：点按钮后先等 TR_STATE.jobId 递增（证明事件到达），再等 busy === false，最后用临时目录快照对比确认新文件。只等 busy===false && lastOut 会在瞬时失败时读到残留旧值（假阳性）。
  3. 音符数从 #convLog 文本取（正则 识别出 (\d+) 个音符）；#convInfo 只显示「输出 …」，不含计数。
  4. 导入去重：addToLib 按 name 去重，重复导入同一文件不会新增条目——测导入要换不同文件或先清空资料库。
  5. 后台进程：用 Bash run_in_background 启动应用；普通 & 后台进程会随调用 shell 回收而退出。
  6. 测试真实文件：音频用 C:\Users\qdTXTbp\Music\钢琴曲\*.mp3（及裁剪的 _fufutest\t20.wav），MIDI 用 E:\Midi\midi\*.mid。
  7. 测试残留脚本（_apptest.js / _trtest.js / _diag.js 等 CDP 驱动器）与临时 MIDI 输出用完即清，不进交付包。

4.3 通过标准

  • 全部用例 PASS，且转录 / 修正产物为新生成文件（非历史残留）。
  • 三引擎 + 修正 + 导入 + 播放 + 预设全绿；卸载后系统无残留。
  • 任一环节失败 → 修复后从该环节起重走完整流程，直到完全通过；出问题的安装包 / 源码包不留桌面。

  • 新增预设参数键名必须与 music2midi.py 的 CLI 参数对应（app/main.js 里 engine:convert 的映射表）。
  • 引擎模式默认预设映射在渲染器 MODE_DEFAULT_PRESET（FuFumidi.html）。

插件系统开发者文档

版本：v1.1.0 ｜ 适用代码：app/plugin-host.js、app/main.js、app/preload.js、app/plugins/

本文面向想要为 FuFumidi 编写第三方插件的开发者。插件由你主动安装，等同本地可信代码，主进程入口拥有完整 Node.js 权限——请只安装信任来源的插件。

架构概览

FuFumidi 的插件系统分两层：

┌─────────────────────────────────────────────────────────┐
│  主进程（Node.js / Electron main）                       │
│  ┌─────────────────────────────────────────────────────┐│
│  │ PluginHost（app/plugin-host.js）                    ││
│  │  · 扫描目录、加载插件、调用 activate/deactivate      ││
│  │  · ctx 受控 API（commands/events/engine/settings/…）││
│  │  · 单插件 try/catch 隔离 + 引擎超时兜底              ││
│  └─────────────────────────────────────────────────────┘│
│  通过 IPC 与渲染层通信（plugins:* / app:event）          │
├─────────────────────────────────────────────────────────┤
│  渲染进程（浏览器环境，contextIsolation + sandbox）      │
│  · window.fuBridge（preload.js 暴露）                   │
│  · 插件渲染脚本（可选 renderer）注入到页面               │
│  · 收到 ui.broadcast → CustomEvent 'fuplugin:<id>:<n>' │
└─────────────────────────────────────────────────────────┘
  • 主进程插件：一个 CommonJS 模块，导出 activate(ctx)。可以注册命令、监听事件、调用引擎、读写自己的设置、向界面广播消息。
  • 渲染层脚本（可选）：一段注入到界面的 JavaScript，能操作 DOM、调用 window.fuBridge、接收主进程插件发来的广播。
  • 应用内置了同结构的示例插件：app/plugins/example-hello/。

插件是什么

一个插件就是一个目录，里面至少包含 plugin.json 清单和入口脚本：

my-plugin/
  plugin.json        # 清单（必填）
  index.js           # 主进程入口（必填，路径由 entry 指定）
  ui.js              # 渲染层脚本（可选，路径由 renderer 指定）

目录名不限；扫描时以 plugin.json 里的 id 为准。同目录层级下，用户插件目录优先级高于内置插件目录；同 id 只会加载优先级最高的那份，其余跳过。

安装位置

类型路径优先级
用户插件（推荐）用户数据目录/fufumidi/plugins/<插件名>/高（先扫描，同 id 覆盖内置）
随应用内置安装目录/resources/app/plugins/<插件名>/低
  • Windows 用户插件一般位于：%APPDATA%\fufumidi\fufumidi\plugins\
  • 也可以直接在应用内「设置 → 插件」查看实际路径。

安装后：

  1. 进入 设置 → 插件；
  2. 点 重新扫描；
  3. 打开插件的启用开关。

未启用的插件不会接收事件、不能调用命令。

最小可运行插件

plugin.json：

{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "author": "你",
  "description": "一句话说明",
  "entry": "index.js",
  "commands": ["hello"]
}

index.js（CommonJS）：

module.exports = {
  activate(ctx) {
    ctx.commands.register('hello', async () => '你好，来自插件！');
  },
  deactivate() {
    // 可选：清理资源
  },
};

放好后重新扫描并启用，「设置 → 插件」里会出现插件卡片，以及一个 hello 命令按钮，点击即调用并显示返回值。

清单 plugin.json

字段类型必填说明
idstring✅唯一 ID，正则 ^[a-z0-9][a-z0-9_-]*$（小写字母/数字/-/_ 开头不能是 -）
namestring展示名
versionstring版本号，如 1.0.0
authorstring作者
descriptionstring一句话说明
entrystring✅主进程入口文件路径（相对插件目录，CommonJS），必须存在，否则加载失败
rendererstring渲染层脚本路径（相对插件目录），注入到界面执行
commandsstring[]声明命令名；设置页会自动为每个命令渲染一个可点击按钮

缺少合法 id 或 entry 不存在都会导致加载失败，错误记入插件日志。

主进程入口 entry

入口文件是 CommonJS 模块。两种写法都支持：

// 写法 A：导出对象
module.exports = {
  activate(ctx) { /* ... */ },
  deactivate() { /* 可选 */ },
};

// 写法 B：直接导出函数
module.exports = function (ctx) {
  /* activate 逻辑 */
};
  • activate(ctx)：插件激活时同步调用，应在这里注册命令、订阅事件。
  • deactivate()（可选）：停用/卸载时调用，用于清理（定时器、监听等）。
  • 入口抛出的异常会被捕获并记日志，不会拖垮主进程。

上下文 ctx API

ctx 在 activate 时注入，包含 id、manifest（你的 plugin.json 原文）以及下列受控 API：

7.1 commands —— 命令注册

ctx.commands.register(name, fn)
ctx.commands.list()   // -> ['hello', ...]
  • fn(payload) 可以是同步函数或返回 Promise。
  • 渲染层/设置页调用命令时，payload 会被透传。
  • 调用结果：成功返回 { ok: true, result }；抛错返回 { ok: false, error }。
ctx.commands.register('convert', async (payload) => {
  // payload = { audio: 'C:/.../song.mp3', ... }
  return { received: !!payload };
});

7.2 events —— 事件订阅与广播

const off = ctx.events.on('song-loaded', (m) => { /* ... */ });
// 不再需要时：off();

ctx.events.emit('my-custom-event', { any: 'payload' });
  • on 返回取消订阅函数。
  • emit 会广播给所有已启用插件的同名监听器；每个监听器独立 try/catch，一个出错不影响其余。

7.3 settings —— 插件私有持久化设置

ctx.settings.get()            // 整个插件设置对象
ctx.settings.get('greet')     // 单键
ctx.settings.set('greet', 'hi')
ctx.settings.set({ a: 1, b: 2 })  // 传对象批量合并
  • 数据存于 settings.json 的 plugins.<id> 段，不与其他插件/主设置冲突。
  • 内置示例 example-hello 用 ctx.settings.get('greet') 演示了读写。

7.4 ui —— 界面广播与提示

ctx.ui.broadcast('my-event', { text: 'hello' });   // 通知渲染层脚本
ctx.ui.notify('操作完成', 'ok');                    // 顶部 toast（type: info|ok|err 等）
  • 渲染层脚本通过 window.addEventListener('fuplugin:<id>:<name>', fn) 接收，fn 的参数 ev.detail 即 payload（见渲染层脚本一节）。
  • notify 本质是广播名为 __toast 的特殊事件，由界面转成 toast。

7.5 log —— 日志

ctx.log('任意', '参数', { 对象: true });
  • 输出到「设置 → 插件」日志区与主进程控制台，带 [plugins] / [<id>] 前缀。
  • 引擎子进程的 stdout 也会以 plugins:log 流进同一区域。

7.6 app —— 应用信息

const meta = ctx.app.getSongMeta();
// -> { fileName, trackCount, totalTicks, totalSec, bpm } 或 null
  • 返回当前已载入歌曲的轻量信息（song-loaded 时刷新）；未载入返回 null。

7.7 engine —— 引擎调用

const r = await ctx.engine.run(['mycmd', '/path/input.mid'], {
  script: 'smart_midi.py',   // 默认 'music2midi.py'；可为绝对路径
  timeoutMs: 60000,          // 默认 30 分钟
});
// r = { code, result, out, err }

详见下一节。

引擎子进程 engine.run

复用主程序的 Python 引擎，开箱支持：

  • 内置 Python 运行时解析（打包内置 → 用户指定 → 环境变量 → 系统 Python）
  • UTF-8 中文路径适配（PYTHONIOENCODING=utf-8、PYTHONUTF8=1）
  • 离线模型目录自动注入（FUFUMIDI_MODELS_DIR）
  • 超时强制终止（默认 30 分钟，防止死循环）
  • ###RESULT {json} 结果解析

脚本约定：

  • script 默认 music2midi.py（引擎主脚本）；传入绝对路径可运行你自己的 .py。
  • 子进程 cwd 为引擎目录 engine/，引擎内的模块（如 presets）可直接 import。
  • 脚本在 stdout 输出一行 ###RESULT {json}，engine.run 会把解析出的 JSON 放进 result；其余 stdout 逐行进入插件日志。
// 示例：对已转录 MIDI 再做一遍自研处理
const r = await ctx.engine.run(['mycmd', midiPath, '-o', outPath], {
  script: 'C:/my-plugins/scripts/post.py',
  timeoutMs: 5 * 60 * 1000,
});
if (r.result && r.result.ok) {
  ctx.ui.notify('处理完成', 'ok');
}

返回结构：

字段说明
code进程退出码；异常/超时可能为 -1
result###RESULT {json} 解析对象；无则 null
out全部 stdout
err全部 stderr

应用事件

插件通过 ctx.events.on(name, cb) 订阅以下应用级事件（由界面通过 fuBridge.notify 上报）：

事件payload触发时机
song-loaded{ fileName, trackCount, totalTicks, totalSec, bpm }载入歌曲
view-changed视图名字符串：play / edit / transcribe / analyze / score / viz切换主视图
transcribe-done{ ok, out, note_count, mode, perf }转录完成
refine-done{ ok, out, stats, mode }智能修正完成

也可以订阅其它插件 emit 的自定义事件（events.emit 全局广播）。

渲染层脚本 renderer

plugin.json 声明 "renderer": "ui.js" 后，该脚本会被注入到界面环境执行：

  • 运行在页面主世界：可访问 document、window、toast()、window.fuBridge。
  • 没有 Node 权限：主窗口 sandbox: true、contextIsolation: true、nodeIntegration: false。
  • 每个插件脚本只注入一次（重复广播会被去重）。

接收主进程插件的广播：

window.addEventListener('fuplugin:my-plugin:my-event', function (ev) {
  console.log(ev.detail);   // 即 ctx.ui.broadcast('my-event', payload) 的 payload
  toast('收到：' + ev.detail.text, 'ok');
});

事件名规则：fuplugin:<插件id>:<广播名>。

调用主进程插件的命令（window.fuBridge.plugins）：

const res = await fuBridge.plugins.invoke('my-plugin', 'convert', { audio: '...' });
if (res.ok) { /* res.result */ } else { /* res.error */ }

上报应用事件给插件：

fuBridge.notify('view-changed', 'analyze');

window.fuBridge 暴露的插件相关接口：

方法说明
plugins.list()插件列表
plugins.setEnabled(id, enabled)启用/停用
plugins.invoke(id, cmd, payload)调用命令
plugins.rescan()重新扫描
plugins.openDocs()打开开发者文档（HTML）
plugins.onUi(cb)订阅 plugins:ui（广播/toast）
plugins.onLog(cb)订阅日志流
plugins.onScript(cb)订阅渲染脚本注入
notify(ev, payload)上报应用事件

生命周期与状态

时机行为
启动 loadAll()依序扫描用户目录 → 内置目录，逐目录加载；同 id 只留优先级高的一份

安全模型与健壮性

  • 隔离：单插件激活、命令调用、事件处理全部 try/catch，任何异常只记日志，不影响主程序。
  • 超时：engine.run 默认 30 分钟超时，插件内 Python 死循环会被强制终止。
  • 命令/事件受控：未启用的插件不接收事件、不可调用命令；ctx 不暴露任意文件/进程 API。
  • 渲染层受限：渲染脚本无 Node 权限；主窗口 sandbox + contextIsolation + nodeIntegration:false。
  • 信任模型：主进程入口拥有完整 Node 权限，插件等同本地可信代码——只安装你信任来源的插件。
  • 完整性检验：应用内置完整性模块会检测 plugin.json 清单缺失等异常并在设置页提示。

调试与排障

  1. 看日志：设置 → 插件 → 日志区（保留最近 300 行），主进程控制台亦有 [plugins] 前缀输出。
  2. 常见错误：
    现象原因
    插件卡片没出现目录/plugin.json 放错位置；未点「重新扫描」
    加载失败：缺少合法 idplugin.json 的 id 为空或不符正则
    加载失败：entry 不存在entry 相对路径写错或文件缺失
    激活失败入口未导出 activate(ctx) 或激活抛异常（看日志区）
    命令不存在命令未注册，或插件未启用
    引擎返回 code: -1engine.run 异常/超时，看 err 字段
  3. 渲染脚本不生效：确认 renderer 字段存在、文件可读；脚本只注入一次，改后需重新扫描。
  4. 检查清单：用 JSON 校验器检查 plugin.json（不允许注释/尾逗号）。

  • 工程文件（.fufu）：保存 / 恢复编辑状态、混音、循环、速度与目标轨道。
  • 导出 MusicXML：把当前曲目导出为标准 MusicXML，可导入 MuseScore / Sibelius 继续编排。
  • 实时和弦识别：演奏视图实时显示当前和弦名。
  • 循环点拖拽：演奏视图 Shift+拖拽设置循环区间，并高亮循环区域。
  • 歌词显示：解析 MIDI 歌词轨道，播放时逐行高亮（卡拉 OK 式）。

界面

  • 安装 / 卸载界面：字体换用微软雅黑 UI（小字号清晰锐利），顶部横幅加入 F 徽标。

1.0.2 — 2026-08-14 缺陷修补

修复

  • MIDI 转换后无法导出保存 WAV 音频文件：根因是 Electron 33（Chromium 130）下 <a download> 锚点下载经 will-download 的 preventDefault + setSavePath + resume 处理后 0 字节取消（blob/data/http 均复现）。改为 IPC file:saveBinary：渲染进程把字节交给主进程，走原生「保存文件」对话框并写盘，彻底绕开失效的下载子系统。
  • 编辑视图「导出 MIDI」同样失效：同一锚点下载机制，一并切换。
  • 「打开输出文件夹」定位错误：保存后记住实际路径（convSavedPath），按钮直接定位到刚保存的文件。

1.0.1 — 2026-08-13 修补 + 小功能

优化

  • 内置 Python 运行时瘦身：新增 scripts/prune-python.js，删除全部 __pycache__、标准库测试套件、torch 构建工具目录；bundle-python.js 构建后自动调用。安装包由 853MB → 556MB（-35%）。

新增

  • 内置两个推荐预设并设为默认：
    • 「人声：最优」（人声分离模式）：起音 0.05 / 判定 0.25 / 最短音符 100ms / 输出鼓组节奏轨 / 智能降噪 / 响度平衡 / 自动 BPM。
    • 「钢琴：最优」（钢琴专用模式）：起音 0.05 / 判定 0.06 / 最短音符 20ms / 合并间隔 0ms / 含踏板 / 智能降噪 / 响度平衡。
  • 新装默认应用「人声：最优」；手动切换引擎模式时自动套用该模式的默认预设。
  • 转录高级参数新增两项：
    • 钢琴模式「音符合并间隔」滑杆（0–200ms，对应引擎 merge_gap_ms）。
    • 人声分离模式「输出鼓组节奏轨」开关（对应引擎 with_drums）。
  • 「最短音符」滑杆范围放宽至 10–300ms（配合钢琴预设的 20ms）。
  • 预设管理：可对预设列表 ↑/↓ 排序（持久化到 presets.json 的 order）、删除内置预设（隐藏机制 + 「恢复全部内置预设」一键还原）、点击名称立即应用；删除操作改为二次确认防误删。

修复

  • 设置 / 主题库对话框右上角「×」关闭按钮失效：data-close 存的 id 缺 # 前缀，querySelector 取到 null 抛 TypeError。
  • 卸载后残留空安装目录：卸载器 CWD 位于 $INSTDIR 时 Windows 锁定当前目录，RMDir 删不掉目录本身；customRemoveFiles 先 SetOutPath "$TEMP" 再删。
