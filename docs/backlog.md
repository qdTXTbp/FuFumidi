# FuFumidi 后续优化方向（Backlog）

本文件只收录**有实测依据**的方向，每条都附上测量口径与当前数据。没有数据的猜测不写。
数据来源：`docs/test-reports/2026-09-17-v4.3.0-l2-host.md`，探针在 `scripts/cdp/`。

## A. 可视化与渲染

| # | 方向 | 当前数据 | 依据 / 下一步 |
|---|---|---|---|
| A1 | **细分「播放期主线程开销」** | 6 万音符瀑布流：绘制 2.7~3.0 ms/帧，但帧交付间隔 18~24 ms；暂停后间隔回落到 16.7 ms（= 应用自带 60 fps 限流上限） | 绘制只占不到 1/6，剩下的时间不在画布上。下一步用 `PerformanceObserver(['long-animation-frame'])` + `performance.measure` 把每帧切成「调度 / 响应式 / 分析器读取 / 绘制」四段，先定位再优化 |
| A2 | **琴键层离屏缓存** | 琴键底色渐变已从 90 个/帧降到 4 个/帧，绘制 3.6 → 2.7 ms | 琴键本身不随滚动变化（只有余辉/按下态在变），可以把「底色 + 分键线 + C 标签」整层画到 `OffscreenCanvas`，每帧只 `drawImage` + 叠余辉层 |
| A3 | **60 fps 上限是否自适应** | 限流常量 `MIN_FRAME_MS = 15`（`ViewViz.vue`），本机裸 rAF 节奏 3.3 ms（约 300 Hz 面板） | 当前是「一刀切 60 fps 省 5 倍开销」。若要支持高刷观感，可做成「有音乐能量时提高上限、静止时降回」，但需先做 A1 确认有预算 |
| A4 | 音符瀑布的亚像素绘制 | 不吸附（CoV 12.6%）已优于吸附到 CSS 像素（24.6%）与设备像素（21.6%） | 已定案，保留记录以防后人「顺手吸附一下」 |

## B. 音频

| # | 方向 | 当前数据 | 依据 / 下一步 |
|---|---|---|---|
| B1 | **预排窗口与节点预算的自适应** | 内置合成器路径：极密段落（约 180 音符/秒）下节点占用会稳定在软上限 768 附近，预排窗口由 1.0 s 收到约 0.40~0.43 s | 这是本轮修复「丢音」后的取舍：窗口换取不丢音。若要两者兼得，需要按设备能力（CPU/内存）自适应上调 `_liveLimit`，并同步压 `pruneLive` 的应急路径 |
| B2 | **空间声的最大展宽与单声道兼容性** | s=1 时硬声声像：本侧 1.5×、对侧 0.5× 且**反相** | 反相副本会让单声道兼容性下降（单声道回放时对侧分量会部分抵消本侧）。可考虑上限封到 s≈0.6，或加「低频单声道化」（bass mono）保护后再展宽 |
| B3 | 音效链的链路粒度 | EQ 仍是 3 段固定 + lowshelf，全部作用于整条总线 | 目前没有多段动态、湿声卷积混响、限幅器。若要继续做音效，建议先加输出限幅（当前靠 `master` 固定增益，音效叠加后没有峰值保护） |
| B4 | 极密曲目在 SF2 路径的丢音 | `_sf2SeqMode` 下节点数为 0（事件写在音频线程音序器），本轮实测 `pruneCalls=0` | 无需处理，保留记录：丢音问题只存在于「预排即建节点」的内置合成器路径 |

## D. 已知取舍（不是待办，避免后人重复踩）

- **极密构造曲目（160 音符/秒）复现用的 `large-60k.mid` 不入库**：360 KB 二进制样本，
  `scripts/cdp/cdp-viz-immersive.cjs` 用 `CDP_MIDI` 指定，任意 ≥100 音符/秒的 MIDI 都能触发同一量级的问题。
- **「帧交付间隔」在普通曲目上是饱和指标**：两版都跑满应用自带的 60 fps 上限，
  要发现几毫秒级回归必须用「帧内绘制耗时」（见报告 L2 帧时间基线对照）。
- **只测总电平的音频验证会漏掉声道级缺陷**：本轮空间声的右声道符号错误就是总电平守恒掩盖掉的，
  必须做左右声道分离度测量。
