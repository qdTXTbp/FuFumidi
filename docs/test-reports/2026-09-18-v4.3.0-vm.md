## 未验证项与风险

- **L4 增量更新（4.2.2 → 4.3.0）**：本轮不在 L3 内 —— 更新器的下载源是
  `releases/latest/download/FuFumidi.Install.exe`，必须先把 4.3.0 的 Release 资产上传才有得可更。
  上传后单独跑，结论并入本报告（见文末补记）。
- **UTAU 合成渲染 / 声库切分**：未在 VM 内实跑（需要先上传音频做声库切分，链路长且耗时）；
  本版未改动 UTAU 相关代码，风险低。引导中该章 2 步已按 SKIP 如实标注。
- **模型下载**：未在 VM 内实跑（需外网 + 大流量）。出厂依赖自检已覆盖「不下载模型也能用」的路径。
- 已知环境限制（非产品缺陷）：
  - 卸载后残留 `resources\python` 7 个文件 + 1 个孤儿 `python.exe`。触发条件是**测试脚本强杀主进程**
    （`Stop-Process -Force`）——引擎子进程来不及随之退出，文件被占用删不掉。真实卸载路径（用户关闭
    程序或不关时由卸载器提示结束进程）不会走到这里；记录在案以便后续加一层「卸载前回收引擎子进程」。
  - VirtualBox NAT 会静默回收空闲 TCP，宿主机经反向隧道驱动 guest 界面的**长求值（>30 s 静默）响应会丢**：
    脚本其实已经在页面里跑完，只是结果回不来。对策是把结果挂到页面 `window` 上，再用一次短求值取走
    （本轮转录、多语言、主题等长探针均按此写）。
  - 走查经隧道跑到第 11 章时连接被回收过，因此 `cdp-guide-walk.cjs` 增加了 `WALK_FROM` / `WALK_TO`
    章节区间参数，可从断点续跑而不是整轮重来。

## 复现方式

```powershell
# 回滚基线并启动
powershell -ExecutionPolicy Bypass -File scripts/vm/reset-test-vm.ps1
# 拷贝产物进 guest（宿主机 → guest）
VBoxManage guestcontrol FuFumidiTest copyto --username=tester --password=*** `
  "release\FuFumidi Setup 4.3.0.exe" "C:\Users\tester\fufumidi-guest\setup-4.3.0.exe"
# 断网静默安装 / 安装后自检 / 首次启动 / 引导走查 / 卸载保数据 / 中文路径安装
VBoxManage controlvm FuFumidiTest setlinkstate1 off
powershell -ExecutionPolicy Bypass -File scripts/vm/guest-run.ps1 -ScriptPath scripts/vm/l3-01-install-offline.ps1
VBoxManage controlvm FuFumidiTest setlinkstate1 on
powershell -ExecutionPolicy Bypass -File scripts/vm/guest-run.ps1 -ScriptPath scripts/vm/l3-02-post-install.ps1
powershell -ExecutionPolicy Bypass -File scripts/vm/guest-run.ps1 -ScriptPath scripts/vm/l3-06-launch-app.ps1
powershell -ExecutionPolicy Bypass -File scripts/vm/guest-run.ps1 -ScriptPath scripts/vm/l3-04-start-relay.ps1
# 宿主机侧：隧道 + 引导走查（CDP 经 9330）
node scripts/cdp/cdp-tunnel-host.cjs
$env:CDP_PORT='9330'; node scripts/cdp/cdp-guide-walk.cjs
powershell -ExecutionPolicy Bypass -File scripts/vm/guest-run.ps1 -ScriptPath scripts/vm/l3-07-uninstall-keep-data.ps1
powershell -ExecutionPolicy Bypass -File scripts/vm/guest-run.ps1 -ScriptPath scripts/vm/l3-08-install-cn-path.ps1
```

> 探针脚本一律留在仓库内（`scripts/cdp/`、`scripts/vm/`），本报告中每个数字都可由上表脚本重跑得到。
