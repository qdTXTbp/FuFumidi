## 未验证项与风险

- **L3 干净虚拟机全功能未跑**：本轮改动集中在音频图与可视化渲染，未触碰安装/卸载/依赖链路；
  但按 `docs/TESTING.md` 的发布闸门定义，**未跑 L3 不得发布**。待版本冻结后与新版本号一起跑。
- **L4 增量更新未跑**：同上。
- **音效链的空间声只验了「总电平不被破坏」**，未验证左右声道分离度的实际听感是否正确
  （mid/side 公式在代码层面与注释一致，但没有做声道级测量）。
- **极密曲目仍有丢音**：预算（1024 节点）用尽时会回收「还没轮到发声」的预排节点。
  在 160 音符/秒这个密度上实测约四分之一预排窗口最远端的节点被回收（rms 0.11 听感是满的，
  但确实存在丢音）。真实曲目（实测最密 31 音符/秒）达不到该密度，不受影响。
  要消除该密度的丢音需让预排窗口随密度自适应收缩，会触及播放器调度时序，需单独一轮并做时序回归。
- **`pruneLive` 的修剪是每音符一次的全量 `filter + sort`**，在超限时开销随节点数上升；
  本轮未优化（先修正确性），可作为后续性能项。
- **已知测量方法陷阱（记录备查）**：新建 `AnalyserNode` 后必须在同一处等过一个渲染量子再读，
  否则读到的是分析器初始缓冲（全 128）会造成「误判为静音」；比较链路的电平增益必须用固定测试音
  做时对齐测量，用播放中的音乐在两个时刻比 rms 会被音乐自身响度波动淹没（本轮曾因此得出
  错误的「+6 dB」结论，已纠正）。
