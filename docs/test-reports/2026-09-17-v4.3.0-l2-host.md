### L2 极密曲目丢音（第 13 项，内置合成器路径）

前提澄清：`large-60k` 在**接外部音源（SF2）音序器路径**下 `live` 恒为 0（事件写在音频线程音序器，

第 3 项修的是「丢正在响的音」，本轮修的是「窗口内节点顶穿预算导致的持续丢弃」。

| 项 | 修复前（本轮起点） | 修复后 |
|---|---|---|
| 修剪调用 | 61.6 次/秒 | **0 次/秒** |

| rms | 0.7186 | 0.7162（不变） |

### L2 空间声声道分离度（第 14 项）

测量点：音效链出口 `fxOut`（展宽级之后），用 `ChannelSplitter` 分左右各读时域 rms，
信号为**同源同相同频**正弦（判定「居中不受影响」的前提）；归一化基准 = s=0 时单侧电平 0.15025。

修复后（实测）：

| 输入 | s=0 | s=1 | 期望 |
|---|---|---|---|
| 居中（L=R） | 1.00× / 1.00× | **1.00× / 1.00×** | 居中完全不变 |
| 硬左 | 1.00× / 0（对侧静音） | **1.501× / 0.500×** | 1.5 / 0.5 |
| 硬右 | 0（对侧静音）/ 1.00× | **0.500× / 1.501×** | 0.5 / 1.5（与硬左对称） |

修复前的实测量（同一探针，仅硬左/硬右；居中的修复前值未用同源信号测过，不做断言）：

| 输入 | s=1 实测 | 应然 | 判定 |
|---|---|---|---|
| 硬左 | 左 1.50× / 右 0.50× | 1.5 / 0.5 | 正确 |
| 硬右 | 左 0.50× / 右 **0.50×** | 1.5 / 0.5 | **本侧被压到 0.5×（−6 dB），未展宽反而衰减** |

根因可由代码直接推导：旧实现 `sideL.gain = +s/2`、`sideR.gain = -s/2`，而 `sideR` 的输入本身
已是 `R - L`（自带反相），两级反相叠加后右耳等效于 `R' = R + s(L-R)/2`。
代入硬右（L=0, R=x, s=1）得 `L' = -x/2`、`R' = +x/2` —— 左右都只剩一半，本侧没有展宽反而被压。
代入硬左得 `L' = 1.5x`、`R' = 0.5x`（正确），**因此这是个只影响右侧声像的不对称缺陷**。
居中时 `L-R = 0`，两级 side 输入都为 0，故修复前后均不变。

> 这条缺陷此前躲过了所有验证，因为**总电平守恒**：`cdp-fx-gain.cjs` 测的「空间声不破坏总电平
> 比值 1.000」在修复前后都成立（`L'² + R'²` 在两种写法下都等于原值）。必须做声道级测量才能暴露。
>
> 另记一处口径教训：本项第一次尝试用**两路不同频率的振荡器**（440Hz 进左、660Hz 进右）测「居中」，
> 但那时 `L-R ≠ 0`，展宽**本来就应该**改变输出 —— 该读数（左 1.58× / 右 0.70×）不能用作
> 「居中信号被改变」的证据，已弃用。判「居中不变」必须让 L 与 R 是同一路信号。

### L2 帧时间基线对照（可视化页瀑布流，修复前 / 后配对）

**测量口径（两次测量完全一致）**：同一首歌 → 非沉浸的瀑布流布局 → seek 到曲长 40% →

- AFTER = `d3381c9`（本轮 HEAD）

普通曲目 `-空中最亮的星`（3440 音符，曲长 223.6s，seek 至 89.44s）：

| 轮次 | BEFORE p50 (ms) | AFTER p50 (ms) |
|---|---|---|
| 第 1 轮 | 17.8 / 16.6 / 16.7 | 17.4 / 18.2 / 16.7 |
| 第 2 轮 | 18.4 / 17.1 / 16.9 | 18.7 / 19.4 / 18.2 |

BEFORE 全部 p50 落在 16.6~18.4，AFTER 落在 16.7~19.4，**两区间重叠，普通曲目无帧时间回归**
（差异在轮间噪声量级内）。

**但这条结论必须配一个上限说明**：`ViewViz.vue` 里为了高刷屏省开销，可视化页从 4.2.2 起就带
`MIN_FRAME_MS = 15`（约 60 fps）的限流，两版一致（已用 `git show f07b0ee:frontend/src/views/ViewViz.vue`
核对）。本机纯 rAF 节奏实测 p50 **3.3 ms**（约 300 Hz 面板），所以 16.7 ms 是**应用自己设的天花板**，
不是渲染能力。也就是说普通曲目这一档两个版本**都已跑满上限，指标饱和**，只能排除「严重回归」，
不能用来发现几毫秒级的回归。要敏感地比较普通曲目，应改量「帧内绘制耗时」而不是「帧交付间隔」。

- **两组区间完全不重叠**（BEFORE 最低 69.7 > AFTER 最高 25.5），压力曲目帧时间 p50 下降

严重回归，实际是画布面积差了一倍。对照组必须先固定几何与内容位置，否则数字没有意义。

指标：连采 40 帧，统计相邻帧变化像素数的波动系数（越低越平滑）。
**口径固定**：同一曲目（`-空中最亮的星`）→ 瀑布流布局 → seek 到曲长 40% → 播放中连采 40 帧、
画布 913×480、dpr 2.5。

| 对照 | mean | std | CoV |
|---|---|---|---|
| BEFORE（`f07b0ee`，4.2.2） | 89,666 | 19,087 | **21.3%** |
| AFTER（本轮，4 次复测） | 101,695 / 109,996 / 111,649 / 118,096 | — | **16.4 / 13.0 / 16.0 / 14.8%** |

修复后 CoV 全部落在 13.0~16.4%，修复前 21.3%，**两组不重叠**。回归阈值取 19%（两侧各留约 2.6pp 余量）。

注：AFTER 的「单帧变化像素数均值」反而略高于 BEFORE（约 11 万 vs 9 万）。这是预期内的：
亚像素绘制会让更多像素产生「细微但均匀」的变化，而波动系数恰恰衡量的是**均匀性**而非变化量。
后文附录里的早期数值（197,870 → 86,993、峰值 284,949 → 130,307、CoV 19.7% → 12.6%）来自
**未固定场景**的测量（换过曲目与位置），与上表不可比，已弃用，仅保留在附录作为「口径不一致会得出不同结论」的例证。

## 未验证项与风险

- **L3 干净虚拟机全功能未跑**：待版本冻结后与发布流程一起跑。
- **L4 增量更新未跑**：同上。
- **极密曲目的「丢音」已消除，但代价是预排窗口变浅**：内置合成器路径下，约 180 音符/秒的段落
  会把节点占用稳在软上限（预算的 3/4）附近，预排窗口由 1.0s 收到约 0.40~0.43s。
  窗口只影响「主线程卡顿的容忍度」，不影响正在响的内容；代价是该段落若发生长于 0.4s 的主线程
  阻塞，会听到断音。要两者兼得需按设备能力自适应上调节点预算（已记入 `docs/backlog.md` B1）。
- **空间声的反相分量**：s=1 时对侧得到的是反相副本（这是 mid/side 展宽的定义使然）。
  单声道回放时对侧分量会与本侧抵消，已记入 `docs/backlog.md` B2（可考虑封顶或低频单声道化）。
- **已知测量方法陷阱（记录备查）**：新建 `AnalyserNode` 后必须在同一处等过一个渲染量子再读，
  否则读到的是分析器初始缓冲（全 128）会造成「误判为静音」；比较链路的电平增益必须用固定测试音
  做时对齐测量，用播放中的音乐在两个时刻比 rms 会被音乐自身响度波动淹没（本轮曾因此得出
  错误的「+6 dB」结论，已纠正）。

- **帧时间已做配对对照（原「未做干净对照」一项已解决）**：见「L2 帧时间基线对照」——普通曲目
  两版都跑满应用自带的 60 fps 限流上限（指标饱和，只能排除严重回归）；6 万音符压力曲目 p50 由
  BEFORE 的 69.7~112.6 ms 降到 AFTER 的 23.7~25.5 ms，两组区间不重叠。
  琴键渐变已在本轮由 90 个/帧降到 4 个/帧，绘制耗时 3.6 → 2.7 ms；压力曲目 AFTER 仍有约
  18~24 ms/帧（未达 60 fps 预算），后续方向见 `docs/backlog.md` A1/A2。
- **已知测量方法陷阱（追加）**：
  - 用「给上一帧做整体位移后再比对」来判定「闪烁是否只是滚动」是**无效**的：当所有元素
    共享同一小数相位时会整帧同跳或整帧不跳，平均下来各档位移的残差看不出差别。
  - 用「让 `createLinearGradient` 返回同一个缓存对象」来估算渐变重建开销会把语义改坏
    （实测反而把 p50 从 19 ms 顶到 236 ms），不能用来下结论。
  - **不固定场景的对照会得出互相矛盾的结论**：同一份平滑度代码，未固定曲目/位置时测出
    CoV 19.7% → 12.6%，固定后测出 21.3% → 13.0~16.4%。两组数字都「看起来合理」，
    但只有后者能与改动前做有效比较。尤其是均值：未固定时显示「均值 −56%」，
    固定后实际是「均值略升、波动显著下降」——方向完全相反。
  - **断言里出现 `null` 会把失败伪装成通过**：`rB.covPct < 16` 在 CoV 为 `null`
    （画面没有任何变化）时为真。凡是要比阈值的量，必须先断言「测量有效」。
  - **探针之间有状态残留**：连续跑套件时，出现过 `cdp-fx-tempo` 3 项失败、单独重跑即 10/0 的情况
    （前一个探针留下了「正在播放 / 沉浸态 / 弹窗未关」）。当前结论以「每项单独重跑」为准；
    要用于 CI（`docs/backlog.md` C1）必须先给每项加统一的现场复位（暂停 → 关弹窗 → 退出沉浸）。
