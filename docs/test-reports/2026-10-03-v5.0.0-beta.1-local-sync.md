## 3. 构建产物

链路：`npm --prefix frontend run build` → `electron-builder --win dir` → `scripts/build-kachina.ps1 -Version 5.0.0-beta.1` → 同步更新器 → `electron-builder --win nsis --publish never`。

| 产物 | 大小 | 说明 |
|---|---|---|
| `release\FuFumidi Setup 5.0.0-beta.1.exe` | 673.5 MB | NSIS 完整安装包（含内置 Python 1.5 GB / 模型 164 MB / g2p 24 MB / 更新器） |
| `release\update\FuFumidi.Install.5.0.0-beta.1.exe` | 150.8 MB | 离线增量包 |
| `release\update\FuFumidi.update.exe` | 8.2 MB | kachina 更新器（内嵌最新 config） |
| `release\latest.yml` | — | `version: 5.0.0-beta.1`（sha512 与安装包一致） |

**踩坑记录（下次省时间）**

1. `electron-builder` 的 `extraFiles` 取 `release/update/FuFumidi.update.exe`；而 `build-kachina.ps1` 会在跑完 `electron-builder --win dir` 之后**回写** `win-unpacked`。所以**必须在 `--win dir` 之后再跑 kachina**，否则安装包里嵌的是上一版更新器（本次就出现过：安装包内嵌了 9/18 的旧更新器，已重新生成并校验哈希一致）。
2. 用 PowerShell 传 `-c.directories.output=xxx` 会被参数绑定吃掉（变成读配置文件 `.directories.output=xxx`，报 ENOENT）；改用 `--config.directories.output=xxx`，或放进 .cmd 里执行。
3. 一次性构建脚本若把 electron-builder 的输出用管道/重定向接走，偶发在 `packaging` 阶段卡死（进程 0% CPU、0 IO）。改为直接重定向到文件后正常。
4. 静默安装必须走 cmd：`"…Setup 5.0.0-beta.1.exe" /S /D=E:\Midi\FuFumidi`。经 `Start-Process -ArgumentList '/S','/D=…'` 会因引号规则失败（退出码 -1，且 `preInit` 已清掉注册表卸载项）。
