# FuFumidi v3.1.22

## 修复
- **收藏按钮不可见 / 点击无反馈**：图标库缺失 `heart / heart-o`，导致曲库每行的「♥ 收藏」按钮渲染为空（不可见）。已补齐图标（收藏=实心珊瑚色、未收藏=描边灰），点击新增「已加入收藏 / 已取消收藏」提示；顺带修正按钮无障碍标签显示原始代码的问题
- **Aria-AMT 钢琴无法安装运行时**：资源中心的运行时依赖组把 aria-amt 实际提供的模块（`amt`）误判为 `ariautils` 检查，且 aria-amt 声明的 `torchaudio<=2.5` 会强制降级现有 torch/torchaudio 导致安装失败。现改为按真实模块检查（`amt / ariautils / safetensors / orjson`），并用 `--no-deps` 安装 aria-amt 本体、单独安装 `ariautils`，不再触碰已装好的 torch
- **Aria-AMT 装好运行时也转录失败**：引擎原按 `python -m amt transcribe` 调用，与 aria-amt 真实 CLI（`aria-amt transcribe <variant> <ckpt> -load_path -save_dir`）完全不符。已改为真实 CLI 调用、自动定位权重目录、CUDA 下开启 `-compile`
- **「补全模型依赖」弹窗一直显示「正在检查…」**：安装进行中弹窗误用「正在检查」文案，容易被误以为卡死。现改为显示「正在安装…」，并逐组实时显示进度（钢琴 / 人声分离 / MuScriptor / Aria / Transkun 完成情况），关闭弹窗后按钮状态与任务同步
- **转录页参数预设应用无效**：后端预设加载为空或异常时列表静默留空，点「应用」无任何反应。现在加载异常/为空时自动兜底内置预设，应用成功后明确提示「已应用预设：xxx」，滑块与模式同步更新
- **大 MIDI 文件分析功能失效**：和弦检测原为「每个小节扫全量音符」（O(小节数×音符数)），大文件会把界面卡死/无结果。改为近线性算法（只累计音符实际覆盖的小节），小节密度等增加规模上限；进入分析页先显示「正在分析…」再计算，超大 MIDI 也能正常出结果

## 改进
- **转录输出与输入文件同源**：不手动指定输出时，生成的 MIDI 默认保存到**音频所在的同一目录**（此前固定写入系统临时目录，用户很难找到）；若在设置里配置了「默认输出目录」则优先使用；目标目录不可写时自动回退临时目录，并自动处理重名
- **依赖安装提速**：镜像顺序改为国内快源优先（清华 → 阿里 → 官方 PyPI），pip 增加短超时与低重试，不再长时间卡死在不可达的源上；「一键补全缺失依赖」整体更流畅

## 更新方式
- 3.1.x 用户：应用内自动更新（增量更新器差分下载，只拉改动部分），或下载 `FuFumidi.Install.exe` 离线包覆盖安装
- 新用户：下载 `FuFumidi-Setup-3.1.22.exe` 完整安装
