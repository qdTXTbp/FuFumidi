# FuFumidi 6.5.0

这一版把两件事合并发布：

1. **热补丁通道**（新能力）：以后修引擎里的小文件不必再发完整包；
2. **转录质量修复**：解决「一段有鼓、一段没有」，并补一个可选的官方解码档位。

本版**不改模型权重、不改模型结构**，只调整送入模型的音频边界、解码选项，以及新增一条独立的小补丁通道。

## 一、热补丁（新增）

### 它解决什么

以前改一行引擎 Python，也要走完整发布链：升版本、打 700MB 安装包、用户下载安装。热补丁是与之解耦的第二条通道：

- 维护者把改动的几个小文件打成一个 zip + 签名清单，push 到仓库固定目录；
- 客户端启动约 9 秒后自动拉取、验签、校验 SHA256，然后覆盖；
- 不建 release、不建 tag、不改版本号，用户无感。

### 安全边界（刻意收窄）

| 范围 | 可否热补丁 |
| --- | --- |
| `resources/app.asar.unpacked/engine/**/*.py`、renderer vendor 资源 | ✅ 可覆盖 |
| `main.js`、`main/*.js`、`preload.js`、`renderer/dist/assets/*.js` | ❌ 封在 `app.asar` 内，必须整包发版 |

另外硬性拒绝：路径穿越 / 绝对路径 / 盘符、`.exe/.dll/.pyd/.node/.asar/.pyc`、单文件 > 2 MiB、总量 > 12 MiB、超过 60 个文件。

清单与补丁包都必须通过 Ed25519 签名（与整包更新同一把密钥）与逐文件 SHA256；任何一项不符直接拒绝，不写盘。

### 完整更新不会冲掉补丁

安装器的保护目录不含 `app.asar.unpacked`，完整更新会把它整体替换。因此补丁状态与备份放在 `FuFumidiData/hotpatch/`（受保护），每次启动比对目标文件哈希，被冲掉就**从本地缓存自动重放**，不用重新下载、也不用重新发布。

### 界面

设置 → 更新页新增「热补丁」区块：已应用补丁 id、上次检查时间、失败原因、`检查补丁`、`回滚补丁`。
`FUFUMIDI_NO_HOTPATCH=1` 可彻底关闭；仓库还没放补丁时显示「暂无可用热补丁」，不报错。

> 注意：**这一版是热补丁的 bootstrap 版**。比它更早安装的版本没有检查补丁的代码，收不到任何补丁；从 6.5.0 起，后续引擎小改动才能真正免发版。

## 二、边界对齐修正（默认开启）

参考 [DamRsn/muscriptor.cpp](https://github.com/DamRsn/muscriptor.cpp)（[cleafw/NeuralNote](https://github.com/cleafw/NeuralNote) 使用的 C++/ggml 引擎）的 `Transcriber`。它的 API 文档明确写着，相对官方 PyTorch 参考实现默认多做两条修正，其中 lead-in 修的是：

> 模型把每个 5 秒块开头已经在响的声音，当成需要续接的 tie prologue；pitched notes 进 prologue，drum hits 不发出 → 块首的鼓被整段吞掉。

补 0.2 秒静音后再把所有事件时间回移 0.2 秒，让每个块的开头落在静音上，同时把 5 秒分块网格整体平移。官方 Python 实现没有这一步。

实测（同一首 2 分钟曲目的前 30 秒，medium / CPU）：

| 输入 | 鼓音符 | 每 5 秒鼓数 | 耗时 |
| --- | ---: | --- | ---: |
| 原始 | 236 | 32 / 53 / **0 / 0** / 84 / 67 | 176 s |
| 前补 0.2 s 静音 | 331 | 32 / 54 / 50 / 58 / 79 / 58 | 171 s |

按实际默认路径（整曲锁定乐器组 + 边界修正）端到端复跑：`34 / 54 / 50 / 63 / 77 / 57`，无空鼓块。

实现上严格遵守 6.4.6 的教训：**不重采样、不下混、不改位深**，位深跟随源文件，音频流式逐块复制（内存恒定）；节拍网格与乐器组预分析仍以原音频为时间基准。生成失败会退回原路径，环境变量 `FUFUMIDI_MS_LEADIN=0` 可关闭。

## 三、可选「补足鼓点（采样 0.9）」解码档

转录页 MuScriptor 区块新增一档，使用官方原生 `use_sampling=True, temperature=0.9`。
实测同样能补齐空鼓块、镲占比 75%→70%、耗时不增；代价是每次结果略有不同、不可复现，因此**默认仍是官方 Quickstart 的贪心解码**。

边界修正同样补齐空鼓块且结果可复现，所以设为默认；两档叠加反而变差，不建议同时开。

## 已知边界

- **「模型很喜欢用镲」没有解决**。五个解码档位实测镲类占比 69–77%，三个历史版本的《群青》也稳定在 62–65%，这是 medium 模型的固有偏置，不是本应用链路造成的。真正能改善的是换 **Large（1.4B）** 权重，或转录前手动限定确实存在的乐器组（界面已有「手动限定」）。
- 内置 Python 运行时受更新器保护、不随应用增量升级；旧运行时若不支持新增的官方参数会自动忽略并在日志里提示。
- 本版跳过构建期的 Python 运行时裁剪（该步骤在部分 Windows 机器上会被内核句柄卡住），因此安装包体积略大于 6.4.9，功能完全相同。
