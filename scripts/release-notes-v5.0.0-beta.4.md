# FuFumidi v5.0.0-beta.4

**内测版**。这一轮只做两件事：修好**暂停后还在响**，以及把 MuScriptor 转录里
**"同一段旋律每隔几秒换一次音色"**从根因上解决 —— 顺带让"乐器组"这个开关真正生效。

> 测试版（prerelease）：仅「设置 → 更新 → 测试版通道」开启的用户可收到。

## 播放：暂停 / 停止后不再留音

- 暂停 / 停止 / 跳转时，被取消的音符以前收不到 note-off，于是会一直响；现在统一补发
  **CC120（All Sound Off）+ CC123（All Notes Off）**，16 个通道全覆盖。
- 实测：暂停后残留响度 0.003（播放中 0.286），一次性补发 32 个控制事件。

## 转录：乐器组约束真正生效

- 界面里选「限定乐器组」以前**完全不生效** —— 参数在主进程的两处（worker 请求体、命令行参数）
  都没有转发，模型一直按自由判定跑。现在补齐，日志会打印
  「旋律乐器组已锁定：…（模型不会输出其它乐器）」。
- 乐器组只留两档：**限定乐器组（硬约束）** 与 **不限定（模型自由判定，默认）**。
- 实测：锁定 voice + drums 后，输出只有两条轨（人声 1719 音 + 鼓 647 音）。

## 转录：为什么"同一段旋律隔几秒换一次音色"

- **根因是分块边界，不是乐器组判定**。MuScriptor 按 5 秒一块解码，`prelude_forcing`
  负责把上一块没结束的音**按原乐器**续进下一块；批量推理（batch>1）必须关掉它，
  于是模型只能自己猜，边界上的延音会被重新判定乐器。
- 实测（同一首歌、同一模型，只改这一个变量）：

  | | 串行 + prelude_forcing | 批量（prelude 关闭） |
  |---|---|---|
  | 相邻 5 秒分块换乐器组 | **1 次** | **16 次** |
  | 非鼓轨 | 5 条 | 9 条 |
  | 音符总数 | 2531 | 1962（少 22%） |

- 因此：**批量推理（约 2.3× 提速）改为显式开关，默认关闭**；性能档（均衡 / 高性能）不再自动开启它。
  开启时日志会写明代价，耗时估算与转录后提示同步更新（撤掉了旧文案里"chunk 边界质量差异极小"这句已被实测推翻的说法）。

## 其它

- 引擎新增独立的乐器组分析工具：`python engine/instrument_probe.py 歌曲.flac --json`，
  先看模型会把这首歌判成哪些乐器、各占多少，便于排查"为什么转出了奇怪乐器"。
- 相关单测：乐器组取值解析、选窗跳过静音、按音符数汇总、鼓保底、失败不抛。
