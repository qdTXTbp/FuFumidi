# FuFumidi 5.2.3

> 一次以「少坑」为目标的修版：曲库重命名真正落到磁盘文件名、应用内更新不再报「安装包损坏」，
> 并把内置 Python 运行时统一回 3.12、给发布构建加上自动断言。

## 曲库

- **重命名同步改磁盘文件名**：此前侧边栏「编辑信息 → 名称」只改曲库里的显示名，磁盘上的 .mid 纹丝不动
  （判断读的是不存在的字段，整段改名被静默跳过）。现在先改文件、改不动就整体放弃，再把新路径写回库。
- 顺带修好重命名后**重启会丢失曲目路径**的问题：落库改成扁平记录（与曲库自检回写同形），
  MIDI 字节按「内存 → IndexedDB → 改名后的文件」三级回读，不会把内容写丢。
- 提示文案同步改口（中 / 英 / 日）。

## 更新

- **修掉「安装包损坏，请重新下载」**：安装包里内嵌的更新器没有嵌入应用配置（embedded_config 为空，
  运行时把安装路径认成 C:\Program Files\KachinaInstaller，更新必然校验失败）。
  现在构建脚本在 kachina gen 之后把带配置的更新器同步回 release/update 与 win-unpacked，
  并新增一键发布脚本 scripts/build-release.ps1（前端 → win-unpacked → kachina → NSIS），
  末尾自动断言「更新器里必须含应用配置」。

## 翻唱 / 人声分离

- **修掉人声分离不可用**：engine/msst_configs 里 27 份分离模型配置（yaml）在仓库里丢失（只剩 index.json），
  引擎因「yaml 缺失、自动生成也没通过校验」直接拒绝分离 —— 翻唱工作流第一步就断。已恢复全部配置。

## 构建

- 内置 Python 运行时统一为 **3.12**（5.2.1 / 5.2.2 的安装包误打包了 3.11，
  会让 CP312 的 GPU 增强包在新装机器上被判不可用）。
- 修复 4 个 .ps1 缺少 UTF-8 BOM，Windows PowerShell 5.1 把中文注释读成乱码后整轮脚本报语法错。
- 上传器：正式版不再被建成 prerelease（否则 electron-updater 默认跳过、应用内收不到更新）；
  CNB 建 release 的字段名修正为 target_commitish。

## 测试

- 虚拟机 L3（干净 Windows 11 基线）：断网静默安装 → 首启 → 逐模型转录实跑 → 引擎导入（转译 / 调教 / 翻唱）
  → 卸载保留数据。
- 宿主机功能实测：转译（多模型）、调教（DiffSinger 渲染）、翻唱（分离 → 扒谱 → 合成 → 混音）。
