# FuFumidi 6.4.8

## 转录：模型外面不再叠任何东西

MuScriptor 的调用**整体回到官方写法**，和官方命令行逐字节一致：

```
load_model(规格 / 本地权重)
  → detect_beat_grid_for(音频, "best-effort")
  → transcribe(音频)                  # 不带任何参数 = 上游默认
  → events_to_midi_bytes(事件, 节拍网格)
```

- 同一段 60 秒素材（medium、CPU）：本程序输出的 MIDI 与
  `python -m muscriptor transcribe` 的输出 **SHA256 完全相同**（3485 字节）。
- 移除的补丁层（这些都会改变模型听到的东西或写出的 MIDI）：
  音频预处理链、乐器组探测与硬约束、生成参数（采样温度 / 引导系数 / 束搜索 / 批量 /
  跨块延音 / 计算精度）、音频证据式收尾、跨块缝合、token 落盘回放、识别片段长度。
- 保留的都与结果无关：本地权重解析、暂停（只延迟事件流出）、显存/算力不足时换 CPU
  重跑一次、0 音符保护。

## 节拍网格真正生效

以前即使装了「节拍网格检测（Beat This!）」权重也不会用上（默认关），现在按官方默认
`best-effort` 执行：把音符起点对齐到节拍网格，并把速度与拍号写进 MIDI。拿到网格后
不再额外做一次整曲变速 —— 那一步会把官方网格的结果二次拉伸，节奏反而更歪。

没装权重时**立即跳过**：此前权重缺失会让上游去国外服务器下载，实测把一段 60 秒素材
拖成 4 分钟以上无输出。资源中心装好后会自动启用。

## 界面

MuScriptor 只剩「模型规格」一个选项。乐器组、标签模型、探测段长、节拍网格、采样温度、
引导系数、束搜索、计算精度这些开关已全部移除 —— 它们不再有任何作用，留着只会让人以为
调了会变。旧队列/旧预设里残留的这些键仍能正常载入，只是不再影响结果。

## 说明

本版没有改变模型本身。如果换到 6.4.8 后对某首歌的结果仍不满意，那已经是这个规格
（medium）在这份音频上的上限 —— 官方文档建议追求质量时用 `large`，可在资源中心下载后
在转录页切换规格。
