# FuFumidi 6.4.10

转录质量修一版：解决「一段有鼓、一段没有」，并补一个可选的官方解码档位。
本版**不改模型权重、不改模型结构**，只调整送入模型的音频边界与解码选项。

## 主要改动

### 1. 边界对齐修正（默认开启）

参考 [DamRsn/muscriptor.cpp](https://github.com/DamRsn/muscriptor.cpp)（[cleafw/NeuralNote](https://github.com/cleafw/NeuralNote) 使用的 C++/ggml 引擎）的 `Transcriber`。它的 API 文档明确写着，相对官方 PyTorch 参考实现默认多做两条修正，其中 lead-in 修的是：

> 模型把每个 5 秒块开头已经在响的声音，当成需要续接的 tie prologue；pitched notes 进 prologue，drum hits 不发出 → 块首的鼓被整段吞掉。

补 0.2 秒静音后再把所有事件时间回移 0.2 秒，可让每个块的开头落在静音上，同时把 5 秒分块网格整体平移。官方 Python 实现没有这一步。

实测（同一首 2 分钟曲目的前 30 秒，medium / CPU）：

| 输入 | 鼓音符 | 每 5 秒鼓数 | 耗时 |
| --- | ---: | --- | ---: |
| 原始 | 236 | 32 / 53 / **0 / 0** / 84 / 67 | 176 s |
| 前补 0.2 s 静音 | 331 | 32 / 54 / 50 / 58 / 79 / 58 | 171 s |

按用户实际默认路径（整曲锁定乐器组 + 边界修正）端到端复跑：`34 / 54 / 50 / 63 / 77 / 57`，无空鼓块。

实现上严格遵守 6.4.6 的教训：**不重采样、不下混、不改位深**，位深跟随源文件，音频流式逐块复制（内存恒定）；节拍网格与乐器组预分析仍以原音频为时间基准。生成失败会退回原路径，环境变量 `FUFUMIDI_MS_LEADIN=0` 可关闭。

### 2. 可选「补足鼓点（采样 0.9）」解码档

转录页 MuScriptor 区块新增一档，使用官方原生 `use_sampling=True, temperature=0.9`。
实测同样能补齐空鼓块、镲占比 75%→70%、耗时不增；代价是每次结果略有不同、不可复现，因此**默认仍是官方 Quickstart 的贪心解码**。

对比之下本版把边界修正设为默认：它同样补齐空鼓块，但结果可复现、无随机性。两档叠加反而变差，不建议同时开。

## 已知边界

- **「模型很喜欢用镲」没有解决**。五个解码档位实测镲类占比 69–77%，三个历史版本的《群青》也稳定在 62–65%，这是 medium 模型的固有偏置，不是本应用链路造成的。真正能改善的是换 **Large（1.4B）** 权重，或转录前手动限定确实存在的乐器组（界面已有「手动限定」）。
- 内置 Python 运行时受更新器保护、不随应用增量升级；旧运行时若不支持新增的官方参数会自动忽略并在日志里提示。
- 本版跳过构建期的 Python 运行时裁剪（该步骤在部分 Windows 机器上会被内核句柄卡住），因此安装包体积略大于 6.4.9，功能完全相同。
