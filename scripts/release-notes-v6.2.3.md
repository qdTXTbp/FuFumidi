# FuFumidi 6.2.3

发布于 2026-10-24。安装包 / 更新包与上一版保持同一套离线引擎，本版只改转录页的分段识别开关与三个可选引擎的运行时封装。

## 分段识别改为「不强制开启，允许用户手动切换」

上一版（6.2.2）按「取消分块转录」把「识别片段长度」整体移除了。经确认，正确做法是
**保留能力、但默认关闭、由用户自己决定**，本版据此调整：

- **默认 0 = 不开启**：各转录模型用**原生训练块长**、整曲一次推理 —— 与 6.2.2 的行为
  完全一致，也是质量最稳的档位。
- **只有你在高级参数里把「识别片段长度」滑条调离 0**，才按你给的秒数切片识别再合并
  （Basic Pitch 分段 predict / MuScriptor 改 `_SEGMENT_DURATION` /
  piano-transcription 改 `segment_samples` / Aria-AMT 改 `LEN_MS` /
  Transkun 传 `--segmentSize`）。
- **预设一律不再写这个值**：6.1.x 的预设给每个模型都写了值（MuScriptor 5s /
  钢琴 10s / Aria 30s / Transkun 16s），切换模型就自动套上 —— 那就是「强制开启」。
  现在切模型只会套质量类参数，不会替你决定要不要分段。这一条由
  `engine/tests/test_transcribe_options.py` 与转录页 e2e 用例固化为机器断言。
- 界面在开启时显示代价提示：分段识别可能让块与块之间质量参差不齐
  （接缝重复音、换音色、延音被切断）；MuScriptor 改块长还会离开训练分布
  （官方 checkpoint 按 5 秒块训练）。

老预设/脚本里若写着 `segment_sec`，仍然兼容生效；想关掉把它调回 0 即可。

## 另两种分块保持移除

- 引擎内的「静音分段」（按完全空白静音切核心段逐段推理后合并）—— 未恢复。
- MuScriptor「自动探测（分段）」乐器组档 —— 未恢复（A/B：音色切换 4 次、
  边界重复音 1 个、耗时 +3.6 s，F1 还低于整曲探测）。旧值 `probe_segments`
  按整曲探测兼容，不会报错。

## 其余（同 6.2.2）

- 统一三个可选引擎（hFT-Transformer / YourMT3+ / MIROS）的运行时、下载与管理：
  运行时发现不再写死训练批次目录名；补中途暂停、线程上限、显存归还、0 音符报错；
  下载走同一个安装通道（下载 → 校验 → 解包 → 结构验收 → 清理临时产物），
  删除模型时连压缩包与分片目录一起清掉。
