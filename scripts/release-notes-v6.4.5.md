# FuFumidi 6.4.5

**一次阻断级修复：MuScriptor 选了之后完全转不了。**

## 转录（MuScriptor）· 全面回退 4.3.x 逻辑

- 默认路径回到 4.3.x 的做法：**一次解码、一次模型调用、上游默认参数、零预处理零后处理**。
  6.x 在模型调用前叠了一整串补丁层（音频链预处理 → 音频证据钩子 → 乐器组探测 →
  生成参数 → 自定义事件流 → 跨块缝合）；Python 运行时在更新器的 `ignoreFolderPath` 里
  **不随版本升级**，于是「新引擎代码 × 旧 muscriptor 包」是常态 —— 新版引擎默认传
  `batch_size` 等新 kwargs，旧包的 `transcribe()` 不认就直接 TypeError，整次转录报废。
  裸调用不跟任何 kwargs，什么版本的包都能跑，也是用户认定的质量基准（4.3.1）。
- 内置「MuScriptor · 最优」预设精简为**只选模型**：不再默认做分段乐器组探测
  （`probe_segments`），不再默认发批量推理（medium/small 的 `batch_size=4`）。
  批量推理当年就因「实测是纯损失」被删除（bca0a55），且与跨块延音默认开互相矛盾。
- 手动在界面选的「限定乐器组」（硬约束）仍然生效；进度显示、0 音符保护、
  显存不足 / CUDA 运行期报错自动换 CPU 重跑都保留。
- 新流水线**没有删除**：设环境变量 `FUFUMIDI_MS_MODERN=1` 可调用，供调试对照。
  该路径的 `batch_size` 默认也回到 1。
