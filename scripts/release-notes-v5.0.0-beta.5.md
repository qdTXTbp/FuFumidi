# FuFumidi v5.0.0-beta.5

**内测版**。这一轮把「**翻唱**」做成一条能跑完的工作流：**一首歌进去，一个成品出来** ——
分离人声、扒谱（音符 + 歌词）、用你选的音色唱出来、混音成成品，全在一个页面里。

> 测试版（prerelease）：仅「设置 → 更新 → 测试版通道」开启的用户可收到。

## 翻唱（新页面）

- 导航新增「**翻唱**」：① 选歌 → ② 选音色 → ③ 输出与选项 → ④ 开始。
- 两条音色通道，产出同构（一条整长干声轨），后面的混音完全共用：
  - **DiffSinger 声库**（原有）：扒谱出的音符 → 逐句渲染；
  - **GPT-SoVITS 音色**（新）：逐句拿**原唱那一句**当参考重合成。
- **人声分离复用「音频处理」面板同一套模型**（music2midi.py separate 同一个入口），
  而且在那边分离完可以直接把「人声 / 伴奏」带进翻唱页，不用再选一次歌、再分离一遍。
- **断点续跑**：每一步的产物旁边写一份签名（输入文件 + 参数）。人声轨、歌词、声库、
  参数没变就跳过 —— 中途断了再跑一次不会从头来。界面上的「不复用上次的中间结果」
  可以强制全部重算。

## GPT-SoVITS 音色怎么唱指定旋律

本地 vendored 的 GPT-SoVITS 是**纯 TTS**：它的 SoVITS 推理**没有 F0 入口**，
旋律只能由**参考音频的 mel** 带出来。所以路线是「**逐句参考重合成**」：

    原唱第 N 句（已分离人声）→ 当参考音 → 用目标音色重合成 → 对齐/校正 → 填回时间轴

- 参考音**自动卡在 3~10 秒**（它的硬性检查；短句往后借气口、长句截断），
  目标时长则用这一句真正的演唱跨度 —— 两者分开算。
- 对齐链：**相位声码器整段拉伸**到目标时长（上限 1.6×）→ **WORLD 音高校正**
  （把输出的 F0 换成原唱这一句的 F0，谱包络不动，单帧限幅 ±7 半音）→ **逐句电平配平**（±8 dB）。
- 每句给出客观量：逐帧相关、**时间归一化后的旋律相关**（拉伸不敏感，判据用这个）、
  MFCC 距离。旋律相关过低的句子会在结果里提示「该换路线 B（专门 SVC）」。

## 资源中心：GPT-SoVITS 音色终于有入口了

- 模型管理新增「**GPT-SoVITS 音色**」分类。此前这类音色在页签里**没有任何分类展示它** ——
  下载链路一直是好的，纯粹是入口缺失，界面上看不到（用户报的正是这条）。
- 翻唱页的「运行时 / 解释器」各有一个「选择」按钮：选一次写进
  `<数据根>/gpt-sovits/runtime.json`，以后自动带出来。

## 引擎

- **ONNX 会话缓存**：建会话要重新解析计算图 + 分配权重（acoustic 200MB+，一次 3~8 秒）。
  现在同一模型在进程内只解析一次（缓存键含**文件大小 + mtime**，换声库自动失效）。
  这是「整首一次渲染」能跑通的前提（以前要把歌切成 ≤140 音符的小段绕开）。
- **provider 解析按 device 缓存**：以前只存一个全局值，第一次用 auto 解析出 CUDA 之后，
  后面所有 cpu 请求都被悄悄当成 CUDA（`--device cpu` 形同虚设）。
- 分离与渲染的 GPU 守卫：GPU 被别的进程占满时**降级 CPU 并如实上报设备**
  （GPU 上静默退出、分离 TTA + batch>1 撑爆显存都是实测踩过的坑）。

## 已知限制

- GPT-SoVITS 音色通道**不是 SVC**：它是「跟着原唱重唱一遍」，音高/咬字贴近原唱，
  不是「把原唱换成目标音色」。追求 100% 音色替换请等路线 B（专门 SVC）。
- 逐句合成约 **30~50 秒/句**（GPU 与其它任务共享时更慢），一首 45 句的歌约 20~30 分钟；
  中途失败会自动从断点续跑（最多 4 次尝试，且要求每轮至少多完成一句）。
- GPT-SoVITS 需要一份**独立运行时**（代码 + 预训练基础模型）和一套**装好 torch 的解释器**，
  与 DiffSinger 那条通道的依赖不是一回事。
