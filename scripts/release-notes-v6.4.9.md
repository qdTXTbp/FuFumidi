# FuFumidi 6.4.9

## 「节拍网格检测」权重：自有仓库，国内 / 国外双源

MuScriptor 的官方节拍网格（Beat This! `final0`）此前只有一条 GitHub raw 地址，
国内直连基本没有吞吐。本版把资源中心的下载点明确成两端，都在我们自己的仓库里：

| 线路 | 地址 | 用途 |
| --- | --- | --- |
| 国内 | CNB `FuFuCloud-mirror/Models` 整树镜像 | 默认（自动 / 国内）优先，实测约 6.2 MB/s |
| 国外 | GitHub `monologue82/Models` raw | 选「全球」时优先，另叠加 6 个 GitHub 加速前缀 |

- 用户设置的「设置 → 下载源（自动 / 国内 / 全球）」现在**对模型下载真正生效**。
  此前注册表里的 `mirrors` 被无条件排到最前，选「全球」等于没选；本版把
  「国内端 / 国外端」分组后再按设置排序，另一端始终保留为失败回落。
  同一处修正也让 hFT-Transformer、乐器组标签模型两个条目受益。
- 国内镜像已逐字节核对：81,058,141 B，SHA256 `8c328b45…8331`，与登记的
  官方权重完全一致；按资源中心真实链路端到端下载并校验通过。
- 下载时增加确切字节数校验（`expectSize`），文件被截断当场报错，不会等
  装完才发现损坏。两端下下来的文件都过同一道 SHA256。

## 转录：修跨块换音色、鼓点断续、进度不动

对照官方提交 `302343e8` 与第三方包装（固定官方 v0.4.0）逐行核对后确认：
本机 muscriptor 0.3.0 的 `events.py` / `streaming.py` / `tokenizer/mt3.py`
与官方 v0.4.0 **逐字节相同**，差异只在 MIDI 导出/量化 —— 换包治不了这个症状。

真正原因是 6.4.8「全面回退」时，把**官方 API 的 `instruments=` 硬约束**
连同补丁层一起删掉了。MuScriptor 逐 5 秒块判乐器，`prelude_forcing` 只管
「上一块没结束的续音」，管不了「新起音被判成别的乐器」；不锁定乐器组，
每块都可能改判，于是同一段旋律换音色、鼓点断续。

`docs/plans/2026-10-18-muscriptor-preset-ab.md` 的 A/B（medium / 30 秒
双音色素材，每档跑 2 次取第 2 次）：

| 配置 | 音色切换 | F1 | 轨数 | 耗时 | 峰值显存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 不锁定（6.4.8 行为） | 5 | 0.4914 | 3 | 2.23 s | 3703 MB |
| 只做整曲锁定 | **0** | **0.7692** | 1 | 3.41 s | 3703 MB |
| 锁定 + 音色稳定后处理 | 0 | 0.7692 | 1 | 3.29 s | 3703 MB |

`probe_only` 与 `stable` 指标完全相同 ⇒ 有效的是**官方硬约束**，不是后处理
（第三方 CLI 的 `--instrument` 就是它）。本版恢复为默认：转录前用同一模型
在 3 段 20 秒代表窗短推理取乐器组并集，探测到鼓必留，再交给官方
`transcribe(instruments=...)`；不改音频、不改事件、不改 MIDI 字节。

同时：

- **进度透传**：官方事件流每块交织一个 `ProgressEvent`，而官方
  `events_to_midi_bytes` 会把它 `continue` 掉 —— 现在在流上拦截转 `###PROG`，
  转录页真实分块进度与任务中心恢复，事件本身原样下传。
- **显式启用 `prelude_forcing=True`**，并用 `inspect.signature` 做能力探测：
  旧 wheel 不认这些参数时退回零 kwargs（不会 TypeError）并给出醒目告警。
  内置 Python 运行时受 `ignoreFolderPath` 保护、不随应用更新升级，
  装得早的机器若仍是旧包，日志会明确写出「运行时过旧」。
- 转录页新增三档：**自动锁定（默认） / 不限定（官方自动识别） / 手动限定**，
  另有「常用编制 + 鼓」「钢琴 + 鼓」快捷填充。

**代价**：自动锁定会多跑一段预分析（GPU 约 +1 秒，CPU 可能多约 1 分钟）；
且它是整曲硬约束，探测没听到的长尾乐器会被挡住 —— 这类曲子请切「不限定」。

## 统一下载管理

传输层早已统一（FastDL），任务层此前完全没统一：8 个下载模块各有自己的
进度事件与取消表，任务中心预留的下载类型是死代码。本版加一层旁路，把
模型 / 音色 / 声库 / 壁纸 / GPU 包 / 更新包 / 识谱组件的进度统一登记进任务
中心；**各模块原有 IPC 字段一个没改**，取消与断点仍由各自资源页掌握。

## 说明

- 装上「节拍网格检测」权重后，转录会自动按官方 `best-effort` 启用网格；
  没装则立即跳过，不会联网去国外服务器下载。
- CNB 的 git raw 有 100 MiB 读取上限且不支持断点续传；81 MB 在限内，
  下载器会自动退回单连接，这个体积足够快，无需切片。
- 本版与 6.4.8 的**模型权重和推理本身**一致，改变的是官方参数的用法、
  进度透传与下载管理。
