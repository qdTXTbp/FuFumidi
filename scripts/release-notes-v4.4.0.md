# FuFumidi v4.4.0

这一版的主题是**国内网络**：给所有需要联网的资源加了一条国内线路。此前不管你在哪儿，
更新检查、模型、音色库、壁纸、GPU 增强包全都直连 GitHub —— 国内网络下经常卡在 0 字节，
或者干脆列不出内容。现在这些都走同一套「下载源」偏好，并且已经把整份资源镜像到了国内。

同时补上了两个一直在等的基础设施：正式版 / 测试版双通道，以及 GPU 增强包的预打包一键下载。

## 新增

### 下载源（设置 → 更新）

三选一：**自动（优先国内）/ 国内（CNB）/ 全球（GitHub）**。同一套偏好同时作用于
更新检查、增量更新、模型、音色库、壁纸与 GPU 增强包 —— 任何一处失败都会自动回退到
序列里的下一个源，不会因为某一侧不可用而收不到资源。

### CNB 国内镜像

- **模型仓库**：整树镜像，1558 个文件 / 37.07 GB。
- **音色库**：7 个 SF2（含 1.18 GB 的 Salamander，走 Release 资产通道）。
- **动态壁纸**：含 2 个 Git LFS 视频真身。
- **GPU 增强包**：CUDA 分卷 + DirectML，共约 3.02 GB。
- **历史版本的安装包与增量更新资产**：46 个 release / 124 个资产。

镜像的地址结构与 GitHub 一一对应，所以走国内源时拿到的是同一份文件，只是换了个下载地址。

### 正式版 / 测试版双通道（设置 → 更新）

想抢先体验的可以切到测试版，正式用户完全不受影响 —— 两条通道靠 GitHub 的
prerelease 语义天然隔离，`releases/latest` 会自动跳过测试版。版本比较改为语义化
（`4.4.0-beta.1 < 4.4.0-rc.1 < 4.4.0`），避免把测试版与正式版判成同一个版本而收不到更新。

> 注意：第一个测试版通常只能手动分发安装包 —— 更新器的源地址是编译进 exe 的，
> 已经装上的旧版本里没有测试版源，得先升到本版才能在设置里开启。

### GPU 预打包增强包一键下载（设置 → GPU 加速）

直接列出 CUDA 与 DirectML 两个预打包包的体积，点一下即下载并安装。
这是「安装 GPU 加速」（走 pip 在线安装）失败时的备用路径 ——
此前只能自己到 GitHub Release 下载 3 GB 的包，再回来手动导入。

## 修复

- **超过 100 MiB 的音色库与壁纸，在「下载源 = 国内」时完全下不动**。CNB 的 git 直读
  接口对单文件有 100 MiB 的上限，超限的文件**能上传上去、却读不回来**
  （返回「raw file size xxx MiB exceeded 100 MiB」）。受影响的是 FluidR3（141.5 MB）、
  Arachno（148.2 MB）两个音色库和一个 215.7 MB 的动态壁纸，现已改为走 CNB 的
  Release 资产通道分发（对象存储，没有该限制）。
- **只连国内网络时，GPU 增强包列表是空的**。包清单此前只查 GitHub 的接口，
  GitHub 不通就什么都列不出来。现在按下载源偏好决定先查国内还是先查 GitHub，
  任一侧不可达自动换另一侧；并给查询加了超时，避免设置页长时间转圈。
- **下载 GPU 增强包失败会把整个应用带崩**。写文件的流没有挂错误处理，而失败路径
  会先把下载目录删掉，此时仍在打开中的流抛出的「文件不存在」就成了无人处理的错误，
  直接终止主进程。现已补上错误处理，失败只会如实报错。

## 改进

- **原生 Rust 核心改用统一的 MIDI 文件（SMF）解析器，支持 running status** ——
  这是一种常见的省略重复状态字节的写法，此前遇到这类文件会解析失败。
- **曲库去重的内容哈希由 32 位快速哈希升级为 SHA-256**，并与 Rust 核心使用同一算法。
  此前「Rust 是否可用」会影响去重分组结果，同一批文件可能被分到不同组。

## 内部

- CI 的 Node 版本由 20 提到 24（与本地验证环境一致）。`npm run test:ui` 的脚本依赖
  Node 22+ 的 glob 展开，Node 20 会把 `*.test.js` 当成字面路径直接失败 ——
  这意味着此前 test 这一步一直没过，后续的插件沙箱测试与 asar 内容校验从未真正执行过。

## 升级说明

- 应用内更新：设置 → 更新 → 检查更新
- 全新安装：运行 `FuFumidi Setup 4.4.0.exe`
- 本版不涉及安装 / 卸载与数据目录结构，升级不会动你的曲库、模型、声库与设置。

> **从 4.2.2 或更早版本升级时请注意**：更新完成后请**手动重新打开一次 FuFumidi**。
> 自动重启是由「发起更新的那一版」驱动的，而旧版的重启逻辑本身是坏的（守护进程压根没被执行），
> 没法反过来修好这一次升级的过程。更新本身是成功的 —— 文件已替换、数据完好，
> 关掉更新器窗口后手动打开即可。**从 4.3.0 或更新版本升级不受此影响。**
